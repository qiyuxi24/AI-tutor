## 视觉解析 / PDF（详见 `docs/RAG_视觉解析策略_调研与实施方案.md`）
- 用户提议"PDF 直发 M3 视觉" → 不成立：OpenAI 兼容 chat 无 PDF content part，仍须本地渲染成图。视觉是**难页保底牌**，不是默认路径。
- 成本反转：**`qwen-vl-ocr`（¥0.3/¥0.5 每 M）比 MiniMax-M3（¥4.2/¥16.8）便宜约 31 倍** → 200 页教材全量 ≈¥0.3/本。选型：锁 `qwen-vl-ocr-2025-11-20` 或 `-latest`（8192 输出 / 6000 RPM），**别用动态版**（4096 输出 / 600 RPM），旧快照贵 16 倍。
- **本机无 NVIDIA GPU** → 本地 DocVLM（MinerU / olmOCR）否决，唯一 CPU 可行的 Granite-Docling 精度仅 76.8% 且要引 torch → 不做。
- 分层：L0 逐页探针 → L1 本地增强（rawdict 阅读顺序 / `find_tables()` / 字号→标题层级）→ L2 云 OCR 转写难页 → L3 图表描述 + 本地 caption 配对 → L4 交叉校验（相似度 <0.7 拒绝覆盖）。
- **P0 已落地（本地半边）**：`pdf.py` 从"整份文档级阈值判定"改为**逐页探针 + 页级 OCR 路由**（修了"95 页扫描 + 5 页文本的混合 PDF 永不触发 OCR"的真 bug）；`parse_document(verbose=True)` 回传 meta；新增 `parsers/ocr.py` 能力层（pdf/image 共用）；`chunk_text` 剥离 `<<<PAGE n>>>` 并记起页、Markdown 标题成边界。页标记契约在 `parsers/base.py`。

## 上下文工程（详见 `docs/上下文工程_调研与差距审计.md`）
- 核心判断：不是"没做"，是**做了一半且没分层**；对话（保连续）与图谱生成（保全局一致）**不能用同一套机制**。"不能一次生成"是两个独立约束：输出上限 + 全局视野。
- 两个硬缺口：① `call_llm` 硬编码 `max_tokens=2000` → 图谱生成截断 → `if not result: continue` **整块静默丢弃**，且不检查 finish_reason；② 图谱注入每节点 200 字 ≈260 字符 → **200 节点顶穿 32K** → guard 退化为"照发 + warning"。
- **P0 落地**：`build_graph_context` 加硬上限 `GRAPH_INJECT_MAX_CHARS=12000` + **降级阶梯**（全量含摘要 → 省摘要 → 限量节点二分）+ 焦点邻域优先（`current_node`）+ 尾部展示范围说明（**说明文字计入上限**）。实测 300 节点：83,846 → **11,952 字符**（44,713 → 7,418 token）。
- 关键量化（复用价值高）：Manus 输入:输出 ≈100:1、缓存 $0.30 vs $3.00（**10×**）；Chroma 实测 18 模型 / 194,480 次调用 → 性能随长度**持续**退化、1 个干扰项就有害、**打乱的干草堆优于结构化的**；工具描述做 RAG 后选择准确率 ≈3×。
- 明确不做：多 Agent 隔离、Mem0/Zep/Letta、Leiden 社区检测、LLMLingua、微调解锁长输出。

## 图谱生成：两轮修复
- 第一轮：`call_llm` 参数化 + `finish_reason=="length"` 告警 + `GRAPH_MAX_TOKENS=8000` + `failed_chunks` 可见；三处复用收口（两份生成循环合并 `_generate`、分块改用 `kb_manager.chunk_text`、JSON 提取统一为 `llm/json_extract.extract_json`）。
- 第二轮（**真主因**）：**M3 的思考与正文共享同一个 `max_tokens`** → 3/8 块思考写 2.6~2.9 万字符烧完 8000 → 正文 0（日志表现为 `E-LLM-006`）。修：`thinking=False`（仅 M3）+ 串内未转义英文引号兜底 + `GRAPH_JSON_RETRIES=1` → 复测 **8/8 成功、82 节点 127 边**（修复前 5/8）。
- **单纯调大 max_tokens 治不了**（思考会一起涨）；⚠️ `GRAPH_MAX_TOKENS` 与 `GRAPH_CHUNK_CHARS` 必须**成对调**。
- 否决：`response_format={"type":"json_object"}` 被端点接受但**不强制**（仍包 ```json 围栏）。
- 解析失败日志要打**头 200 + 尾 120 + 总字符数**（尾部是否收在 `}` 才能区分"截断" vs "引号未转义"）。

## 多 Agent：结论 = 暂不引入
- 4 条依据：单线教学场景不适配（成本最多 15×）、设计文档已列为非目标、当前唯一 P0 是上下文过大（多 Agent 反而叠加窗口）、观测契约是扁平单 run（多 Agent 要 trace 树 = 改唯一事实源）。
- 三个"像多 Agent 其实不是"的便宜做法：整书建图（后台任务模式）/ 该教还是该练（确定性策略层）/ 多智能体叙事（角色化 prompt）。
- 引入判据（须三条同时满足）：单窗口放不下 + 子任务可并行 + 有 eval 证明收益 > 成本。
- 顺带发现的**文档漂移**：README 仍写"先流式裸答 + 后台补刀"（代码已是 `run_agent_loop` 为主）；GraphAnalyzer 第二入口仍在（每轮多 1 次 LLM 调用）。
