## PDF 解析 / 识图能力评估（讨论，未定案）

**用户提议**：把 PDF 直发 MiniMax M3 视觉解析全部页，替代现有解析。
**结论**：方向对一半 —— 视觉是**难页保底牌**，不是默认路径；真正短板在「逐页路由」与「图片全丢」。

**前提澄清（官方文档核实）**：M3 支持 `image_url`（URL/base64，detail low/default/high，单图 ≤10MB，请求体 ≤64MB），但 OpenAI 兼容 chat **无 PDF/document/file content part** → 「直发 PDF」不成立，仍须本地渲染成图。价格 ≤512k：输入 ¥4.20/M、输出 ¥16.80/M。200 页书 `detail=high` ≈ ¥10/本，100 本 ≈ ¥500–1000。

**现状盘点（逐条查过代码）**：
1. 扫描判定是**整份文档级**（`pdf.py:44-47`，`SCAN_TEXT_THRESHOLD=20` 对**全文** strip 长度判定）→ 95 页扫描 + 5 页文本层的混合 PDF **永不触发 OCR**，静默丢内容（**真 bug**，比质量问题严重）。
2. `parse_document()` 返回 `(text, ext)`，**丢弃 `ParseResult.meta`**（`parsers/__init__.py:100-105`）→ OCR 标记/页数不进下游，无法知悉解析方式与质量。
3. `get_text("text")` 纯顺序提取（`pdf.py:41`）：表格被线性化打乱、公式/特殊字体出乱码（无检测）、页眉页脚污染、多栏阅读顺序错。
4. **图片/插图/图表 100% 丢弃**（无抽取、无 caption 配对、无描述）→ 所谓「识图不足」实为**能力为零**。
5. `chunk_text` 纯字符窗（500/50）+ heading 取首行前 30 字（`kb_manager.py:54-90`）→ 结构在解析后又被打平，只升级解析收益被吃掉一半。
6. `upload_and_index` 同步内联在 HTTP 请求内（`kb_manager.py:157-208`）→ 长文档模型解析必超时。
7. `core/llm` 无多模态基建：`build_api_messages` content 直通（可放 parts），但 `call_llm` 固定 `max_tokens=2000`（`llm/call.py:41`）不够转写一页。

**推荐分层（便宜先行）**：L0 逐页探针分流 → L1 数字页本地增强（rawdict 阅读顺序 / `find_tables()` / 字号→标题层级 / 页眉页脚去重）→ L2 仅失败页渲染成图交 M3（4–8 页/批）→ **L3 仅图片/图表走视觉描述 + caption 绑定为独立 chunk（性价比最高）**。配套：交叉校验（模型输出异常偏短则保留本地）、按结构分块、预算/配额、meta 记 method、异步任务化（照抄 collector tasks）。
**风险**：模型抄错/漏行/擅自总结 → **污染知识库且难发现**（最严重）；干净文本层 PDF 上模型转写严格劣于 PyMuPDF。
**优先级**：P0 = 逐页判定 + meta 透传 + 结构化分块（小改、零 API 成本、收益最大）；P1 = 图表抽取走视觉 + 公式本地 OCR；P2 = 难页视觉兜底 + 校验 + 配额。
**待办**：用户未定案；我建议先写探针脚本跑真实 PDF 统计静默丢失率，用数据决定是否上视觉。
**外部卡点**：`text-embedding-v4` 欠费 → 向量检索降级 BM25，会压低本项投入的体感回报。

### 交付：上下文工程调研报告已产出（`docs/上下文工程_调研与差距审计.md`）

**核心判断**：① 不是"没做"，是"做了一半且**没分层**"；② **两个场景性质根本不同，不能用同一套机制** —— 对话 = 有状态保**连续**（业界主线 Anthropic 三技术 / Manus 六原则 / LangChain 四策略）；图谱生成 = 无状态保**全局一致**（学术主线 GraphRAG 层次 map-reduce / LongWriter·DOC plan-then-expand / iText2KG 增量一致）；混用两头失手。
③ **「不能一次窗口生成」是两个独立约束**：**(i) 输出上限**（与输入窗口无关，LongWriter 实测"能读 10 万 token 却写不过 2000 词"，根因是 SFT 缺长输出样本 → 只能工程拆解，因为用第三方 API 无法微调）**(ii) 全局视野**（跨块一致性需看全局但塞不进窗口）。

**审计出的两个硬缺口（P0，已写入 MEMORY.md）**：
1. `llm/call.py:41` `max_tokens=2000` 硬编码 vs 图谱生成要求每节点完整 Markdown → 截断 → `graph_generator.py:526-527` `if not result: continue` **整块静默丢弃**；且**从不检查 finish_reason**。
2. 主对话路径 `detailed=True` 每节点注入 `content[:200]`（`graph_analyzer.py:150-153`）≈ 260 字符/节点 → **约 200 节点顶穿 32K 预算** → `context_guard.py:86-88` 退化为"照发+仅 warning" → 静默失效。
另有缺口：#4 `existing_nodes` 全量注入每块 + 每块全量重查（O(N²)）；#5 **无跨批全局骨架 → 跨章节 prerequisite 边永远抽不到**；#6 结构与内容耦合在同一次调用；#7 `/kb/graph/generate` 是**同步 HTTP 端点**跑长任务；#10 无前缀缓存策略（system prompt 每轮含动态图谱）。

**方案**：
- 场景 A（对话）：A1 图谱注入预算化 + 复用**已有** `graph_middleware.slice_graph` 切片 + 节点内容改走 `rag_search` just-in-time（progressive disclosure）；A2 `context_guard` 升级为分层摘要；A3 **Tool Result Clearing**（Anthropic 称最低成本最安全，保留 `tool_call_id` 只清 content，**不破协议**）；A4 前缀稳定化（把动态内容移出 system prompt 头部，Manus 实测缓存 10× 价差）；A5 可观测。
- 场景 B（图谱生成）**三段式**：① 骨架段（只出 id/name/summary/difficulty/edges，**不出 content** → 输出小到不截断）→ ② **归一化段（新增，第一次看到全局）**：同义合并复用现有 0.78+LLM 确认、id/粒度对齐、**补跨块边**（可复用 `core/prerequisite.py` F1 0.941 做候选生成）→ ③ 内容段（**每节点独立调用**，用 `rag_search(source="kb")` **定向取源片段**而非塞整本书，可并发/可断点续跑，落盘 `graph_skeleton.json` + `nodes/{id}.md` 即幂等载体）。产 `/kb/graph/generate` 改后台任务，**照抄 `collector/manager.py` 任务模式**。
- **明确不做**：多 Agent 隔离（单线教学场景 + 成本最多 15×）、引入 Mem0/Zep/Letta/LangMem（与现有图谱+画像同构）、Leiden 社区检测（`subject→board→node` 层次已定义）、LLMLingua、微调解锁长输出。

**关键量化数据（复用价值高）**：Manus 输入:输出 ≈ **100:1**、缓存 $0.30 vs $3.00/MTok（**10×**）、框架重建 4 次；Chroma 实测 **18 模型 / 194,480 次调用**，结论：性能随长度**持续**退化、**1 个干扰项就有害**、**打乱的干草堆一致优于结构化**、LongMemEval 长提示（11.3 万 token）显著差于聚焦提示（300 token）；Claude Code **95% 窗口触发 auto-compact**；工具描述做 RAG 后选择准确率 **≈3×**；GraphRAG 两阶段索引 + 预生成社区摘要 + 查询期 map-reduce，百万 token 级全局问题显著优于常规 RAG。

**可复用既有资产**（勿重造）：`scripts/eval_graph_injection.py` / `eval_rag.py` / `eval_prerequisite.py` 三个评测脚本、`tests/test_context_guard.py`、`core/collector/manager.py` 任务模式。

## 修「生成学科图谱」：Docker 日志实证 + 复用收口（2026-09-13 晚）

**已修（P0 缺口 #1/#2，见 `docs/上下文工程_调研与差距审计.md` §2.3 + §10）**：
1. `call_llm(system_prompt, messages, max_tokens=2000)` 参数化（默认不变向后兼容）+ 新增 `finish_reason == "length"` 告警 → 截断不再与"模型没返回"混淆。
