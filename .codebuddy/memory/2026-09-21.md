## 知识图谱生成重写：求「单节点深度」（GQ-5 / GQ-6 落地）

用户诉求原话："单个节点现在切的太过于稀碎，我需要在单个节点的深度"；成本口径"先小样验证再说"。
动手前先确认过方向（"递归"有两种解读：原文层级下钻 vs 知识点图扩展），用户选了前者。

### 实测根因（旧实现）
- `graph_generator._generate` 按固定 3000 字符滑窗切块，uid5 一本 RL 教材 **316 块 / 均值 583 字符/块**。
- **两个碎片放大器**（审计时没定位到的，这次挖出来了）：
  1. `chunk_text` 把 Python 代码注释 `# 衰减因子` 当 Markdown 标题反复断块 —— 583 字符/块的真正来源；
  2. 正文折行 `第5章作为整个内容的核心…` 被章标题规则误判成新章。
- prompt 自设上限「content ≤300 字 + 每次 8 个节点」→ 正文中位 241 字。

### 新实现（全在 `backend/app/core/kb/graph_generator.py`）
- `build_section_tree(text)`：中文「第X章」**优先**（`_rule_section_tree`，递归下钻「第X节」），
  Markdown 标题兜底。判定关键 = 章号后必须有分隔符 + 不含句读标点 + ≤40 字。
- `collect_units(sections)`：递归切成生成单元（下限 1500 / 上限 5000 / 软上限 6000 / 下钻 ≤4 层）；
  短块相邻合并、超长按段落滑窗（**刻意不用 chunk_text**，原因见上）。
- `_drop_shallow_nodes`：正文 <400 字拒收并计数（`rejected_shallow`）。放在**编排层**而非
  `_write_to_graph` —— 后者被 `test_node_write_paths.py` 的写入路径用到，改它会连带弄红别人的测试。
- prompt 重写：每单元 3-5 个节点、单节点 600-1000 字五段式（定义/要点/**示例须含数值或代码**/易错点/前后置关系）。
- `kb_manager._make_chunk` 新增 `path` 字段（真实标题层级，空 = 无标题；新增 key 不影响现有消费方）。

### 实测效果（零成本切分预览）
uid5 强化学习 PDF（191,771 字符）：**316 块 / 583 字符 → 43 个单元 / 4402 字符**（最小 1536，最大 5743），
章节层级正确（第1章～第10章）。单元数 -86%。

### 小样验证入口
`backend/scripts/smoke_graph_depth.py`
- 只看切分（零成本）：`--user-id 5 --node-id 5`
- 真跑一章：`--chapters 1 --run --subject 强化学习`（默认**不写库**，`--write` 才落库）
- 退出码：正文中位 ≥600 且空壳率 ≤10% = 0
