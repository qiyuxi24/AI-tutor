## AI-Tutor：RAG 语义检索 + 文件上传知识库（已实现）

### 架构决策（用户确认）
- **Embedding**：阿里云 API `text-embedding-v4`（联网，非本地 fastembed）
- **向量存储**：SQLite 存向量 + numpy 余弦相似度（未用 LanceDB，避免额外二进制依赖）
- **知识图谱 RAG 与上传文件知识库分开检索**，互不混合
- 前端引入 **Element Plus**（el-tree + el-upload）；PDF 用 PyMuPDF、Word 用 python-docx

### 1. 图谱 RAG（backend/app/core/rag/）
- `chunker.py`：Markdown 按标题分块（heading 作溯源，长段二次切分）
- `vector_store.py`：SQLite 向量存储（rag.db，按 user_id 隔离）+ numpy 余弦检索
- `manager.py`：RagManager 单例，封装嵌入/索引/检索/统计
- API（api/v1/rag.py）：POST /rag/index、GET /rag/search、GET /rag/stats
- 集成：`chat_service._build_system_prompt` 改 async 并注入 `_build_rag_context()`；`_analyze_and_apply` 后 `_index_applied_nodes()` 增量索引变更节点；`knowledge.py` delete_node 同步清理索引
- 图谱节点创建/更新时走增量索引，节点规模小足够

### 2. 文件上传知识库（backend/app/core/kb/）
- `parser.py`：PyMuPDF 解析 PDF、python-docx 解析 Word、UTF-8/gbk 解析 MD/TXT
- `kb_store.py`：KbStore 资源管理器式多级目录树（nodes 表 parent_id 递归 + documents 表），含 collect_descendant_files（递归深度限制 max_depth）、delete_node_recursive（级联删除）、build_tree
- `doc_vector_store.py`：DocVectorStore 上传文档向量存储（doc_chunks 表，按 doc_id/node_id 维度）
- `kb_manager.py`：KbManager 单例，upload_and_index（上传→解析→分块→向量化→入库）、search（按 node_ids 范围检索）、create_folder、collect_files、build_tree、delete_node
- API（api/v1/kb.py，已注册 main.py）：GET /kb/tree、POST /kb/folder、POST /kb/upload、DELETE /kb/node/{id}、GET /kb/search、POST /kb/context、GET /kb/stats
- 新增依赖：PyMuPDF、python-docx、python-multipart、numpy（已入 requirements.txt）

### 对话集成（上传文件知识库）
- `ChatRequest` 增加 `kb_node_ids`/`kb_node_name`
- `chat_service` 三个处理函数加 kb 参数，新增 `_build_kb_context()`（在所选目录范围检索，注入提示词标注「知识库参考（来自「{name}」）」）
- chat.py 构造 kb dict 传给 process_message/process_message_stream/process_background_tools
- 前端：store.kbContext + setKbContext，sendMessageStream 携带 kb_node_ids/kb_node_name

### 前端
- main.js 全局注册 Element Plus（全量引入，JS 924KB，后续可改按需优化）
- `api/kb.js`：getKbTree/createKbFolder/uploadKbFile/deleteKbNode/searchKb/getKbContext/getKbStats

### Bug 修复：create_node 全局 ID 冲突（已修复）
- 根因：nodes.id 是全局 TEXT PRIMARY KEY，但 generate_node_id/add_node 只检查当前用户（带 user_id），不同用户可能生成相同 ID → 插入主键冲突 500
- 修复：新增 `_node_id_exists_globally()`（不带 user_id 查全局），generate_node_id/add_node 改用全局唯一性检查
- 验证：两用户建节点 → new_006 / new_007，无冲突

## 统一对话历史折叠按钮（2026-08-27 追加）

> 用户需求：把对话页"打开/收起对话历史"的按钮统一图标和样式。

### 方案：单一切换按钮（VSCode 风格）
- **`HomeView.vue`**：原来两个按钮（侧栏标题栏的 `cs-collapse` 书页图标 + 折叠后边缘的 `conv-expand-btn` 双箭头）合并为**一个 `.conv-toggle-btn`**：
  - 展开态：按钮贴在侧栏右边缘（left: 260px），图标 `‹`（chevron-left），title"收起对话列表"
  - 收起态：按钮移到内容区左边缘（left: 0），图标 `»`（chevron-right），title"展开对话列表"
  - 图标随状态切换（`v-if="!sidebarCollapsed"` / `v-else`），圆角随位置镜像，`left` 带 0.3s 过渡动画
  - 尺寸 22x52，与旧展开条一致
- **`ConversationSidebar.vue`**：移除标题栏的 `cs-collapse` 按钮（书页图标）及对应 emit/style，标题栏只留"对话"文字，折叠统一由边缘按钮控制。

### 结果
- 打开/收起由**同一个按钮**完成，图标和样式完全统一，不再有"两个按钮两种图标"。
- `vite build` 通过，零 lint 错误。
