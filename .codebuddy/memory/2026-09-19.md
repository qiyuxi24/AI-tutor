**🔑 核心技术发现：Windows OpenSSH 支持 `SSH_ASKPASS`（9.5p2 实测可用）**
- 探测法：把 `SSH_ASKPASS` 指向不存在路径 → 报 `CreateProcessW failed error:2` + `ssh_askpass: posix_spawnp: No such file or directory`，证明它**真的会去 spawn** askpass（不是不支持）。
- **`.cmd` 脚本可以直接当 askpass 用**（不需要编译 .exe）：内容 `@echo off` + `echo <密码>` 即可。posix_spawnp 能执行 .cmd。
- 生效三件套：`SSH_ASKPASS=<askpass.cmd 路径>` + `SSH_ASKPASS_REQUIRE=force`（绕过 TTY/DISPLAY 判断） + 密码由 askpass 输出到 stdout。
- 落盘位置（临时，非项目内）：`C:\Users\34239\AppData\Local\Temp\sshask\askpass.cmd`；另存了通用版本 `askpass.rs`（从环境变量 `SSH_PASSWORD` 读密码，不含硬编码，可用 rustc 编译）。
- 意义：在**非交互终端**中也能完成密码型 SSH 认证，绕开 Windows 无 sshpass 的限制。通用于任何需要密码登录的主机。

## 踩坑
- `execute_command` 被 PowerShell 包装执行 → 调用 exe 必须用 `&` 调用符，不能像 cmd 那样裸写路径（`"C:\...\ssh.exe" -o ...` 会报 `意外的标记"-o"`）。
- 重定向/管道报错信息里的 `posix_spawnp` 是 win32-OpenSSH 自身的兼容层实现。
- 用 `Get-Content` 读文件再写入会被平台安全钩子拦截（编码风险）→ 直接内联字符串绕过。
- **复杂嵌套引号会被终端包装层搞坏**（PS 单引号里再嵌 bash 双引号+转义 JSON → ParserError）。解法：配置文件先 `write_to_file` 本地 → `scp` 上去 → 远端 `sudo cp`。
- **远端 sudo 无 tty 时凭据不缓存**：`sudo -S` 成功后紧跟的第二个裸 `sudo` 报 "A terminal is required"。每条 sudo 都要单独 `echo 密码 | sudo -S -k`。
- PowerShell 双引号字符串里 `$Server:/tmp` 会被解析成作用域语法报错 → 必须 `${Server}:/tmp`。
