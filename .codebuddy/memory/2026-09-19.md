## 踩坑
- `execute_command` 被 PowerShell 包装执行 → 调用 exe 必须用 `&` 调用符，不能像 cmd 那样裸写路径（`"C:\...\ssh.exe" -o ...` 会报 `意外的标记"-o"`）。
- 重定向/管道报错信息里的 `posix_spawnp` 是 win32-OpenSSH 自身的兼容层实现。
- 用 `Get-Content` 读文件再写入会被平台安全钩子拦截（编码风险）→ 直接内联字符串绕过。
- **复杂嵌套引号会被终端包装层搞坏**（PS 单引号里再嵌 bash 双引号+转义 JSON → ParserError）。解法：配置文件先 `write_to_file` 本地 → `scp` 上去 → 远端 `sudo cp`。
- **远端 sudo 无 tty 时凭据不缓存**：`sudo -S` 成功后紧跟的第二个裸 `sudo` 报 "A terminal is required"。每条 sudo 都要单独 `echo 密码 | sudo -S -k`。
- PowerShell 双引号字符串里 `$Server:/tmp` 会被解析成作用域语法报错 → 必须 `${Server}:/tmp`。

## 修复 E-AUTH-005 误报警告（日志噪音）

**现象**：后端控制台出现 `E-AUTH-005 | 身份凭证无效或已过期，请重新登录`（WARNING 级别），但同批 login/chat 请求全是 200。

**根因**：`backend/app/core/auth.py::get_current_user_from_token` 把 `log_error(ErrorCode.AUTH_TOKEN_INVALID)` 写在函数**第一行**（用于构造 401 的 detail），**成功路径也必然执行** → 每次带 token 的鉴权（含 SSE `/knowledge/events`）都打一条假警告。`log_error` 无 exception 时走 `logger.warning` 分支，所以表现为"警告"而非"错误"。

## Agent Loop 工具调用安全边界（2026-09-19 晚，接上文并发会话未完成部分）

> 上文第 113 行提到"loop.py 正被另一会话并发改造 `_LoopGuard`" —— 本次接手落地并通过全量；若再发现 loop.py 被并发改动，先比对 mtime。

**需求来源**：用户反馈测试中出现"agent 循环输出无用数据"。

**诊断（结论：无 `while True` 式无限循环，`for range(max_rounds+1)` 有界；但有四类退化）**
1. **工具调用次数无界**：单轮可并行返回 N 个 tool_calls，5 轮能跑出几十次调用，无总数/墙钟上限。
2. **无重复调用检测**（主因）：同 (工具, 参数) 反复重试，拿到的永远是同一份结果/报错。
   ⚠️ **`Tool Result Clearing` 会诱发它**：早期结果被换成「需要时请重新调用」占位符（保留最近 2 批），第 3 轮起模型很可能原样重取同一份。
3. **工具连续失败无熔断**：失败只是文案喂回模型，可被一轮轮换参重试到轮数烧完。
4. **日志几乎为零**：loop 内原先只有一条 Tool Result Clearing 的 info，无 run_id、无每轮摘要、无终止原因，排查"为什么输出无用内容"只能事后查 DB。

**落地改动（改 `backend/app/core/agent/loop.py` 为主）**
- 新增 `_LoopGuard`（与 loop.py 同文件，未新增模块）：四道边界 —— 调用总次数 12 / run 墙钟 180s / 同参数重复 ≤2 / 连续失败熔断 3；默认值经 `run_agent_loop` 新参数可覆盖。**只判定不执行**，成败由 `_execute_tool` 调 `note_result()` 回报（子执行 → 主循环报告契约）。
- 越界的 tool_call **不静默丢弃**：回填写明原因的拒绝文案（`_DENY_MESSAGES`），且仍 append tool 消息保住 `tool_call_id` 配对（否则会 400）。
- 统一收尾出口 `_build_result` + `_finish_without_tools`（`_force_finish` 复用）：写 `loop_stop` 证据 + run 级日志 + `AGENT_DONE(stop_reason=)`。
- 日志全面补：`[run xxxxxxxx]` 短标贯穿 —— run 开始（预算/消息数/预计 tokens）、每轮工具清单+耗时+失败项、收尾原因与统计。
- `AgentRunResult.stop_reason` ∈ `natural/max_rounds/time_budget/call_budget/fail_circuit/error`，三出同值（结果/事件/证据），**未动 agent_runs 表结构**。
- 后台子任务报告：`core/quiz/chat_quiz.py` 的 `_run_guarded` 加 `wait_for(CHAT_QUIZ_TIMEOUT_SECS=120)` —— 原先 LLM 卡住会永久挂着，`_INFLIGHT` 不释放 → **该用户此后永远出不了题**（工具一直回"已经有一道题在生成中"）；超时/异常一律推 `QUIZ_READY ok=False` + 带耗时日志。

**测试**：`tests/test_agent_loop.py` 新增 4 例（重复调用被拒 / 次数预算提前收尾 / 连续失败熔断 / stop_reason 上报事件）；`tests/test_chat_quiz.py` 新增 1 例（超时回报 + 释放占位）。离线全量 **731 passed, 7 deselected**（基线 711，含其他会话新增）。

**文档同步**：`AGENTS.md`（loop 默认值 + 排查线索）、`backend/app/core/agent/README.md`（模块表、时序图、坑 12/13、新增 §6.1 安全边界表）。

**未做（显式留给后续）**：真正 detached 子任务（quiz 出题）的 `run_id` 回填（需把 run_id plumb 到工具 handler，成本高）；agent_runs 加 `stop_reason` 列（当前走 evidence 的 loop_stop，够用）。
