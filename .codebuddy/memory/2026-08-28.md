# 2026-08-28

## 混合检索（Hybrid Search）落地 — 上传知识库

用户要求做"双搜索系统"（传统关键词检索 + 向量语义检索）。调研了论文（RRF/Cormack SIGIR2009、BM25、SPLADE、RAG综述）和开源方案（rank_bm25、whoosh、faiss、SPLADE、llamaindex/haystack），结合项目"零新增数据库依赖、手写轻量模块"原则，选定：**whoosh（BM25 稀疏）+ 现有 numpy 向量（稠密）+ 加权分数融合**。

用户选项：whoosh 引擎 / 加权分数融合 / 先做上传知识库。

### 新增模块 `backend/app/core/hybrid_search/`（完全解耦）
- `whoosh_index.py`：`SparseIndex` 类，每个用户独立索引目录 `data/kb/{user_id}/whoosh_index/`
  - schema：chunk_id(NUMERIC unique 主键) / node_id / doc_id / chunk_index / heading / content(STORED) / content_zh / content_en
  - 中文分析器：whoosh 2.7.4 **无内置 ChineseAnalyzer**（也避开 jieba），自定义：`RegexTokenizer(连续CJK) | NgramFilter(2,2)` 做中文 bigram；英文 `StemmingAnalyzer`
  - BM25 打分，分数用 `score/(score+1)` 归一化到 (0,1]
  - 范围过滤用 `Or([Term("node_id", nid)])` 与解析查询做 `And`
  - 方法：upsert_chunk / delete_node_chunks / delete_chunks / clear_user / search / count
- `fusion.py`：`fuse(vec_results, sparse_results, alpha=0.6, min_score)` 加权分数融合，chunk_id 聚合，保留首次元数据
- `__init__.py`：导出 SparseIndex、fuse、DEFAULT_ALPHA

### 改动既有文件
- `backend/app/core/kb/doc_vector_store.py`：
  - `upsert_chunk` 改为返回 `lastrowid`（chunk_id），作为混合检索统一主键
  - `search` 结果增加 `chunk_id` 字段
- `backend/app/core/kb/kb_manager.py`：
  - `__init__` 增加 `self._sparse` 缓存；新增 `_get_sparse()`
  - `_index_document`：写向量拿到 chunk_id 后同步 `sparse.upsert_chunk`，删除前同步 `delete_node_chunks`
  - `delete_node`：**修复原有 bug**——原来在 `delete_node_recursive` 删完后再查节点类型，节点已不存在导致 `file_node_ids` 为空，向量索引永远清不掉。改为删除前先 `collect_descendant_files` 收集文件 ID，删后再清索引
  - `search`：改为 向量 + whoosh 双路检索，`fuse(alpha=VEC_WEIGHT=0.6, min_score=MIN_SCORE)` 融合
  - `stats` 增加 `sparse_chunks`
- `backend/requirements.txt`：加 `whoosh>=2.7.4`
