# 2026-09-11

## 调研：embedding 模块可替代方案（未动代码，纯方案对比）

**触发**：用户问「embedding 还有什么方案？MiniMax 能不能用？有没有替代方案」。背景是 P0 卡在阿里 text-embedding-v4 额度。

### 代码侧现状（三个入口，两条链路，易踩坑）
1. `core/llm/clients.py` → `embed_client = AsyncOpenAI(api_key=DASHSCOPE_API_KEY, base_url=EMBED_BASE_URL)`；对话 client 与 embed_client 已解耦。
2. **RAG/KB 主链路**：`kb/kb_manager.py` 与 `rag/manager.py` 各自 `EMBEDDING_MODEL = "text-embedding-v4"` **硬编码**，各有一个 `_embed()` 直接调 `client.embeddings.create(model=..., input=texts)`，失败返回 []（KB 侧退化为 BM25-only 写 NULL）。
3. **图谱语义去重链路**：`kb/embedder.py` 独立可插拔（ApiEmbedder / SentenceTransformerEmbedder / HashEmbedder + `get_embedder()` 三级降级）——**与主链路不共享**，换模型要改两处。
4. 向量存储：`rag/vector_store.py`（chunks 表）+ `kb/doc_vector_store.py`（doc_chunks 表），JSON 字符串存 TEXT，numpy 余弦暴力检索。
5. **真实隐患**：`VectorStore.search` / `DocVectorStore.search` 里 `np.dot` **不校验维度**（doc_vector_store 的 try 只包 json.loads），换维度且未重建 → ValueError 500。换模型必须清空重建。
6. 现有重建手段：`POST /rag/index`（图谱全量）、KB 重新上传/`scripts/seed_collector.py`；whoosh BM25 索引与 embedder 无关，不用重建。

### MiniMax 结论
能用但**不是最省事**：官方有 `POST /v1/embeddings?GroupId=...`，模型 `embo-01`，**1536 维**，请求体 `{model, texts, type: db|query}`，响应 `{vectors, total_tokens, base_resp}`。坑：① 非 OpenAI 兼容（要用 httpx 写适配器，或走支持它的网关）；② 需 GroupId（当前 .env 没有）；③ **db/query 非对称**，入库与查询要传不同 type，两个调用点都得改；④ embo-01 是 2024 年老模型，中文检索大概率弱于 text-embedding-v4 / bge-m3。

### 替代方案矩阵（要点）
- 阿里 text-embedding-v4/v3：**充值即解阻塞**，v4 便宜（灌库成本级毛钱），最省事。
- OpenAI 兼容云 API：**硅基流动 SiliconFlow**（`api.siliconflow.cn/v1`，BAAI/bge-m3=1024 维、Qwen3-Embedding 系列，有免费额度）、智谱 embedding-3（2048 维）、ModelScope。改动 = 换 key/base + 删两处硬编码模型名。
- 本地：fastembed（ONNX，无 torch）、sentence-transformers（torch，embedder.py 已有骨架）、Ollama（bge-m3/nomic-embed-text）、TEI/Xinference 自建。零额度 + 「数据不出本地」是教育隐私卖点；代价是首次下载模型与 CPU 编码。
- 零向量：只跑 whoosh BM25（mock 实测 R@1 **0.964**，反而最高；fuse 0.818 / RRF 0.766 / vector 0.470）——演示可跑，无任何额度依赖。

### 建议路径（待用户定）
1. 先充值阿里（几块钱）解 P0；2. 再加 `EMBED_MODE=api|local|hash` 开关（TODO_Collector B4.3 早已规划）做离线兜底；3. 换供应商前先用 `scripts/eval_rag.py` 量化收益，别凭感觉换。

### 顺带发现的改进点（未做）
- 两个 `_embed()` 应合并为统一门面（含 kind=db/query），否则每换一次供应商要改 3 处；
- 向量检索应加维度校验/跳过，避免混维度直接 500。
