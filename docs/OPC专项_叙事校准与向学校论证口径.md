# OPC专项（赛道二）· 叙事校准与向学校论证口径

> 用途：找出"附件6 OPC专项要求"与"AI-tutor 现状叙事"之间的裂缝，给出**每个裂缝怎么补、每类敏感问题怎么答**的统一口径，供写申报书、给学校沟通、答辩共用。
> 依据：附件6《中国国际大学生创新大赛(2026)陕西赛区特色专项赛道方案》原文；BP v2（docs/bp_v2/）；团队信息补充资料。
> 关联文档：`docs/OPC专项_学校参赛合规材料清单.md`（资格/证据清单）；本文讲**叙事与口径**，两文配合使用。

## 〇、先立一个总原则

**OPC 赛道评审的不是"谁的技术强"，而是"一个人 + AI 能不能把一件事从想法做到能赚钱"。**

所以给学校的每一份材料、每一次回答，都要能同时回答三个递进问题：
1. 这项目**解决真问题**吗？（有用）
2. 一个人 + AI 工具**真的做得出来**吗？（合理、可行）
3. 它**凭什么能赚钱、能长大**？（商业可行、有潜力）

当前 BP 主要回答了第 1 问（痛点 + 学习科学实证）和第 2 问的"技术已做出"部分；第 2 问的"AI 工具运用"和第 3 问是弱项——**这三个弱项正是裂缝所在**。

## 一、叙事裂缝总览（规则 vs 项目现状）

| # | 规则侧（OPC要求） | 项目现状（BP叙事） | 裂缝 | 校准方向 |
|---|---|---|---|---|
| 1 | 核心主创仅1人、凸显**单人主导创业** | BP 多处强调"5人学生团队、模块分工、团队协作优势" | 叙事重心在"团队"而非"单人" | 主创=佀佳超（唯一），4人降格为"协作者/早期试用成员"，删掉"共同推进/共同创立"类措辞 |
| 2 | 以个人为核心主体，**打通研发→产品→运营→客服全链条** | 技术研发部分极强；运营/客服环节基本空白（还在MVP） | 只有"研发"这一环，闭环未讲 | 把**产品本身 + 开发过程**都讲成"单人+AI全链条"；运营/客服写"用AI工具怎么自动化跑"而非"以后招人跑" |
| 3 | 依托大模型/AIGC/智能协作工具，看重 **AI工具综合运用能力** | BP 讲产品"用了AI"，但没讲主创"创业过程用了哪些AI工具" | 缺"工具运用"证据 | 补一张"主创的AI工作流"清单（AI辅助编码/测试/文档/设计/将来自动化营销客服），并强调本项目是"用AI造出来的AI产品" |
| 4 | 商业模式可行、可盈利、**轻量化可持续** | 商业模式三阶段逻辑完整，但阶段二写"BD团队地推、50-150万投入" | 规模化路径依赖"人海"，与单人矛盾 | 换口径：PLG + AI自动化交付 + 轻BD（校内试点→院系轻订阅→高校合作），弱化"雇团队"表述 |
| 5 | 一人公司 / 主创绝对控股 | 未注册，BP 未解释"为何不注册/何时注册" | 评委可能问"不注册怎么商业落地" | 给"注册时点决策"口径（见专题三），并说明校园阶段以个人/工作室参赛完全合规 |
| 6 | 全垂直领域之一：AI教育服务 | 项目正属 AI教育服务 | 无裂缝，是天然契合点 | 在申报书第一页**主动点题**"本项目属于'AI教育服务'鼓励方向"，帮评委快速归类 |
| 7 | 负责人≤35周岁 | 主创为在校生 | 无裂缝 | 名册标注出生日期即可 |

> 结论：真正的裂缝只有 4 条——**团队口径、全链条闭环、AI工具运用、规模化路径**。下面逐条给说法。

## 二、裂缝①：团队口径 —— "5人团队"怎么讲成"单人主导"

**硬约束回顾**：规则允许团队 ≤15 人，但"核心主创仅 1 人"且要"凸显单人主导创业核心特征"。

**合规做法（不造假）**：主创仍然只有佀佳超一个人，其余 4 名同学是**成员/协作者**，不是"联合创始人"。技术上这完全说得通——BP 里本来就只有佀佳超承担核心开发。

**必须统一的三处用词**（在申报材料、给学校 PPT、答辩里一致）：
- ✅ 用："核心主创佀佳超 **主导**产品定义、系统架构与 AI/Agent 主链路；4 名同学在指定模块**协作**，并作为首批种子用户参与内测。"
- ❌ 禁用："5 人共同创立""团队共同推进""多位发起人""一起创业"。
- ❌ 慎用："5 人团队" 单独出现（容易被读成 5 人合伙）——出现时必带定语："主创 1 人 + 协作成员 4 人"。

**一句话定调（可直接背）**：
> "项目以主创个人为创业主体：需求判断、产品方向、核心开发、商业决策全部由主创一人完成并负责；其他成员承担任务型协作（如前端组件、评测脚本、内容整理），其角色在扩张阶段将逐步由 AI 工具与 Agent 接管——这正是 OPC 描述的'单人+智能体'形态。"

> ⚠️ 底线提醒：如果学校/学院要求"团队必须全员真实参与"，那就如实列 5 人（≤15 合规），只把主创标成唯一核心即可。切勿既想少人又想冒领他人工作。真实是最高优先级。

## 三、裂缝②：全链条闭环 —— 把"只有研发"讲成"研发即全链条"

规则原话要点：**以个人为核心主体，打通创意研发、产品迭代、市场运营、客户服务全链条自主商业闭环**；评审看 **AI工具综合运用能力、主创主导性**。

**AI-tutor 最独特的叙事优势（现在没用上）**：
> **"AI-tutor 本身，就是一个人用 AI 工具链完成的完整产品闭环。"** 这不是套话——91 个源文件、1.7 万行代码、46 个 API、90+ 测试，主创独立完成；而完成它的方式（AI 辅助编码、AI 写测试、AI 生成文档、Agent 协作）本身就是"单人+智能体"商业形态的**活证据**。

**把四环补齐的口径**：

| 闭环环节 | 现在能讲什么 | 建议补什么 |
|---|---|---|
| 创意研发 | ★ 已闭环（痛点→方法→MVP 全自主） | 补充：开发全程用 AI 工具链提效的证据（可在答辩演示 Git 记录） |
| 产品迭代 | ★ 已闭环（两阶段流式、事件总线、测试先行） | 讲"快速验证→改版"的循环速度是单人+Agent 才有的优势 |
| 市场运营 | △ 计划中（B站/小红书学长学姐口碑） | 改口径：**内容由 AIGC 生产、分发靠平台推荐**，单人即可运营，不靠团队铺人力 |
| 客户服务 | △ 计划中 | 改口径：知识库 + Agent 自动答疑即"客服"；将来用 function calling 做自助排障，单人维护即可 |

**一句话定调**：
> "传统创业每增加一个环节就要增加一个人；OPC 模式下，新增环节由新增的 **Agent/AI 工具**承接，主创保持一人。因此单人覆盖全链条在 AI 时代是可持续的，这正是本赛道的立足点。"

## 四、裂缝③：商业模式与盈利 —— 面对"你怎么赚钱"怎么答

### 4.1 评委/学校真正想问的三个问题
1. 现在 0 收入，是不是只是"学生作业"？
2. 你说高校 SaaS，**一个人怎么卖得动 50 所学校、怎么交付维护**？
3. C 端大学生付费弱，你的钱到底从哪来？

### 4.2 三个问题分别怎么答

**Q1 "现在 0 收入"** → 不是短板，是策略：
> "MVP 期 0 营收是**主动选择**：先用免费 C 端验证留存（目标 ≥3 校 1000+ 学生，月留存 ≥30%），有留存数据才有资格谈 B 端付费。单人创业的最大好处是**验证成本近乎为零**——每月固定成本只有 LLM API 费用，试错无负担，不需要融资续命。等到留存指标达标，商业模式再启动，顺序是'先证明有用、再谈收费'。"

**Q2 "一个人怎么服务 50 所高校"** → 把"销售/交付"翻译成可被 AI 承接的动作：
- **获客**：不靠 BD 扫楼，靠①比赛/学术背书（中国教育技术协会大赛获奖=敲门砖）②内容营销（AIGC 生成的教师端教程/案例视频在 B站/公众号分发）③"先在一个学院做成案例，再横向复制"。
- **交付**：产品是标准化 Web + SQLite，**零部署成本、一键脚本**，学校自己装即可——单人可维护；私有化部署用 Dockerfile 自动化。
- **客服/实施**：知识库 Agent 自动答疑 + 视频教程自助上手，主创只处理剩余长尾。
- **定价**：从"整校大额采购"降为"先院系轻订阅（学年制、几万元级）→ 跑通 2-3 所标杆校 → 再谈整校"，降低单点对个人的依赖。

> ⚠️ 请把 BP 阶段二里"50-150 万投入 BD 团队地推"这类表述，改为"以 AI 工具与内容渠道为主、合作渠道为辅的轻获客"。这是目前 BP 里与 OPC 叙事**冲突最大的一处**，不改会被当"假单人"。

**Q3 "钱到底从哪来"** → 给清晰的三层收入漏斗（BP 第 5 章已有，只需加固"单人可实现"）：
| 收入层 | 来源 | 单人怎么实现 |
|---|---|---|
| C 端（2026-27） | 单学科深度包/增值订阅（参考月均 20-50 元） | 数字商品零边际成本；付费功能由 Agent 测评后自动开通 |
| B 端（2027-29） | 高校按院系/按校 SaaS 订阅 | 标准化交付 + AI 客服 + 内容获客，主创 + 合作渠道 |
| 平台期（2029+） | API 开放 / 内容分成 / 多学段复制 | 能力复用，边际成本趋零 |

**盈利答辩金句**：
> "我的单位经济模型里，**边际成本是 AI 调用费，不是人力**。新增 1000 个学生和新增 10 个学生，我的交付成本几乎不变——这是单人公司敢做订阅制的原因，也是它比传统教培公司更轻的原因。等 B 端有稳定收入后，再考虑注册主体与团队扩张。"

## 五、裂缝④：一人公司 —— "要不要注册、合不合理"怎么说

### 5.1 先给结论（建议口径）
**申报阶段不注册，写"未工商注册"即可**——规则明说"是否工商注册不作硬性限制"，不注册最省事、零合规风险。**不要写"即将注册/正在注册"**，那会立刻引来"那股权结构呢？"的追问。

### 5.2 如果评委问"不注册怎么做生意/怎么收款"
> "注册是**需求驱动的时点决策**，不是身份标签。校园 MVP 阶段以个人开发 + 免费验证为主，无对公收款需求，不需要法人主体；当产品进入 B 端付费试点、需要开票签合同、或需要以独立主体承接知识产权与数据合规责任时，再注册。届时按规则选择**一人有限公司**（主创 100% 持股），天然满足'一人公司或主创绝对控股'的要求。"

### 5.3 为什么"一人公司"在未来是合理的（评委追问时的论证）
- **规则本身背书**：OPC 赛道定位就是"单人+智能体"新业态、培育数字经济新业态青年创业主体——**单人公司是这个赛道官方认可的形态**，不是异类。
- **成本结构**：一人公司固定成本≈LLM API + 云服务，无房租/无工资，现金流压力小，能活过普通初创活不过的验证期。
- **决策速度**：AI 时代产品迭代以周为单位，单人决策无沟通损耗，主创即 CEO+CTO+PM。
- **政策趋势**：数字经济下"一人企业""数字游民创业"是被鼓励的方向，AI Agent 补齐了单人缺失的执行力。

### 5.4 若学校/评委反将一军："一人公司抗风险能力差、是减分项"
> "正因单人，我把**风险前置设计**进产品：核心模块文档化 + 1000 query 离线评测集，任何协作者/未来雇员都能快速接手；数据按用户隔离、架构模块化解耦，关键人不依赖某一位'核心员工'——因为主创自己就是文档化最充分的那个人。抗风险不靠人多，靠系统冗余和低固定成本下的长生存周期。"

## 六、裂缝⑤（潜在）：向学校证明"合理有用" —— 给学校的论证骨架

学校收到材料时会自动带入三个视角：**这东西是真的吗 / 会不会给我校惹麻烦 / 能不能代表学校拿奖**。据此把论证组织成 4 段：

1. **真问题（有用）**：4700 万在校大学生的自学刚需 + "AI 直接给答案"的反学习缺陷——用 Bastani 2025 / Karpicke 2008 两个数据点即可，**不要铺开引用**，学校老师要的是快结论。
2. **真做出来了（合理）**：可运行产品 + 公开代码仓库 + 91 源文件/1.7万行代码/46 API + 三层测试（90+单测/11集成/1000 query 评测）。**给仓库链接和演示视频链接**，比任何形容词都有效。
3. **真符合赛道（合规）**：一页"规则-证据对照"（用 `docs/OPC专项_学校参赛合规材料清单.md` 第二节那张表），让审核老师 3 分钟核完六条要求。
4. **真能成长（潜力）**：三阶段路线 + 硬性门槛（留存≥30% 才进 B 端、标杆校案例再复制），展示"我不是画饼，是有门槛的路线图"。

**给学校讲解时务必讲人话**：把"Kahn 拓扑排序/RAG 路由/两阶段流式"翻译成"系统知道学生学过什么、该学什么、下一步推什么"，技术细节留给附录，别让非技术老师卡在第一页。
