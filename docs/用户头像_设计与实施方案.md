# 用户自定义头像 — 设计与实施方案

> **状态**：已实现（自动化已验证，见 §6；浏览器手测待人工确认）
> **日期**：2026-09-28
> **目标**：新增「用户头像」模块 —— 用户可用本地照片做头像，替换当前默认的人形图标 / 👤 emoji
> **影响范围**：`frontend/src/components/{ActivityBar,MessageBubble}.vue`、`frontend/src/utils/`（新增）、
> `backend/app/api/v1/profile.py`（或新增 `avatar.py`）、`backend-admin/app/core/db.py`、`docs/`

---

## 0. 一句话总览

新增一个**独立于用户画像 JSON 的图片资源**：用户上传本地照片 → 后端裁成正方形并压缩到固定尺寸 → 落
`data/profiles/avatars/{user_id}.png` → 前端通过**带鉴权的 blob 请求**取回并用 `objectURL` 渲染到所有头像位。

**刻意不把头像塞进用户画像 JSON**，理由见 §5.1（有一条前车之鉴）。

## 1. 现状诊断

### 1.1 "用户头像"现在长什么样

| 位置 | 文件:行 | 现状 | 问题 |
|---|---|---|---|
| 左侧活动栏头像 | `frontend/src/components/ActivityBar.vue:138-143` | 内联**人形 SVG**（stroke=currentColor） | 与对话里的 emoji 不一致 |
| 对话气泡（用户侧） | `frontend/src/components/MessageBubble.vue:113-117` | **`👤` emoji** | 违反"项目禁 emoji、不引图标库"的既有约定（该约定写明在 `NodeDetail.vue:117`） |
| 用户画像面板 | `frontend/src/components/UserProfile.vue` | **没有头像** | 面板头部只有文字标题 |

→ 三处需要收敛成同一个"真实头像 / 默认图标"的二选一渲染。

### 1.2 已有能力（可复用的部分）

| 能力 | 位置 | 说明 |
|---|---|---|
| 用户身份 | `backend/app/core/auth.py:77-83` `get_current_user` | JWT Bearer，依赖注入拿 `int user_id` |
| 用户数据目录 | `backend/app/core/profile/store.py:19-30` | `data/profiles/{user_id}.json`（JSON，非 SQLite，原子写） |
| 画像接口 | `backend/app/api/v1/profile.py:34-101` | `GET/PUT/PATCH /api/v1/profile`、notes 增删 |
| 前端画像 API | `frontend/src/api/index.js:70-93` | `getProfile / saveProfileData / …` |
| 图片处理 | `backend/requirements.txt:17` `Pillow>=10.0.0` | 服务端裁剪/压缩**无需新增依赖** |
| 共享响应式状态范式 | `frontend/src/utils/floatingBall.js` | "后端偏好 → 共享 reactive → 多组件消费"，本模块照抄这个结构 |
| 账号删除清理 | `backend-admin/app/core/db.py:202` `purge_user_storage` | 删号会清磁盘数据 —— **新增磁盘数据必须挂进来** |

### 1.3 关键限制（决定了方案形态）

1. **`<img src="/api/...">` 带不上鉴权头**。token 存在 `localStorage['ai_tutor_token']`，由 axios 拦截器挂
   `Authorization: Bearer`（`frontend/src/api/index.js:42-48`）—— 原生 `<img>` 不受拦截器管辖 → 直接写 URL 必然 401。
   **必须走 axios blob → `URL.createObjectURL`。**
2. **项目目前没有任何静态文件服务**：全仓无 `StaticFiles` / `FileResponse`，Vite 也只代理 `/api`。
   所以"把图片放个目录直接给 URL"这条路走不通，要么走接口返回，要么走前端本地。
3. **图片格式白名单里没有 HEIC**：`backend/app/core/kb/parsers/image.py:30` 只认
   `png/jpg/jpeg/bmp/webp/tiff/gif`；Pillow 默认也不吃 iPhone 的 `.heic`。需明确提示用户。

## 2. 关键决策（**已确认 2026-09-28**）

> | 决策 | 结论 |
> |---|---|
> | D1 存哪 | **方案 A：服务端存文件**（跟账号走，换设备可见） |
> | D2 画像加字段 | **不加** —— 头像的"有无"由独立端点的 200/404 表达 |
> | D3 尺寸 | **输出 256×256，输入上限 2MB** |
> | D4 渲染位置 | **活动栏底部头像 + 对话里用户气泡**（用户画像面板不加） |
> | D5 入口 | **设置页新增「头像」小节**（不做活动栏快捷菜单） |

### D1. 头像存哪？—— 本方案的主分叉

| | **方案 A：服务端存文件（推荐）** | **方案 B：纯前端本地** |
|---|---|---|
| 存储 | `data/profiles/avatars/{user_id}.png` | `localStorage` / IndexedDB 的 dataURL |
| 换设备 / 换浏览器 | ✅ 跟着账号走 | ❌ 换台机器就没了 |
| 后端改动 | 新增 3 个端点 + 图片处理 + 删号清理 | **零** |
| 隐私 | 照片会上传到服务器（自托管） | 照片不出本机 |
| 复杂度 | 中 | 低 |
| 容量 | 无压力 | 受 localStorage ~5MB 限制（256px PNG 约 30–100KB，够用） |

**倾向 A**：项目本身是账号体系 + 用户数据全部分区落盘（图谱/画像/知识库/对话），头像作为"账号的一部分"
放服务端语义更一致；且 B 方案在"切换设备"时表现会像 bug。

### D2. 是否往用户画像里加字段？—— **建议不加**

不加字段，头像的"有没有"由 `GET /api/v1/profile/avatar` 的 200/404 表达。
理由见 §5.1 的前车之鉴：往 `ProfilePreferences` 加字段而忘了同步后端模型，会被**静默丢弃**且不报错。

### D3. 处理尺寸与上限（**待确认**）

- 输出：**中心正方形裁剪 + 缩放到 256×256**，PNG（带透明）或 JPEG q85（更小）
- 输入上限：**2 MB**；类型白名单 `png/jpg/jpeg/webp`
- 不做：拖拽裁剪框、多尺寸自适应、动图

### D4. 入口放哪（**待确认**）

- 候选 1：**设置页新增「外观 / 头像」小节**（与现有悬浮球小节并列，`SettingsView.vue:355-436` 同款结构）
- 候选 2：点活动栏头像 → 下拉菜单里加一项「修改头像」（`ActivityBar.vue:147-172` 已有菜单）

## 3. 设计方案（按方案 A 展开）

### 3.1 存储布局

```
data/profiles/
├── {user_id}.json            # 现有：用户画像（不动）
└── avatars/
    └── {user_id}.png         # 新增：头像，每用户一个文件，覆盖写
```

**为什么放这个目录**：`docker-compose.yml:52` 已经挂了 `./data/profiles:/app/data/profiles` ——
头像落在卷内**零 compose 改动**就能持久化（对比：如果另起 `data/avatars/`，就得再加一条卷，漏了就容器一重建全丢）。

写入用"临时文件 + `os.replace`"原子替换，与 `store.py:51-59` 现有画像写入保持同一手法。

### 3.2 后端接口契约

挂在 `/api/v1/profile/avatar` 下（复用 `profile.py` 的 router，或新建 `avatar.py` 再 `main.py` 注册）。

| 方法 | 路径 | 请求 | 响应 | 错误 |
|---|---|---|---|---|
| GET | `/api/v1/profile/avatar` | — | `200` `image/png`，带 `ETag` + `Cache-Control: private, max-age=0, must-revalidate` | `404` 未设置头像 |
| POST | `/api/v1/profile/avatar` | `multipart/form-data`，字段名 **`file`** | `200 {"ok": true, "updated_at": "…", "bytes": 12345}` | `413` 超过 2MB；`415` 类型不支持；`422` 图片解码失败 |
| DELETE | `/api/v1/profile/avatar` | — | `200 {"ok": true}`（幂等，无头像也 200） | — |

要点：
- 三个端点都 `Depends(get_current_user)`；`GET` 只读自己的，**不接受 user_id 参数**（越权面为零）。
- 上传用 `await file.read()` 读进内存后立刻判长度，**再**交给 Pillow（避免超大文件先解码）。
- `POST` 沿用知识库上传的 multipart 约定（字段名 `file`，见 `api/v1/kb.py:70-96`），前端不学两套写法。

### 3.3 图片处理管线

```
bytes → 大小校验(≤2MB) → 扩展名/内容类型白名单 → PIL.Image.open
     → ImageOps.exif_transpose（修正手机照片的旋转）
     → 中心正方形裁剪 → LANCZOS 缩放到 256×256
     → 统一转 RGBA → 存 PNG（原子替换）
```

- `exif_transpose` 必须有：手机竖拍照片带 EXIF Orientation，不修正会出现"上传后躺倒"。
- 统一转 RGBA 再存 PNG：避免调色板/灰度图导致前端渲染异常。
- **不做**：把原图留档、多分辨率缩略图、EXIF 清除策略（当前不对外暴露原图，风险可接受）。

### 3.4 前端模块

新增 `frontend/src/utils/avatar.js`（结构对齐 `utils/floatingBall.js`）：

```js
// 全应用共享的响应式头像状态
export const avatarState = reactive({ url: null, loading: false, version: 0 })

export async function loadAvatar()        // GET blob → createObjectURL；404 → url = null
export async function uploadAvatar(file)  // FormData('file') → POST → 成功后重建 objectURL
export async function removeAvatar()      // DELETE → 释放 objectURL，回到默认图标
function revoke()                         // URL.revokeObjectURL，避免内存泄漏
```

- 请求走 `frontend/src/api/index.js` 里的 axios 实例新增三个方法（`getAvatarBlob / uploadAvatar / deleteAvatar`），
  复用现成的 token 拦截器与 401 处理。
- `HomeView.vue` 挂载时调一次 `loadAvatar()`（与 `loadBallPrefs()` 并列，`HomeView.vue:99` 附近）。
- **objectURL 生命周期**：每次替换/清理前先 `revokeObjectURL`；`url` 为 `null` 表示"没有头像"。

### 3.5 渲染改造点

统一成"有头像用图片，没头像用默认人形 SVG"：

| 文件 | 改法 |
|---|---|
| `ActivityBar.vue:138-143` | `<img v-if="avatarState.url" class="ab-avatar-img" :src="avatarState.url">` + `v-else` 保留现有人形 SVG（该按钮在左下角、设置按钮下方，点开是"用户画像 / 切换账号"菜单） |
| `MessageBubble.vue:113-117` | 用户侧 `<img v-if="avatarState.url">` + `v-else` 人形 SVG（**顺手删掉 `👤` emoji**，消除 §1.1 的不一致） |

> 用户画像面板（`UserProfile.vue`）本次**不加**头像（决策 D4）。

CSS：`.avatar` 已有 `border-radius:50%` + 固定尺寸；图片补 `object-fit: cover`，避免非正方形被拉伸。

## 5. 风险与坑（写出来是为了不再踩）

### 5.1 ⚠️ 前车之鉴：往画像加字段会被静默丢弃

`GET /api/v1/profile` 里读 `data.preferences.floating_ball` 的悬浮球偏好，
**当前其实没生效**（推断依据，未实跑验证）：

- `ProfilePreferences`（`backend/app/models/schemas.py:112-117`）只有 4 个字段，**没有 `floating_ball`**；
- Pydantic v2 默认 `extra='ignore'`，`PATCH /profile` 把 body 解析成 `ProfileData` 时该字段**已被丢掉**，
  根本到不了 `manager.update_data()`（`manager.py:91-101`，且它只合并 `EDITABLE_SECTIONS`）；
- 响应模型同样是 `ProfileData` → 也回传不回来。

**结论**：本方案**不往画像加任何字段**（D2）。头像的"有无"由独立端点的 200/404 表达。
将来若确实要加，必须同步改 `models/schemas.py` + 确认 `EDITABLE_SECTIONS`，并补一条回归测试。

### 5.2 其他

| 风险 | 处置 |
|---|---|
| `<img>` 带不上 `Authorization` | 必须 axios blob + `objectURL`（§1.3-1） |
| `objectURL` 泄漏 | 替换/卸载前 `revokeObjectURL`（§3.4） |
| 手机照片方向不对 | `ImageOps.exif_transpose`（§3.3） |
| HEIC（iPhone 默认格式）不支持 | `415` + 前端提示"请转成 JPG/PNG"（§1.3-3） |
| 删号残留头像文件 | 挂进 `purge_user_storage`（清单 #9） |
| Docker 部署没有新卷 | 复用 `./data/profiles` 卷（§3.1），无需改 compose |
| 隐私：照片上传到服务器 | 自托管实例，需在设置页写明"头像会保存到你的账号下"（**待你确认是否接受**，§8-Q1） |
| 头像被注入 LLM 提示词 | **不会**：`get_summary()` 走 `render_profile_markdown`，只渲染画像字段，与头像文件无关 |

## 7. 边界与未做（YAGNI）

- 不做 GIF 动图、不做视频头像
- 不做拖拽裁剪 UI（只做自动中心方裁）
- 不做多头像 / 头像历史 / 头像款式（DiceBear 之类）
- 不做 CDN / 对象存储（自托管单机，落盘即可）
- 不做"随机头像生成"
- 不做 AI 侧的头像（AI 继续用品牌像素星 `/brand-star.svg`，本次不动）
