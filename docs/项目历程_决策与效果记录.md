## 1. 2026-08-27 ~ 08-29：RAG 双体系与能力铺开

### 1.1 情境

项目已有知识图谱，但"让 AI 讲课时有据可依"缺两样东西：**图谱节点自身的语义检索**与**用户上传教材的检索**。同时前端是单页切换式，"工具感"不足。

### 1.2 关键决策：向量层怎么选（D01）

| 备选 | 结论 | 理由 |
|---|---|---|
| 本地 fastembed / sentence-transformers | ✗ | torch 依赖重（2GB+），与"轻量自研"定位冲突（当时；09-12 才留作可选降级位） |
| LanceDB | ✗ | 引入额外二进制依赖；数据量级（万级 chunk）不需要 |
| **阿里 text-embedding-v4 API + SQLite 存 JSON 向量 + numpy 暴力余弦** | ✓ | 零新依赖、复用现有 SQLite 体系、中文效果最好 |

**配套决策**：图谱 RAG 与上传文件 KB **分开检索、互不混合**（两条数据源语义不同，混检会污染溯源）。

### 1.3 落地与效果

- 新增 `core/rag/`（chunker 按 Markdown 标题分块 + vector_store + manager）与 `core/kb/`（parser + kb_store 多级目录树 + doc_vector_store + kb_manager）。
- 对话侧 `ChatRequest` 增 `kb_node_ids`，`chat_service` 新增 `_build_kb_context()`。
- **实测**：图谱全量索引 6 节点 20 片段，"大模型幻觉"查询命中 **0.7555**；上传《排序.md》检索"快速排序时间复杂度"精准命中。
- **修掉的真 bug**：`nodes.id` 是全局 TEXT 主键，但 `generate_node_id` 只查当前用户 → 跨用户 ID 撞车主键冲突 500。改为 `_node_id_exists_globally()`。

### 1.4 前端布局：三栏 S 布局 → 去顶部栏 → 统一折叠按钮

- 情景：用户要 VSCode/ima 风格（活动栏 + 每页二级侧栏 + 内容区），并明确"顶部栏所有功能下沉"。
- 决策：ActivityBar 做成**自包含**组件（品牌/导航/主题/用户菜单/设置全在里面），HomeView 只保留编排职责（图谱 CRUD、节点详情、画像、引导）。
- 效果：顶部栏彻底删除，界面 = 52px 活动栏 + 内容区；`vite build` 零错误。

### 1.5 混合检索：whoosh + 向量（D02，08-28）

- 情景：用户要"传统关键词 + 向量语义"双搜索。
- 调研：RRF（Cormack SIGIR 2009）、BM25、SPLADE、rank_bm25 / whoosh / faiss / llamaindex。
- **决策**：whoosh（BM25 稀疏）+ 既有 numpy 向量 + **加权分数融合 α=0.6**；先只做上传 KB（图谱侧后置）。
- 关键实现：whoosh 2.7.4 **无中文分析器** → 自定义 `RegexTokenizer(连续CJK) | NgramFilter(2,2)` 做 bigram，英文走 `StemmingAnalyzer`，**不引 jieba**；BM25 分归一化 `score/(score+1)`。
- 统一主键 `chunk_id`（向量侧 `upsert_chunk` 改返回 `lastrowid`）。
- **顺带修的真 bug**：`delete_node` 先删节点再查类型 → `file_node_ids` 恒空 → 向量索引永远清不掉。改为删前先 `collect_descendant_files`。

### 1.6 08-29：一次铺开四项能力

| 能力 | 决策要点 | 效果 |
|---|---|---|
| 学科图谱生成（书→图谱） | 整学科 + 按章节两模式；**AI 直接写库不经人审**；学科复用 tags 第一个非难度标签 | py_compile 通过，学科过滤逻辑临时测试通过 |
| AI 出题（quiz 后端） | **依据优先用上传教材 KB 混合检索**；prompt 强约束"只基于参考材料"；单选/多选/判断/填空规则判分，简答走 LLM | 纯逻辑单测通过；真实 LLM 判分待额度 |
| `fetch_webpage` 工具 | SSRF 防护（黑名单 + DNS 解析后 ipaddress 检查）、仅 http/https、10s 超时、20000 字上限 | `example.com`/`python.org` 抓取成功；`127.0.0.1` 与 `ftp://` 被拒 |
| 语义去重 | 可插拔 embedder：API → sentence-transformers → numpy 哈希；嵌入粗筛 0.78 + **LLM 二次确认**，LLM 失败时 ≥0.90 才保守合并 | 实测"二叉树结构→二叉树" sim 0.918 正确命中 |

### 1.7 解析器解耦 + rag_pipeline 解耦（08-29 收尾）

- **解析器**：`BaseParser` + `ParserRegistry` 按扩展名路由，新增格式 = 新增类 + 注册，**3 个调用方零改动**；可选依赖缺失自动降级为"不支持"；pdf 的扫描版走 dpi=200 渲染 + RapidOCR 回退。老式格式（doc/ppt/xls）**刻意不装外部工具**，保持轻量。
- **RAG 路由**：从"`chat_service` 里硬编码两次检索"改为 `rag_pipeline` 包（`RagSource` 协议 + `GraphRagSource`/`KbRagSource` + 纯规则 `router` + 跨源 `_fuse`）。
- **鲁棒性铁律**：`asyncio.gather` **必须 `return_exceptions=True`**，单源 8s 超时，异常在 `_safe_retrieve` 内吞掉返空 —— 否则任一源 401/超时会让整轮对话炸掉（踩过）。
- 效果：14 项单测（按需开关/跨源融合/异常隔离/超时隔离/全源失败不抛错）。

## 2. 2026-08-30 ~ 08-31：工程化与检索优化

### 2.1 统一 Settings 模块（D03）

- 情景：CORS 白名单硬编码，各处 `os.getenv` 散落。
- 决策：`dataclass Settings` + `from_env()` 集中读取，`load_dotenv` **只在 config.py 执行一次**，全局单例 `settings`；**零新依赖**（不引 pydantic-settings）。
- 效果：`from app.main import app` 构建 OK，51 条路由，CORS 正确注册。

### 2.2 图谱 board（板块）维度（D04）

- 情景：图谱只有学科一级分组，前端一次性全量拉取，"图谱无限生长"。
- 决策：新增 `board` 列 + `graph_middleware.slice_graph(kg, subject, board)` 三级切片（**纯函数、无状态、可独立测试**）。
- 效果：板块侧栏 `GraphBoardSidebar.vue` 上线；历史节点 board 为空统一落"未分组"。

### 2.3 父级扩展 + 宽召回 + RRF（D05）

- 调研结论（反直觉）：**512 token 块比 1024 的 MRR 高 12~18%**（大块语义噪声拉低排序）→ **检索用小块、返回用大块**。
- 决策：父块 = 相邻块拼接（滑窗），固定预算 `PARENT_EXPAND_CHARS=1500` / 最多 `PARENT_MAX_BLOCKS=8`，命中块居中左右交替扩展；**仅扩展后有增益才替换**（纯函数 `_expand_one`，8 项边界测试）。
- 召回侧：直接 `top_k=5` 太窄 → **宽召回 Top-30 → RRF 融合 → 精排 Top-5**；RRF 基于排名 `1/(k+rank+1)`，对分数尺度不敏感（测试证明它不被单路极端高分主导）。
- 效果：`rrf_fuse` 9 项 + 集成 5 项全绿。

### 2.4 主题体系重构（html.dark + EP 变量）

- 情景：部分输入框不随主题切换。
- 根因三条：① **Element Plus 从未引入官方暗色 `dark/css-vars.css`，也没在 html 挂 dark class**（元凶）；② 自定义组件写死颜色；③ 自定义体系用 `[data-theme]` 而 EP 要 `html.dark`。
- 决策：统一到 `html.dark` + CSS 变量（EP 官方 / VueUse / Tailwind 通用标准），`theme.js` 重写为 dark/light/system 三模式；`isDark` 由函数改 computed（调用点同步改，勿再加括号）。

### 2.5 健壮性两项：alert→ElMessage、LLM 重试

- 前端统一 `utils/feedback.js`（notifyError/Success/Info/Warning），约定"以后提示一律走它"。
- LLM 重试：**3 次 + 指数退避 + 抖动**；`_is_retryable` 只认瞬时错（timeout/conn/rate limit/429/5xx），**401/400 不重试**（重试无意义）。
- 效果：mock 验证 500 连败 2 次后第 3 次成功（退避 1.4s→2.4s）；400 只调 1 次即抛。

### 2.6 测试体系从零搭建（D06）

- 情景：RAG 链路 9 大块功能全部落地但**零测试**，README 自承"仅靠手工验证"。
- 决策：三层测试——① 单元（全 mock，零网络，3.3s 跑完）→ ② 集成（mock 确定性 hash 嵌入）→ ③ 离线评测集（CMRC2018 trial，256 文档 / 1000 查询）。
- **评测结果（mock 嵌入，1000 queries）**：vector R@1 0.470 / bm25 **0.964** / hybrid(RRF) 0.766 / fuse(α=0.6) 0.818。
- **关键发现**：弱向量（mock hash）下 RRF 融合**拖累强路**（0.766 < bm25 0.964），加权融合更稳 → 真实 text-embedding-v4 待复跑定夺（额度欠费未跑）。
- **性能修复**：whoosh 每次 commit 固定 ~2.4s（Windows Defender 扫 segment 文件）→ `upsert_bulk` + `begin_deferred/flush`，256 篇 **180s → 4.7s**。
- 坑：`rag_pipeline/__init__.py` 的 `from .pipeline import pipeline` 让**包属性 `pipeline` 被子模块遮蔽成单例** → 测试要 monkeypatch 私有常量时必须 `importlib.import_module` 取真模块（同一坑在 `kb_manager` 模块上也复现过）。

### 3.1 Collector：教育资料采集（设计先行，多轮拍板）

**流程纪律**：用户要求"**先建文档详细讨论、再写代码**" —— 产出 `docs/教育资料采集模块_设计讨论.md`（v0.1 讨论稿，经 6 轮讨论定稿）。

**关键决策**（每条都影响后续实现）：

| 决策 | 结论 | 理由 |
|---|---|---|
| 版权双模式 | `personal`（个学习/合理使用，L0-L2 全采）/ `commercial`（仅 L0） | 复用画像 `preferences.usage_mode`，零迁移 |
| 商用过滤实现 | **零迁移**：按目录前缀 `自动采集/L2` 排除（复用 kb 既有 node_ids 过滤） | 不新增列、不改 schema |
| 学科目录 | 大学 14 门类 117 一级学科 + K12 + 考核类，四层树 | 用户要覆盖面 |
| 「资源形态」维度 | 挂 `knowledge:quiz` 配比画像：K12/考核类题库优先、大学资料优先 | 用户关键洞察 |
| 任务机制 | 进程内 `asyncio.create_task` + 状态表 | uvicorn 单 worker，不上 arq |
| 登录站 | Cookie 会话复用（合法站）；**盗版库不内置适配器** | 合规红线 |

**实现（B1 全量 + B2 全量）**：`core/collector/`（types/store/http/subjects/manager + adapters：wikipedia/wikibooks/oiwiki）+ `api/v1/collector.py` 5 端点 + chapterizer 规则切章 + pipeline_ingest + 离线种子 40 词条。

**踩坑（都是真坑）**：
- `user_profile.update_field` 有 `FIELD_WEIGHTS` 白名单 → `usage_mode` 不登记就**静默存不进去**。
- 原迁移逻辑 `data.update(raw)` 整覆子 dict → **默认新增字段读旧 JSON 时丢失**（潜伏 bug，被 usage_mode 暴露）；改 `_merge_with_defaults` 字段级合并。
- `seed_collector.py` 的 mock 嵌入**必须是 `async def`**，同步 def 会 `TypeError: object list can't be used in await`。

### 3.2 直接触发 Agent Loop 重构的评估（09-05 晚）

**用户判断**："agent 循环比较垃圾。"

**代码级诊断（6 条事实）**：
1. 没有真 loop —— `call_llm_tools` 是**固定两轮**（LLM→工具→LLM 即止），二次响应再带 `tool_calls` 被**静默丢弃**；
2. `/chat/stream` 两阶段割裂（阶段1 纯文本流式不带 tools，阶段2 后台才跑工具）；
3. 单条用户消息触发 2~3 次互不关联的 LLM 调用（对话 + 工具 + GraphAnalyzer）；
4. 无 max_iters / 无循环护栏 / 无 trace；
5. 图谱全量摘要注入 system prompt，随图谱膨胀（无上限）；
6. `fetch_webpage` 同步 httpx 阻塞事件循环。

**公允评价**：错误码体系、指数退避、SSRF、RAG 鲁棒性、用户隔离都不错 —— **弱的是 loop 语义本身**。

### 5.10 09-13 环境陷阱、启动脚本与 Docker

**代理残留陷阱（两次复现）**：
- 现象：`pip install` 全线 `ProxyError`，但 `pip config list` 空、无 proxy 环境变量、无 `pip.ini`。
- 根因：**Windows 注册表 WinINet 代理残留**（`ProxyEnable=1` + `ProxyServer=127.0.0.1:7890`，代理程序已退出）；urllib3 在 Windows 读 `getproxies_registry()`。
- **边界更正**：httpx **也读注册表**（trust_env → `urllib.getproxies()`）→ 应用联网同样可能受影响，**不要假设"只有 pip 受影响"**。
- 清理点只有 2 处：① 注册表 `ProxyEnable` 置 0（**保留 `ProxyServer` 值**，下次开代理免填）+ 补发 `InternetSetOption(39/37)` 刷新；② `git config --global --unset http.proxy/https.proxy`（git 不读系统代理，必须单独清）。

**start.ps1「启动完成后服务莫名全关」（源码级定位）**：
- 根因：`uvicorn/supervisors/basereload.py` 在 win32 用 `os.kill(pid, signal.CTRL_C_EVENT)` 重启 worker，而 **CTRL_C_EVENT 广播给同一控制台所有进程**；reloader 自己有 `is_restarting` 忽略它，共享控制台的启动脚本没有 → `Start-Sleep` 被 Ctrl+C 打断 → `$ErrorActionPreference="Stop"` 让脚本终止 → `finally` 把前端一起关掉。
- **关键判别点（很好用）**：日志里**从来没有** `[WARN] 后端进程已退出` → 说明脚本自己被打死，不是子进程退出。
- 排除的方案：`[Console]::CancelKeyPress` 吞信号（只多活一两拍）；`--reload-include/exclude`（**缺 watchfiles 时无效**，uvicorn 源码明写）。
- 修法：后端**必须独立控制台**（`-WindowStyle Hidden` + stderr 重定向 `logs/uvicorn-dev.log`）+ `--reload-dir app` + `--no-use-colors` + 启动前清残留 + `finally` 用 `taskkill /T /F` 杀整棵进程树。
- 效果：热重载后脚本仍 `alive=True`、前端 5173 存活（旧版这里两者都会死）；收尾后 `8000=0 5173=0 residual=[]`。

**孤儿 worker 事件（09-12 排查）**：`uvicorn --reload` 是双层进程，原 finally 只 `Stop-Process` 单个 PID → worker 变孤儿继续 Listen 8000 → 新后端绑定失败退出，但**孤儿仍响应 `/api/health` 200** 骗过健康检查 → 表现为"启动完成后服务莫名全关"。

**Docker 三个真问题（09-13 排查，用户直觉正确）**：
1. 镜像停在 13 天前（对应 `f8b7a74`），**只有 `docker compose up -d --build` 才同步代码**（光 `up -d` 永远跑旧版）。

**局域网共享本机服务**：

## 7. 踩坑与陷阱总表

### 7.1 Windows / 环境

| 坑 | 现象 | 处置 |
|---|---|---|
| **系统代理残留** | `pip` 报 `ProxyError`，但 pip 配置全空 | 清注册表 `ProxyEnable`（保留 `ProxyServer`）+ `git config --unset http(s).proxy`；**httpx 也读注册表** |
| **uvicorn CTRL_C_EVENT 广播** | 热重载一次，启动脚本与前端一起死 | 后端独立控制台；判别：日志无 `[WARN] 后端进程已退出` = 脚本被打死 |
| **孤儿 `spawn_main` worker** | 端口 8000 被占但"看起来服务正常"（孤儿仍响应 health 200） | `taskkill /T /F` 杀整棵树；启动前按端口清残留 |
| **缺 watchfiles** | `--reload` 降级 StatReload，**监视整个 backend**（跑测试也触发重载） | `--reload-dir app`；`pip install -r requirements.txt` 补装 |
| 网络类别翻转 | 昨天不用加防火墙规则，今天连不上 | `Get-NetConnectionProfile` 判别；Docker 规则只有 `Public` |
| 本机自测骗人 | `curl` 自己 IP 恒 200 | 只能另一台设备实测 |
| PowerShell `Remove-Item Env:X` | 新 shell 里变量不存在 → 报错并中断整条命令 | 每次 `execute_command` 是独立 shell，直接不写该句 |

### 7.2 Python / 代码

| 坑 | 现象 | 处置 |
|---|---|---|
| 包 `__init__` 遮蔽子模块 | `from app.core.kb import kb_manager` 拿到**单例对象**；`monkeypatch.setattr("app.core.kb.kb_manager.embed_texts")` 报 AttributeError | `importlib.import_module("app.core.kb.kb_manager")` 取真模块（`rag_pipeline.pipeline` 同款） |
| monkeypatch 实例方法不触发 descriptor 绑定 | 类级 patch 才生效 | `monkeypatch.setattr(KbManager, "_embed", fake)` |
| `nodes.user_id` 外键 | 脚本/测试直接建节点 FOREIGN KEY 失败 | 先 `INSERT OR IGNORE INTO users` |
| SQLite 无 ALTER 改约束 | 需要重建表迁移 | `isolation_level=None` 手动 BEGIN/COMMIT + 幂等跳过 |
| `model_dump()` 全量 vs PATCH | 未提交字段被重置为默认 | `model_dump(exclude_unset=True)` + 递归合并 |
| 读操作有写副作用 | 空模板永久注入 system prompt（白烧 token） | 读纯读，用 `is_empty_profile()` 判空（`weight=0` 字段不算内容） |
| 中文字符串进 HTTP 头 | `Content-Disposition` `UnicodeEncodeError` 500 | RFC 5987 `filename*=UTF-8''<quote(...)>` |
| `np.dot` 不校验维度 | 换嵌入模型未重建 → ValueError 500 | 维度不符 → skip + warning |
| whoosh commit 慢 | 每次 commit ~2.4s（Windows Defender 扫 segment） | `upsert_bulk` + `begin_deferred`（180s → 4.7s） |
| whoosh 无中文分析器 | 单字查询命中不了 | 自定义 CJK bigram；**单字查询天然不中**（向量路兜底） |
| d3.forceLink 悬空边 | 抛 `node not found` 被 try-catch 吞掉 → SVG 中断（表现为"节点为 0"） | 构建 links 时过滤悬空端点 |
| 前端组件样式覆盖 | 同特异性靠加载顺序，不稳定 | 覆盖子组件根元素**必须带父前缀**（多一个选择器分量） |
| `flex-shrink: 0` 继承 | column 布局下内容溢出被裁而非滚动 | 显式 `flex-shrink: 1` |
| IME 与 Enter | 中文输入法选词时字符丢失 | `compositionstart/end` 跟踪合成态，合成中忽略 Enter |
| `-{}-` 与 `-{}` | 测试里写错标记导致断言失败 | 本就不是合法 MediaWiki 标记 |
| 微信/工具输出转义 | 输出里的 `\"` 是 JSON 转义，别误判为脚本 bug | 读文件确认 |
| **仓库并发写入** | 报错与文件内容对不上（另一会话改了） | 先查 mtime/`Get-FileHash` 取同一快照 |

### 7.3 模型 / 协议

| 坑 | 现象 | 处置 |
|---|---|---|
| MiniMax `<think>` | 推理内容以文本裹进 `message.content`（流式也是） | `reasoning_split=True` 或 `strip_think_tags` |
| mcp v2 属性命名 | `Tool.inputSchema`/`isError` 在 pydantic 侧是 snake_case | 用 `input_schema`/`is_error` |
| ddgs 多后端组合 | `bing,mojeek` 直接抛 `DDGSException` | fallback 自己写循环，不用多后端参数 |
| ddgs 后端消失 | 9.16 移除了 `bing` 后端 → 兜底链失效 | 主后端改 Bing RSS，ddgs 收敛为 `("auto",)` |
| OpenAI usage 位置 | token 统计为 0 | usage 在 **response 层**不在 message 层 |
| force_finish 用 system | 兼容网关对多 system 行为不确定 | 改 user 消息 + try 兜底 |
| 检索为空 → 断言图谱为空 | 对学生个人数据的**确定性幻觉** | 提示词禁止断言图谱状态 |
