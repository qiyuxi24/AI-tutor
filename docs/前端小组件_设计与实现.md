## 一、悬浮球小窗（站内）（已实现 2026-09-27）

### 1.1 需求

1. 悬浮球 + 小窗，**只在本应用内部**（不涉及别人的网页、不装扩展）。
2. 小窗**只放对话**。
3. **对话页不显示**悬浮球（那里已有完整对话区）。
4. 开关放**设置**里，且跟账号走。

> **需求变更记录**：早先按"跨站"（浏览器扩展）设计并实现过一版；2026-09-27 改为**站内**后，那一版产物（`extension/` 整个目录、`views/EmbedView.vue`、`#/embed` 路由、`utils/extensionBridge.js`）**已全部删除**。排除跨站路线的理由见 §1.7。

### 1.4 关键设计决策

1. **可见性由父级控制**：`visible = 已开启 && viewMode !== 'chat'`。球的存在理由是"在别的页面也能随手问一句"；对话页已有完整对话区 → 不需要它。需求里的"对话界面不能存在"就落在这一行。
2. **小窗与主对话共用同一个 `chatStore`**：小窗里聊的内容，切回对话页就在那儿，不搞两套历史。可行前提：`HomeView` 各视图是 `v-if` 切换，进对话页时其它页面已卸载，不会出现两个 `ChatArea` 同时活着；`visible=false` 会让小窗自动收起。
3. **偏好用共享响应式状态**（`floatingBall.js::ballPrefs`）：设置页一改，球立刻响应，无需刷新或事件总线。
4. **偏好的真值源在服务端**（`UserProfile.preferences.floating_ball`）：跟账号走，换设备一致；写入沿用设置页既有"读完整画像 → 合并 → 全量 PATCH"模式，避免覆盖 `usage_mode` 等其它字段。
5. **球的位置只存本机**（`localStorage`）：摆放是浏览器窗口的属性，不是账号的属性。
6. **手动微调优先于预设**：球位 / 窗位 / 窗尺寸都存本机，优先于设置页预设；用户在设置页**主动**改预设时清掉对应手动微调（靠 `ballPrefsMeta.revision` 区分"用户改的"与"首次加载"），否则预设看起来像"点了没反应"。

### 1.5 验收清单

- [ ] 设置 → 悬浮球 → 启用 → 切到图谱页，右下角出现球
- [ ] 切回对话页 → 球消失，且原本开着的小窗自动收起
- [ ] 点球展开小窗，能流式问答（`thinking` / 工具事件也正常渲染）
- [ ] 小窗里发的消息，切回对话页能接着看（同一会话）
- [ ] 拖动球到左下角松手 → 吸附；刷新页面后位置还在
- [ ] `Esc` 收起小窗；Tab 能聚焦到球、Enter 开合
- [ ] 设置里把开关关掉 → 球立即消失（不用刷新）
- [ ] 系统开启"减少动态效果" → 球不再有缩放动画

### 1.6 已知限制 / 后续（都不阻塞使用）

- 快捷键 `Alt+J` 未实现（2026-09-29 起**不再预留** `hotkey` / `theme` 空字段：没人读的配置项就是下次误判的坑；真做时再加）。
- 小窗里不能切换历史会话（"只放对话"的必然结果；换会话请回对话页）。
- 缩放把手是**鼠标专用**（无键盘等价操作）；键盘/触屏用户走设置里的三档预设；8 个把手除右下角外**不可见**（靠指针形状提示，刻意如此）。
- 手动尺寸/位置存本机，多标签页之间不即时同步（刷新后一致）；移动端窄屏未专门适配（`default_open` 建议关闭）。

### 1.7 附：为什么不做"跨站"

**结论**：网页无法向其它网站注入 UI（浏览器安全模型），要出现在别人家的网页上就必须让用户**装一次扩展** —— 额外动作 + 地址匹配、全站权限告警、上架审核等持续成本；而需求只要站内，所以直接做站内版，零安装、零配置、零成本。若将来确要跨站，那套设计（扩展 MV3 / 悬浮球脚本 / iframe 小窗 / token 交接 / 存储分区 / CSP `frame-ancestors` / 商店素材）需重新评估，**不要凭记忆复原**（"站点页面要不要手填扩展 ID""第三方 iframe 的 localStorage 按 (顶层站点, iframe 源) 分区"两个坑当初都踩过）。

### 1.8 修订记录：2026-09-29 审查 + 去硬编码 + 修 3 个 bug

- **① 偏好其实根本没存进去（功能整体失效，最严重）**：`ProfilePreferences`（`backend/app/models/schemas.py`）是 Pydantic 模型，`extra='ignore'` 默认生效，没声明 `floating_ball` → 前端 PATCH 上来的字段**在进业务层之前就被丢掉**；请求 200 + 前端乐观更新照常成功 → 只表现为"设置里开了，刷新就没了"。→ 显式声明该字段；回归 `backend/tests/test_profile_floating_ball.py`（断言"读得回来"，不是"接口 200"）。
- **② 松手吸附从没生效过**：`pos` 拖动时已被 `clamp` 到 `EDGE`(16)，吸附判定却拿钳制后的值直接比 `< SNAP`(16)，两条恒为假 → 死代码。→ 比较前先减掉 `EDGE`。
- **③ 设置页选的角位在刷新后不生效**：`pos` 只在组件 setup 时算一次，而服务端偏好异步到达；到达时球早已按默认档落位，且无 watch 重算。→ 加 `hasManualPos`：本机拖过就以本机为准，否则跟随角位预设（含偏好到达与视口变化）。
- **去硬编码**：尺寸预设表上收到 `utils/floatingBall.js::BALL_SIZE_PRESETS`（原来组件抄一份、设置页再抄 key）；可选值白名单 `BALL_SIZES`/`BALL_CORNERS` 同时供校验与设置页选项；几何魔法数字全部具名（`GAP`/`CLICK_SLOP`/`ABS_MIN_W`…）；球的 48px 由 JS 下发，CSS 不再写第二份；`ballPrefs.offset` 与 `BALL_DEFAULTS.offset` 原本是**同一个对象** → 已拆开；设置页点"已选中项"不再白写一次。

### 1.9 附：顺带修掉的一个既有 bug（与本功能无关）

`chatStore.js` 调 `sendMessageStream` 时多传了一个已被删除的 `mode.value` 位置参数，而现行签名是 `(messages, callbacks, currentNode, kb)`（`api/index.js:115`）→ `callbacks` 实际收到字符串，解构出的 `onToken`/`onDone`/`onError` **全是 undefined**（表现为对话没有流式渲染、`loading` 也不复位）。已删掉该参数。

## 二、用户自定义头像（已实现 2026-09-28）

### 2.1 现状诊断

| 位置 | 现状 | 问题 |
|---|---|---|
| 左侧活动栏头像（`ActivityBar.vue:138-143`） | 内联**人形 SVG**（stroke=currentColor） | 与对话里的 emoji 不一致 |
| 对话气泡用户侧（`MessageBubble.vue:113-117`） | **`👤` emoji** | 违反"项目禁 emoji、不引图标库"的既有约定 |
| 用户画像面板（`UserProfile.vue`） | **没有头像** | 面板头部只有文字标题 |

→ 三处收敛成同一个"真实头像 / 默认图标"的二选一渲染。

**已有能力（可复用）**：用户身份 `auth.get_current_user`（JWT → `int user_id`）；用户数据目录 `data/profiles/{user_id}.json`；画像接口 `GET/PUT/PATCH /api/v1/profile`；图片处理 `Pillow>=10.0.0`（**无需新增依赖**）；共享响应式范式照抄 `utils/floatingBall.js`；删号清理 `purge_user_storage`（**新增磁盘数据必须挂进来**）。

**关键限制（决定方案形态）**：

1. **`<img src="/api/...">` 带不上鉴权头**（token 存 `localStorage['ai_tutor_token']`，由 axios 拦截器挂 `Authorization`，原生 `<img>` 不受管辖）→ 直接写 URL 必然 401，**必须走 axios blob → `URL.createObjectURL`**。
2. **项目目前没有任何静态文件服务**（全仓无 `StaticFiles`/`FileResponse`，Vite 只代理 `/api`）→ "放目录给 URL"走不通。
3. **图片格式白名单没有 HEIC**（`kb/parsers/image.py` 只认 `png/jpg/jpeg/bmp/webp/tiff/gif`；Pillow 默认不吃 `.heic`）→ 需明确提示用户。

### 2.2 关键决策（已确认 2026-09-28）

| 决策 | 结论 |
|---|---|
| D1 存哪 | **方案 A：服务端存文件**（跟账号走，换设备可见）—— 项目本身是账号体系 + 用户数据全部分区落盘，头像作为"账号的一部分"语义更一致；纯前端方案在"切换设备"时表现会像 bug |
| D2 画像加字段 | **不加** —— 头像的"有无"由独立端点的 200/404 表达（理由见 §2.5 前车之鉴） |
| D3 尺寸 | **输出 256×256，输入上限 2MB**；不做拖拽裁剪框、多尺寸自适应、动图 |
| D4 渲染位置 | **活动栏底部头像 + 对话里用户气泡**（用户画像面板不加） |
| D5 入口 | **设置页新增「头像」小节**（与悬浮球小节并列，`SettingsView.vue` 同款结构；不做活动栏快捷菜单） |

### 2.3 设计方案（方案 A）

**存储布局**（放 `data/profiles/` 下）：`data/profiles/avatars/{user_id}.png`（每用户一个文件，覆盖写）。`docker-compose.yml` 已挂 `./data/profiles:/app/data/profiles` → 落卷内**零 compose 改动**即持久化。写入用"临时文件 + `os.replace`"原子替换，与既有画像写入同一手法。

**后端接口**（挂 `/api/v1/profile/avatar`）：

| 方法 | 路径 | 请求 | 响应 | 错误 |
|---|---|---|---|---|
| GET | `/profile/avatar` | — | `200` `image/png`，带 `ETag` + `Cache-Control: private, max-age=0, must-revalidate` | `404` 未设置 |
| POST | `/profile/avatar` | `multipart/form-data`，字段名 **`file`** | `200 {"ok": true, "updated_at":…, "bytes":…}` | `413` >2MB；`415` 类型不支持；`422` 解码失败 |
| DELETE | `/profile/avatar` | — | `200 {"ok": true}`（幂等，无头像也 200） | — |

要点：三端点都 `Depends(get_current_user)`，`GET` 只读自己的、**不接受 user_id 参数**（越权面为零）；上传用 `await file.read()` 读进内存后立刻判长度、**再**交 Pillow（避免超大文件先解码）；`POST` 沿用知识库上传的 multipart 约定（字段名 `file`）。

**图片处理管线**：`bytes → 大小校验(≤2MB) → 扩展名/内容类型白名单 → PIL.Image.open → ImageOps.exif_transpose（修正手机旋转）→ 中心正方形裁剪 → LANCZOS 缩放到 256×256 → 统一转 RGBA → 存 PNG（原子替换）`。`exif_transpose` 必须有（否则竖拍照片"上传后躺倒"）；统一转 RGBA 避免调色板/灰度图渲染异常；**不做**原图留档、多分辨率缩略图、EXIF 清除策略。

**前端模块**：新增 `utils/avatar.js`（结构对齐 `utils/floatingBall.js`）：`avatarState` 共享响应式状态 + `loadAvatar()`（GET blob → `createObjectURL`；404 → `url=null`）+ `uploadAvatar(file)` + `removeAvatar()` + `revoke()`。请求走 `api/index.js` 的 axios 实例新增三个方法（`getAvatarBlob/uploadAvatar/deleteAvatar`），复用现成 token 拦截器与 401 处理；`HomeView.vue` 挂载时调一次 `loadAvatar()`（与 `loadBallPrefs()` 并列）；**objectURL 生命周期**：每次替换/清理前先 `revokeObjectURL`。

**渲染改造**（统一成"有头像用图片，没头像用默认人形 SVG"）：`ActivityBar.vue` 头像位 `<img v-if="avatarState.url">` + `v-else` 现有人形 SVG；`MessageBubble.vue` 用户侧同上（**顺手删掉 `👤` emoji**，消除 §2.1 的不一致）。CSS：图片补 `object-fit: cover`，避免非正方形被拉伸。

### 2.5 风险与坑（写出来是为了不再踩）

**⚠️ 前车之鉴：往画像加字段会被静默丢弃** —— 悬浮球偏好（`data.preferences.floating_ball`）就是踩过这个坑的例子，2026-09-29 已**实跑确认**：`ProfilePreferences` 当初没声明 `floating_ball`，Pydantic v2 默认 `extra='ignore'` → `PATCH /profile` 把 body 解析成 `ProfileData` 时该字段**已被丢掉**，根本到不了 `manager.update_data()`；响应模型也是 `ProfileData` → 也回传不回来；表现极具迷惑性（请求 200 + 前端乐观更新成功 → 只表现为"设置里开了，刷新就没了"）。**结论**：本方案**不往画像加任何字段**（D2），头像的"有无"由独立端点的 200/404 表达。将来若确要加，必须同步改 `models/schemas.py` + 确认 `EDITABLE_SECTIONS`，并补一条断言"值读得回来"（而非"接口 200"）的回归测试。

其它：

| 风险 | 处置 |
|---|---|
| `<img>` 带不上 `Authorization` | 必须 axios blob + `objectURL` |
| `objectURL` 泄漏 | 替换/卸载前 `revokeObjectURL` |
| 手机照片方向不对 | `ImageOps.exif_transpose` |
| HEIC（iPhone 默认格式）不支持 | `415` + 前端提示"请转成 JPG/PNG" |
| 删号残留头像文件 | 挂进 `purge_user_storage`（清单 #9） |
| Docker 部署没有新卷 | 复用 `./data/profiles` 卷，无需改 compose |
| 隐私：照片上传到服务器 | 自托管实例，设置页写明"头像会保存到你的账号下" |
| 头像被注入 LLM 提示词 | **不会**：`get_summary()` 走 `render_profile_markdown`，只渲染画像字段，与头像文件无关 |
