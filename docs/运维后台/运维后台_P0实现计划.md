# 运维后台 P0 实现计划

## 目标
创建一个完全独立的运维管理后台，与主系统解耦。

## 背景与调研依据（业界 RBAC / 账号管理）

> 来源：《运维后台_账号管理功能调研.md》（2026-09-19，已并入本节后删除）。以下为与"独立运维后台"方案直接相关的要点，作为功能取舍依据。

- **权限模型**：主流为 **RBAC**（用户→角色→权限→资源，适合角色固定的 SaaS）、ABAC（属性级细粒度）、ReBAC（关系 / 层级）。本项目规模小，采用**简化 RBAC**：角色 `super_admin` / `admin`，权限为**功能级（菜单可见性）**，不做资源级 / 字段级。
- **账号管理功能清单（业界）**：用户列表（分页 / 搜索 / 筛选 / 排序 / 批量 / 导出）、用户创建（手动 / 邮箱邀请 / 批量导入）、详情与编辑（角色 / 状态 / 登录历史 / 操作日志）、密码管理（忘记密码 / 管理员重置 / 密码策略）、会话管理（多设备 / 强制下线）。本项目 P0 只取 **列表 / 详情 / 禁用·启用 / 重置密码 / 改角色**（见下文 P0 功能清单）。
- **安全与审计**：敏感操作（删号 / 改角色 / 重置密码）需**二次确认 + 审计日志**，记录旧值与新值；批量操作限制单次数量。→ 对应本项目的 `admin_audit_logs` 表（见文末）。
- **框架选型**：业界有 Refine / React Admin / Django Admin 等；本项目**不引入**重后台框架，前端用 Vue 3 + Element Plus 自建，与主系统技术栈一致。
- **密码哈希**：`bcrypt`（与主系统 `backend/app/core/auth.py` 一致）。

（其余业界功能——邀请链接、登录历史、操作审计扩展、多租户——列为 **P1/P2**，不在 P0。）

## P0 功能清单

### 1. 用户列表
- 展示所有用户（分页）
- 搜索（按用户名/邮箱）
- 筛选（按状态：正常/禁用）

### 2. 用户详情
- 查看用户资料
- 修改用户角色（普通用户/管理员）
- 禁用/启用用户

### 3. 密码重置
- 管理员重置用户密码

## 技术方案

### 后端 (FastAPI + 原生 sqlite3，无 ORM)
```
backend-admin/
├── app/
│   ├── main.py                  # 入口 + lifespan（建表 / 初始化超管）
│   ├── api/v1/admin/
│   │   ├── __init__.py          # 路由汇总
│   │   ├── auth.py              # 登录 / me
│   │   ├── users.py             # 列表/详情/禁用/启用/重置密码/改角色
│   │   └── audit_logs.py        # 审计日志查询
│   └── core/
│       ├── config.py            # dataclass + os.getenv（沿用主系统约定）
│       ├── db.py                # 连接依赖 + 审计日志写入 + 建表
│       └── admin_auth.py        # bcrypt + JWT
├── tests/test_admin_api.py      # 13 项 API 测试
├── conftest.py
└── requirements.txt             # 版本与主系统对齐
```

约定（与主系统保持一致）：
- 密码哈希用 `bcrypt`（同 `backend/app/core/auth.py`）
- 不引入 pydantic-settings / SQLAlchemy，配置用 dataclass + os.getenv
- 业务更新与审计日志在同一事务内提交

### 前端 (Vue 3 + Element Plus + Vite)
```
frontend-admin/
├── src/
│   ├── api.js              # 统一 axios 实例：自动带 token，401 回登录页
│   ├── router.js
│   ├── views/
│   │   ├── Login.vue
│   │   ├── Layout.vue      # 侧边栏布局
│   │   ├── Users.vue       # 用户管理
│   │   └── AuditLogs.vue   # 审计日志
│   └── main.js
└── vite.config.js          # /api → http://localhost:8001
```

## 管理员账号设计

### 表结构 (admin_users)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| username | VARCHAR(50) | 登录名（唯一） |
| password_hash | VARCHAR(255) | 密码 |
| role | ENUM | super_admin / admin |
| created_at | DATETIME | 创建时间 |
| last_login_at | DATETIME | 最后登录时间 |

### 审计日志表 (admin_audit_logs)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT (UUID) | 主键 |
| admin_id | TEXT | 管理员 ID |
| admin_username | TEXT | 操作人（冗余，避免关联查询） |
| action | TEXT | login / reset_password / disable_user / enable_user / update_role |
| target_user_id | TEXT | 目标用户 ID |
| target_username | TEXT | 目标用户名 |
| ip_address | TEXT | 来源 IP（取自请求，非写死） |
| details | TEXT | 变更详情，如「角色 user → admin」 |
| created_at | TEXT | 操作时间（ISO8601, UTC） |

### 初始化
- 初始超级管理员：`admin` / `admin123`（仅首次初始化，可用 `ADMIN_DEFAULT_PASSWORD` 覆盖）
- 运维后台使用独立的 `ADMIN_SECRET_KEY`，与主系统 token 互不通用
