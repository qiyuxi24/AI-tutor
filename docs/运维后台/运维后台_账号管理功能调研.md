> 调研日期：2026-09-19

## 1. 概述

运维后台（Admin Panel）的账号管理模块是 B2B SaaS 产品的核心组成部分。本调研涵盖业界常见的设计模式、核心功能、技术实现方案，为 TutorAgent 后续开发提供参考。

## 2. 权限模型

### 2.1 主流模型对比

| 模型 | 全称 | 适用场景 | 复杂度 |
|------|------|----------|--------|
| **RBAC** | Role-Based Access Control | 大多数 SaaS 产品，角色固定 | 低 |
| **ABAC** | Attribute-Based Access Control | 细粒度控制，如按部门/时间/IP | 高 |
| **ReBAC** | Relationship-Based Access Control | 层级组织，如"汇报给"关系 | 中 |

### 2.2 RBAC 核心概念

```
用户 (User) → 角色 (Role) → 权限 (Permission) → 资源 (Resource)
```

**三层规则（The 3-Layer Rule）**：
1. **最小工作单元**：一个人无需他人协作即可完成的动作
2. **角色聚合**：相同动作的人群归为角色
3. **权限绑定**：角色关联到具体权限

### 2.3 业界实践

- **Slack/Notion/Linear**：
  - 基础三角色：`Admin`（管理员）、`Member`（成员）、`Viewer`（查看者）
  - 企业级自定义角色：`Billing Manager`、`Project Manager`
  - 每个租户独立的角色体系

- **常见内置角色**：
  - `Super Admin` / `Owner`：最高权限，可管理所有
  - `Admin`：管理本租户用户和配置
  - `Editor`：可编辑内容
  - `Viewer`：只读访问
  - `Billing`：仅财务管理

### 2.4 权限粒度

| 级别 | 示例 | 实现方式 |
|------|------|----------|
| 功能级 | 能否访问"用户管理"页面 | 菜单/路由可见性 |
| 资源级 | 能否编辑某篇文章 | 数据行级权限 |
| 字段级 | 能否查看用户邮箱 | 列级脱敏 |

## 3. 核心功能清单

### 3.1 用户列表

| 功能 | 说明 |
|------|------|
| 分页/无限滚动 | 后端分页为佳，前端虚拟滚动优化大列表 |
| 搜索 | 按姓名/邮箱/ID 模糊搜索 |
| 筛选 | 按角色/状态/创建时间/部门 |
| 排序 | 按注册时间/最后登录/姓名 |
| 批量操作 | 批量禁用/批量删除/批量修改角色 |
| 导出 | CSV/Excel 导出用户数据 |

### 3.2 用户创建

| 方式 | 说明 |
|------|------|
| 手动创建 | 管理员填写信息直接创建（需设置初始密码） |
| 邮箱邀请 | 发送邀请链接，被邀请人自行设置密码 |
| 批量导入 | CSV 模板批量导入 |

**邀请工作流（推荐）**：
```
1. 管理员输入邮箱 → 2. 系统生成邀请链接（含 token）→ 3. 发送邮件 →
4. 用户点击链接 → 5. 设置密码 → 6. 完成注册
```

**邀请链接关键字段**：
- `token`：唯一标识，过期时间
- `expires_at`：过期时间（通常 24-72 小时）
- `invited_by`：邀请人 ID
- `role`：预设角色

### 3.3 用户详情/编辑

| 功能 | 说明 |
|------|------|
| 基本信息 | 姓名、头像、邮箱、手机 |
| 角色分配 | 切换用户角色 |
| 状态管理 | 启用/禁用账户 |
| 登录历史 | 查看最近登录记录 |
| 操作日志 | 用户关键操作审计 |

### 3.4 密码管理

| 功能 | 说明 |
|------|------|
| 忘记密码 | 邮件重置链接 |
| 管理员重置 | 强制重置（生成随机密码或让用户首次登录改密码） |
| 密码策略 | 长度/复杂度/过期时间 |
| 首次登录改密 | 强制首次登录修改临时密码 |

### 3.5 会话管理

| 功能 | 说明 |
|------|------|
| 当前会话 | 查看当前登录设备 |
| 多设备登录 | 支持多设备同时在线 |
| 强制下线 | 管理员踢出指定会话 |
| 并发限制 | 限制同一账号同时在线设备数 |

## 4. 技术实现

### 4.1 数据库设计

**用户表（简化）**：

```sql
CREATE TABLE users (
    id TEXT PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    name TEXT,
    password_hash TEXT,
    role TEXT DEFAULT 'member',
    status TEXT DEFAULT 'active',  -- active, disabled, pending
    email_verified BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login_at TIMESTAMP,
    tenant_id TEXT  -- 多租户
);

CREATE TABLE user_roles (
    id INTEGER PRIMARY KEY,
    name TEXT UNIQUE NOT NULL,
    permissions JSON,  -- 权限列表
    description TEXT
);

CREATE TABLE invitations (
    id TEXT PRIMARY KEY,
    email TEXT NOT NULL,
    token TEXT UNIQUE NOT NULL,
    role TEXT DEFAULT 'member',
    invited_by TEXT,
    expires_at TIMESTAMP,
    status TEXT DEFAULT 'pending',  -- pending, accepted, expired
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    user_id TEXT REFERENCES users(id),
    device_info TEXT,
    ip_address TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP
);
```

### 4.2 API 设计

| 端点 | 方法 | 说明 |
|------|------|------|
| `/admin/users` | GET | 用户列表（分页/筛选） |
| `/admin/users` | POST | 创建用户 |
| `/admin/users/{id}` | GET | 用户详情 |
| `/admin/users/{id}` | PATCH | 更新用户 |
| `/admin/users/{id}` | DELETE | 删除用户 |
| `/admin/users/{id}/disable` | POST | 禁用用户 |
| `/admin/users/{id}/reset-password` | POST | 重置密码 |
| `/admin/invitations` | POST | 发送邀请 |
| `/admin/invitations/{token}/accept` | POST | 接受邀请（用户侧） |
| `/admin/roles` | GET | 角色列表 |
| `/admin/roles` | POST | 创建角色 |
| `/admin/permissions` | GET | 权限列表 |

## 5. 安全考量

### 5.1 认证与授权

- **认证**：
  - JWT（短期 Access + 长期 Refresh）
  - Session 方式（适合管理后台）
  - SSO/OAuth（企业级）

- **授权检查点**：
  - API 层面：每个写操作校验权限
  - 路由层面：菜单/页面根据角色显隐
  - 数据层面：查询自动附加 tenant_id 过滤

### 5.2 敏感操作

| 操作 | 要求 |
|------|------|
| 删除用户 | 二次确认 + 审计日志 |
| 修改角色 | 记录旧值/新值 |
| 重置密码 | 需管理员二次验证 |
| 批量操作 | 限制单次数量（如≤100） |

### 5.3 审计日志

记录关键操作：
- 用户创建/删除/禁用
- 角色变更
- 权限变更
- 密码重置
- 敏感数据查看

## 7. TutorAgent 适配建议

### 7.1 功能优先级

| 优先级 | 功能 |
|--------|------|
| P0 | 用户列表、查看详情、禁用/启用 |
| P1 | 角色管理、邀请链接、密码重置 |
| P2 | 登录历史、操作审计、批量操作 |

### 7.2 简化模型

考虑到 TutorAgent 主要是单一产品，初期可简化为：

```
角色：Super Admin, Admin, User
权限：功能级（菜单可见性）
```

### 7.3 可复用现有模块

| 模块 | 说明 |
|------|------|
| 现有 `auth.py` | 复用登录/注册逻辑 |
| 现有用户表 | 扩展 role/status 字段 |
| 现有事件系统 | 复用 SSE 推送管理事件 |
