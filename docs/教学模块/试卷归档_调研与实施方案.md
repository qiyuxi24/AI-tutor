> 创建：2026-09-26
> 用户诉求：上传试卷（含拍照 / 扫描 PDF）→ 拆成逐题 → 归档入库 → 关联知识点；**前端展示与题目数字化渲染本期不做**。
> 范围声明：**本文只覆盖「归档」这一步**（解析 → 拆题 → 落库 → 建立关联）。展示、可视化、题目渲染、跨卷考频属后续独立议题。

## 一、核心结论

1. **70% 的代码已经存在，只是没接线**。`split_quiz()` 已实现完整整卷拆题（题号递增防误切、选项、答案区回填、题型/分值推断），但全仓只被测试调用。归档工作的主体是**接线 + 落库 + 补兜底**，不是从零写拆题器。
2. **LLM 只做语义补全，不做切分边界**。边界判定（题号、大题、答案区）必须由正则负责——它确定、免费、可解释、可单测。LLM 负责低置信度题块的答案补全与题干规范化。**整卷一次性丢给 LLM 是最容易踩的坑**：长卷输出必被截断，后半卷静默消失且不报错。
3. **「保证准确性」的正确形态是可量化的置信度闸门**，不是"上 LLM 就准了"。四个客观指标（题号连续性 / 答案覆盖率 / 分值总分一致性 / 拆题产出非空）任一不达标 → 整卷标 `needs_review`，前端提示而非假装成功。
4. **拍照与扫描件的解析能力已有选型结论，但未实施**。主路径 `qwen-vl-ocr-2025-11-20`（约 ¥0.0015/页，**必须锁版本，不用动态版**），方案全文见上游视觉解析文档 §4.4。**拍照特有的透视畸变 / 光照 / 手写**是本文补充的增量（§3.2）。
5. **带图题目只做「裁剪 + 引用」，不做图形理解**。`PyMuPDF` 已有能力拿 bbox 并裁剪；`caption` 用本地几何配对（免费且比 OCR 坐标准）。图形理解是另一个数量级的投入，且对"归档"这一步没有收益。
6. **题目的两个归属方向，用两种手段实现**：
   - 题目 → 试卷：`questions.paper_id` 单向外键（一题必属一卷）。
   - 题目 → 知识点：`question_nodes` **多对多关联表**（综合题跨知识点），结构与已有 `node_themes` 同构。
   - 知识点 → 题目：**运行时反查**。**禁止**把题目列表写进节点 `.md` 正文——会撞 AI 权限护栏（`_guard_human_content`）、会造成 MD 与题库不一致且无修复机制、会污染主题聚类与出题去重。
7. **不上 QTI 等题目交换标准**。它们是"跨平台题库迁移"的设计，XML 冗长、渲染生态重。自用归档用 `Pydantic schema` + LaTeX + 图片路径足够。唯一该引入的场景是将来要把题库交付给外部 LMS——那时写一个导出适配器即可，不影响存储层（§3.4）。

## 三、调研

### 3.1 LLM 在拆题中的正确介入点

**结论：分工而非取代。**

| 环节 | 负责方 | 理由 |
|---|---|---|
| 题块边界（题号 / 大题 / 答案区定位） | **规则**（`split_quiz`） | 确定性信息，正则比 LLM 更稳、可解释、可单测、零成本 |
| 低置信度题块的语义补全 | **LLM** | 补答案、规范题干、拆多问、判题型 |
| 扫描件整体兜底 | **LLM 分段**（按页 / 按大题分段后逐段抽取） | 绝不整卷一次请求 |

**必须显式定义"何时触发 LLM"**（即"保证准确性"的落地形态）：

| 触发条件 | 含义 |
|---|---|
| 题号不连续（`n != prev + 1` 出现跳号） | 题号行被 OCR 打散或存在小问 |
| 答案覆盖率 < 阈值（题数 vs 答案区条目数） | 答案区未被正确识别 |
| 识别总分 ≠ 卷面标注总分 | 分值抽取有误或漏题 |
| `split_quiz` 返回空但文本非空 | 题号行完全不可识别 |

任一命中 → 整卷标 `needs_review`（落 `papers.parse_status`），并记录命中原因到 `parse_meta`。

**M3 调用坑（复述硬约束）**：批量结构化抽取必须 `thinking=False`，长 JSON 显式调大 `max_tokens`，否则"空正文 / 硬截断"交替出现。

### 3.2 拍照（上游文档未覆盖的增量）

拍照 ≠ 扫描件，多三层失真：

| 失真 | 手段 | 难度 |
|---|---|---|
| 透视畸变（斜拍 / 纸面弯曲） | 四点检测 + 透视变换（OpenCV `getPerspectiveTransform`），或前端上传前先矫正 | ★★★ |
| 光照不均 / 阴影 / 手指桌面入镜 | 自适应二值化 + 边缘裁切 | ★★★ |
| **手写体** | ⚠️ **本期明确排除** | — |

**手写体划界**：本期只处理**印刷体试卷**（含教师版带答案的卷子）。学生手写答卷识别（数学过程、连笔）是行业公认的"最后一公里"，识别率会毁掉整条链路。手写批改应独立立项。

### 3.3 带图题目：裁剪 + 引用

```
图元识别 → 按 bbox 裁剪 → 存 data/quiz/{uid}/images/{qid}_{n}.png
        → 题目字段存 images: [{path, bbox, position, caption}]
```

- `get_image_info()` 拿 bbox，`get_pixmap(clip=...)` 裁剪（零新依赖）。
- `caption` 用**本地几何配对**：找图 bbox 下方 / 上方最近的文本块，优先匹配「图 3-2 xxx」正则。
- 过滤装饰性小图（面积 < 页面 3%）与跨页重复的水印。
- **不做**：几何图 / 函数图 / 电路图 / 化学结构式的语义理解。原图是唯一展示真相；可选让 `qwen3-vl-plus` 生成文字描述供检索，但本期归档可先不做。

### 3.4 数字化编码体系：有标准，但本项目不上

| 层面 | 成熟方案 | 结论 |
|---|---|---|
| 题目内容交换 | **QTI 3.0**（1EdTech，XML，2026-09 仍在维护） | ❌ 不上。为「跨平台题库迁移」设计，XML 冗长、渲染生态重 |
| 课程包分发 | SCORM / Common Cartridge | ❌ 不相关（给 LMS 用） |
| 学习行为上报 | xAPI | ❌ 不需要 |
| 知识点编码 | 课标 / 教材章节编码体系 | ❌ 用现有图谱 `nodes.id` + `themes` 层级即可，已有主归属多对多体系 |

**唯一该引入标准的时点**：需要把题库导出交付给外部 LMS。届时写一个 QTI 导出适配器，仅影响导出层，**现在不引入也不会挡路**。

## 四、数据模型

全部落在 quiz 库（`data/quiz/{uid}/quiz.db`），避免跨库事务。

```sql
-- 新建：试卷实体
papers (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id            INTEGER,
  title              TEXT,
  subject            TEXT DEFAULT '',
  source_kb_node_id  INTEGER,        -- 关联 kb_store.nodes.id（上传文件；可为空）
  source_hash        TEXT,           -- 内容 hash：重复上传幂等
  exam_type          TEXT DEFAULT '',-- 期中/期末/高考/模拟/单元测
  year               TEXT DEFAULT '',
  total_points       INTEGER DEFAULT 0,
  question_count     INTEGER DEFAULT 0,
  parse_status       TEXT DEFAULT 'ok',  -- ok / needs_review / failed
  parse_meta         TEXT DEFAULT '{}',  -- JSON：解析方式、OCR 页数、置信度命中原因
  created_at         TEXT DEFAULT (datetime('now'))
)

-- questions 加列（需自写补列迁移，quiz_store 无现成机制）
--   paper_id INTEGER, paper_qnum INTEGER, paper_section TEXT, needs_review INTEGER DEFAULT 0

-- 新建：题目 ↔ 知识点（多对多，结构照抄 node_themes）
question_nodes (
  question_id  INTEGER,
  node_id      TEXT,                 -- 图谱 nodes.id（TEXT！）
  user_id      INTEGER,
  weight       REAL DEFAULT 1.0,
  is_primary   INTEGER DEFAULT 0,    -- 唯一主归属，归一化逻辑复用 set_node_themes
  source       TEXT DEFAULT 'ai',    -- human 不被重算覆盖
  created_at   TEXT DEFAULT (datetime('now')),
  PRIMARY KEY (question_id, node_id)
)
```

**两个方向都是查询，不是冗余写入**：

| 需求 | 查询 |
|---|---|
| 试卷 → 题目（按卷面顺序） | `SELECT * FROM questions WHERE paper_id=? ORDER BY paper_qnum` |
| 题目 → 来源 | `questions.paper_id` + `paper_qnum` + `paper_section` |
| 知识点 → 考过的题（含来源卷） | `SELECT q.*, p.title FROM question_nodes qn JOIN questions q ON q.id=qn.question_id LEFT JOIN papers p ON p.id=q.paper_id WHERE qn.node_id=?` |
| 题目 → 知识点 | `SELECT node_id, weight, is_primary FROM question_nodes WHERE question_id=?` |

> 加表 / 加列纪律（AGENTS.md §1）：新表写自己的 schema + 迁移；新列**必须写进补列清单**，否则老用户库缺列且 `CREATE TABLE IF NOT EXISTS` 不会补。

## 五、分期实施

**本期目标 = 归档闭环，前端零改动。**

| 阶段 | 内容 | 依赖 | 交付 |
|---|---|---|---|
| **A1** | `papers` 表 + `questions` 补列迁移 + `question_nodes` 表 | 无 | 数据模型就位，可单测 |
| **A2** | `split_quiz` 接线：试卷上传 → 拆题 → 落库（含 `paper_qnum` / `paper_section`） | A1 | 印刷体 PDF 可归档；`papers.parse_status` 生效 |
| **A3** | 置信度闸门（四个指标）+ `needs_review` 标记 + `parse_meta` 留痕 | A2 | 拆错了系统自己承认 |
| **A4** | LLM 兜底：仅对命中闸门的题块补答案 / 规范题干 | A3 | 拆题准确率提升，成本按命中量付费 |
| **A5** | 题目 → 知识点映射：检索粗召回 → LLM 闭集判定 → 写 `question_nodes` | A2 | 归档数据可回答"这题考什么" |
| **A6** | 图形裁剪 + caption 几何配对 | A2 | 带图题目归档完整 |
| **A7** | 扫描 / 拍照接入 `qwen-vl-ocr-2025-11-20` + 拍照预处理 | 上游 P1 | 扫描件 / 拍照可归档 |

**建议顺序**：A1 → A2 → A3 → A5 先跑通「印刷体 PDF 全闭环」，再补 A4（准确率）、A6（图形）、A7（扫描拍照）。理由：A7 依赖外部引擎与预处理，是外部依赖最重的一环，不应挡在最前面。

**明确不做（本期）**：前端展示、题目渲染（KaTeX / 图片 / 表格）、考点可视化、跨卷考频、图形理解、手写答卷识别、QTI 导出。

## 六、验证方案

### 6.1 样本集（自建，覆盖归档失效模式）

| 类型 | 份数 | 校验点 |
|---|---|---|
| 印刷体 PDF（文本层完整） | 3–5 | 基准：拆题应近乎全对 |
| 带答案区的卷子 | 2 | 答案回填准确性 |
| 带图的卷子（几何 / 函数图） | 1–2 | 图形裁剪与 caption 配对 |
| 扫描件（无文本层） | 1 | 云 OCR 通路 |
| 拍照件（斜拍 / 光照不均） | 1 | 预处理 + OCR 通路 |

### 6.2 指标

| 维度 | 指标 |
|---|---|
| 拆题 | 题数匹配率、题号连续性、答案覆盖率、分值总分一致性 |
| 结构 | 选项归属正确率（抽样人工） |
| 映射 | 题目 → 知识点 top-1 / top-3 准确率（人工标注 30–50 题） |
| 图形 | caption 配对准确率 |
| 端到端 | 同一份卷子重复上传不产生重复入库（幂等） |

### 6.3 对照

- 基线：现状（试卷走通用 `chunk_text`）
- 实验：A2 后（纯规则拆题）
- 实验：A4 后（规则 + LLM 兜底）

预期：A2 在印刷体上已接近可用；A4 的增益集中在 OCR 打散的扫描件与答案分离的卷子。

## 七、风险与边界

| # | 风险 | 缓解 |
|---|---|---|
| 1 | **拆错静默入库污染归档**（最严重） | A3 置信度闸门 + `needs_review` + `parse_meta` 留痕；不达标不标 `ok` |
| 2 | 长卷 LLM 输出截断 | 分段请求；`finish_reason == "length"` 判失败重试 |
| 3 | 重复上传产生重复试卷 | `papers.source_hash` 幂等 |
| 4 | 答案册与试卷分离成两个文件 | **本期不支持**（跨文件对齐难度陡增），只做「卷内自带答案」 |
| 5 | 拍照识别率不可控 | 先做透视 / 光照预处理再送 OCR；手写明确排除 |
| 6 | 知识点映射准确率无标准答案 | 粗召回 + 闭集判定（禁用开放生成）；低置信度落 `needs_review` |
| 7 | quiz 库加列漏写迁移 | 新列必须进补列清单，老库先跑迁移再读 |
| 8 | MD 与题库双写不一致 | **架构上禁止**：知识点→题目只反查，不写节点 MD |

**YAGNI 边界**：本地 DocVLM（无 GPU，上游已否决）、图形语义理解、手写识别、QTI / SCORM、跨卷考频分析、学生答卷批改。
