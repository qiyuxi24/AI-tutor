## 二、两条已确认的设计决策（含用户"行不行"的正式回答）

### D1 · 节点级：答错 −20，下限 10

`floor_rule` 已选「答错 −20，最低保底 10 分」。

⚠️ **"了解"这一档在代码里不存在**，必须如实说明：现有四档是 `0 未开始 / 1–29 薄弱 / 30–69 学习中 / ≥70 已掌握`；另有一套**仅用于导出文本**的六档标签 `knowledge.py:1300` `{0:未学, 1:入门, 26:熟悉, 51:熟练, 76:精通}`。用户口语的"了解知识那个掌握度"最接近"入门/薄弱"这一层。本次把下限定为 **10**：
- 落在 weak(1–29) 桶，四档文案零改动；
- **始终 > 0** → 答错过的节点永不退回"从未接触/unstarted"，图谱上永远看得出"这块动过"；
- 如果用户其实指六档里的「入门(≥1)」或「熟悉(≥26)」，**只改一个常量 `MASTERY_WRONG_FLOOR`**（以及一句口径文字），不动任何结构。

### D2 · 小节级：按节数比例拆解 —— **行，按 20/N 采纳**

用户原话：「当然应当有一个比例，比如每个小节按数量进行一个比例的拆解行不行」。**回答：行。** 精确口径：

```
penalty = max(1, round(20 / N))     # N = 该节点的小节总数（section_learn_progress()["total"]）
扣分下限同为 10
```

理由（写进代码注释与答辩口径）：
- 一道**节点级**题考的是整个知识点，答错扣满 20；
- 一道**小节级**题只考 `1/N` 个知识点，按"数量比例"把 20 分均摊，只扣 `20/N` → 节数越多的节点，单节答错对整体掌握度的冲击越小，符合"比例拆解"的直觉；
- `round()` 用 Python 银行家取整；`max(1, …)` 是**必须的守卫**：`N=40` 时 `20/40=0.5 → round=0`，若不兜底，答错就完全不掉分，"题目做错了就可以修改掌握度"会静默失效 → 最少扣 1 分，保证负反馈永远有信号；
- 小节原有的状态机（第一次 `retry` 不降级、第二次 `downgrade` 标 confused、全通过置 100）**完全不变**，只是在答错分支上**叠加**一次节点掌握度下调。第一次答错与第二次答错都扣（"做错了就改"是逐次生效的），但每次只扣 `20/N`，不会被一次连续错刷到下限。

### D3 · 扣分绝不能把掌握度"抬高"（实测边界，必须实现）

真实演示库 `data/quiz/5/quiz.db` 唯一错题 `question_id=1` → 节点 `subspace_definition_and_examples`，**当前 mastery = 0**。若简单写 `after = max(10, before - 20)`，`before=0` 会算出 `10` —— 答错反而涨了 10 分。故 `floor` 语义定义为：

```
raw = min(100, before + delta)
if floor is not None and delta < 0:        # 下限只对「扣分」生效
    after = min(before, max(floor, raw))
else:                                      # 正向 delta / floor=None：旧行为，逐字节兼容
    after = max(0, raw)
```

两道守卫，缺一不可：
- `min(before, …)`：既不低于下限，也**不高于扣分前的 `before`** —— 否则 mastery=0 的节点答错会被抬到 10（涨分）。
- **`delta < 0` 才进下限分支**：否则 `before=0, delta=+20, floor=10` 会被 `min(0, …)` 夹成 0，把答对加分也吃掉（Task 1 的 `test_floor_does_not_clamp_positive_delta` 就是专守这个）。

`floor=None` 为默认值 → 所有既有调用（含答对 +20）行为不变；`floor` 只在判分答错（负 delta）时传。

### D4 · 错题定义 = 「最近一次作答为错」，不建表

`wrong_question_ids()` 判据取 `attempts` 中"该题 id 最大的那条 `correct=0`"。**学生订正（换答案再答对）后自动移出错题本**，因此不需要"移出"接口、不需要状态列、不需要 `review_queue` 表。备选口径「曾经答错过」（`SELECT DISTINCT ... WHERE correct=0`）更简单但订正后仍挂着，不作为一期默认；若日后要改成它，只改这一个方法的 SQL。

```python
# backend/app/core/kg/mastery.py —— 替换签名与 :137-138 两行，docstring 的"参数"段补一段
def add_mastery(self, node_id: str, delta: int, *, caller: str = "human",
                 reason: str = "manual", evidence: str = "",
                 floor: int | None = None) -> int:
    """...（原 docstring 保留，在参数段追加）
            floor:    **扣分下限**（只在 delta<0 时生效；None = 沿用旧的 [0,100] 夹取）。
                     扣分时的结果 `min(before, max(floor, min(100, before+delta)))`：
                     既不低于 floor，也**不高于扣分前的 before** —— 否则 mastery=0
                     的节点答错会被抬到 floor，反而涨分（2026-11-16 实测边界）。
                     正向 delta 一律走旧分支（floor 传了也不生效，避免把加分夹掉）。
    """
    self._guard_human_content(caller, node_id)
    delta = int(delta)
    with self._write_txn():
        row = self._conn.execute(
            "SELECT mastery FROM nodes WHERE id = ? AND user_id = ?",
            (node_id, self.user_id),
        ).fetchone()
        if row is None:
            raise ValueError(f"节点不存在：{node_id}")
        before = int(row["mastery"] or 0)
        raw = min(100, before + delta)
        if floor is not None and delta < 0:
            after = min(before, max(int(floor), raw))
        else:
            after = max(0, raw)
        self._conn.execute(
            "UPDATE nodes SET mastery = ?, updated_at = ? WHERE id = ? AND user_id = ?",
            (after, datetime.now().isoformat(), node_id, self.user_id),
        )
        if after != before:
            self._record_mastery_event(node_id, before, after, reason, evidence)
    self._invalidate_cache()
    return after
```

```python
def add_mastery(self, node_id, delta, *, caller="human", reason="manual",
                evidence="", floor=None):
    """增量替身：与真实实现同口径（floor 钳位 + 封顶 100，返回落库值）。"""
    if self._mastery_fails:
        raise PermissionError("人类创建的节点")
    cur = int(self._nodes.get(node_id, {}).get("mastery") or 0)
    delta = int(delta)
    raw = min(100, cur + delta)
    if floor is not None and delta < 0:
        after = min(cur, max(int(floor), raw))
    else:
        after = max(0, raw)
    self._nodes.setdefault(node_id, {})["mastery"] = after
    self.mastery_updates.append((node_id, after))
    self.mastery_meta.append((reason, evidence))
    self.increment_calls.append((node_id, int(delta)))
    return after
```

```python
def apply_mastery_after_answer(kg: KnowledgeGraph, node_id: str,
                               correct: bool, evidence: str = "") -> str:
    """判分后**确定性**更新掌握度（这就是"答对就直接更新进度"）。

    规则（2026-11-16 起双向，刻意简单可解释）：
      - 答对 → +20，封顶 100（reason=quiz_correct）
      - 答错 → −20，下限 10（reason=quiz_wrong）；下限只夹在本次扣分里，
        绝不把 mastery=0 的节点抬高（真实演示库错题节点就是 0 分）。

    ⚠️ 走**增量**接口 `kg.add_mastery`（2026-10-07 多端修复）：读-改-写必须留在
    同一写事务内，否则两端同时判分会 lost update。floor 钳位也在该方法内部。
    caller="human"：这是**用户答题**的结果，用 "ai" 会被 `_guard_human_content` 拦下。
    返回一句给模型看的状态描述（空字符串 = 没更新）。
    """
    node_id = resolve_node_id(kg, node_id)
    if not node_id:
        return ""
    node = kg.get_node(node_id)
    if node is None:
        return ""
    current = int(node.get("mastery", 0) or 0)
    name = node.get("name") or node_id
    if correct and current >= 100:
        return f"「{name}」掌握度已是满值 100，无需再提升。"
    delta = MASTERY_CORRECT_GAIN if correct else -MASTERY_WRONG_PENALTY
    kwargs = ({"reason": "quiz_correct"} if correct
              else {"reason": REASON_QUIZ_WRONG, "floor": MASTERY_WRONG_FLOOR})
    try:
        new = kg.add_mastery(node_id, delta, caller="human",
                             evidence=evidence, **kwargs)
    except Exception as e:
        logger.warning(f"判分后更新掌握度失败（{node_id}）: {e}")
        return ""
    if correct:
        logger.info(f"判分答对 → 掌握度 {node_id}: {current} → {new}")
        return f"已把「{name}」的掌握度从 {current} 提升到 {new}。"
    logger.info(f"判分答错 → 掌握度 {node_id}: {current} → {new}")
    return (f"已把「{name}」的掌握度从 {current} 调整为 {new}"
            f"（答错，保底 {MASTERY_WRONG_FLOOR} 分）。")
```

```python
# backend/app/core/quiz/quiz_store.py —— 放在 record_attempt 之后（:399 后）；方法体内缩进对齐原类
def wrong_question_ids(self) -> set[int]:
    """当前处于「答错」状态的题目 id（错题本派生口径，**不建表、不加列**）。

    判据 = 该题**最近一次作答** `correct=0`（`attempts.id` 自增，MAX(id) 即最近）。
    学生订正（换答案再答对）后自动移出 → 不需要"移出"接口或状态列。
    老库无 attempts 行 → 空集。异常由调用方降级处理（侧边栏不能因此打挂）。
    """
    rows = self._conn.execute("""
        SELECT a.question_id
        FROM attempts a
        WHERE a.correct = 0
          AND a.id = (SELECT MAX(b.id) FROM attempts b
                      WHERE b.question_id = a.question_id)
    """).fetchall()
    return {int(r["question_id"]) for r in rows}
```
