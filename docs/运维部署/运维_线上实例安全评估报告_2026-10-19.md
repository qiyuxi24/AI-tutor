## 一、结论摘要

**一句话**：现有防护对"互联网无差别扫描"是有效的（今日 456 次请求、157 次扫描探针，零穿透）；但对"知道弱口令 / 拿到通行 Cookie / 与访客同链路"的攻击基本不设防，**演示期存在可被直接利用的真实风险**。

| 维度 | 结论 |
|---|---|
| 无差别扫描 / 爬虫 / 漏洞探针 | ✅ **有效**：门口 302/401、容器端口只绑回环，今日全部被挡 |
| 弱口令 / 默认口令 | ❌ **无效**：应用管理员账号实测仍可用弱口令登录（P0-1） |
| 传输层（嗅探 / 中间人） | ❌ **无效**：全站 HTTP 明文，口令、通行 Cookie、JWT 均可被同链路截获（P0-2） |
| 口令爆破（门口） | ⚠️ **弱**：无限速、fail2ban 未覆盖 nginx、门口访问日志关闭（P1-1） |
| 通行 Cookie 管理 | ⚠️ **弱**：静态共享字符串、7 天、JS 可读、不可吊销（P1-2） |

## 六、关键发现（按严重度）

### P0-1 应用管理员仍在使用弱口令（实测可直接登录）

- **证据**：使用与项目默认配置一致的弱口令调用 `POST /api/v1/auth/login`，返回 **HTTP 200 并签发 JWT**（具体口令不在本文重复）；同一口令错误时返回 401，说明验证链路正常。
- **影响**：演示模式已打开登录页（`/` → 200 直达登录页），**任何拿到 IP 的人只要猜中/知道这个弱口令，即可进入系统**，看到全部图谱/对话/资料，并以管理员身份消耗 LLM 额度。应用层无登录失败锁定（仅 5 次/分/IP 的进程内限流，可轮换 IP 绕过）。
- **为何严重**：门口层在演示模式下是敞开的，此时"应用弱口令"就是唯一一道门。
- **建议（演示前必做）**：登录后到系统设置里修改密码（同时建议 ≥12 位、非同项目默认值、不与门口口令复用）；如前端无改密入口，可调用 `POST /api/v1/auth/change-password`。改完用新口令登录验证一次。
- **验证命令**：`curl -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8080/api/v1/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"<RSA密文>"}'` 应返回 200（新口令）/401（旧口令）。

### P0-2 全站无 TLS（HTTP 明文）

- **证据**：公网 443 无响应；`/gate` Basic 凭据、通行 Cookie、JWT、RSA 公钥全部走明文 HTTP。
- **影响**：同一链路（会场 Wi-Fi、代理、运营商）上的被动嗅探可直接拿到门口口令与 7 天有效的通行 Cookie；主动 MITM 还能替换 `public-key`，使 RSA 传输加密失效。演示场景常在公共网络，风险高于平时。
- **建议**：有域名就 `certbot --nginx`（免费、自动续期）或走 Cloudflare 代理；无域名时优先申请一个便宜域名（IP 证书少见且贵）。最低限度：演示用网络不要与陌生人共享、演示结束立即 `off` 并轮换通行 Cookie。

### P1-1 门口无速率限制、且不记访问日志（爆破不可见）

- **证据**：`/gate` 没有任何 `limit_req`；`access_log off`；fail2ban 只配了 `sshd`；error.log 仅记录 "password mismatch"（今日 2 条）。
- **影响**：攻击者可无限速尝试门口口令（`.htpasswd` 为 `$apr1` MD5 弱哈希，离线可 crack）；且这些尝试不进 access.log，**没人会发现**。一旦门口口令被猜中（或泄露），即获得通行 Cookie。
- **建议**：门口加限速 + fail2ban 过滤 + 打开访问日志（见 §8 阶段 A/B 配置）。

### P1-2 通行 Cookie 是静态共享令牌（7 天、JS 可读、不可吊销）

- **证据**：门页 JS 写入固定 32 位十六进制值，`max-age=604800`、`SameSite=Lax`、无 `HttpOnly`/`Secure`；nginx 侧只做字符串相等 `map`。
- **影响**：① 任何人转发该 Cookie（截图/粘贴/日志/浏览器同步）即全站通行 7 天；② 不能单独吊销某个访客，泄露后必须改所有人的值；③ JS 可读 → 前端一旦有 XSS 即外泄。
- **建议**：改成"签名 + 过期"的票据（nginx `secure_link` 或 `auth_request` 小服务 / Cloudflare Access），服务端可设短 TTL（如 12h）并可按人吊销；短期至少把 `max-age` 降到演示时段 + 演示后轮换值。

### P1-3 演示模式"3 席位"是全局锁，3 条长连接即可占满

- **证据**：`limit_conn_zone $server_name zone=tutor_seat:1m;`（key 是 `$server_name` 而非客户端 IP）→ 全站共享 3 条 SSE；第 4 条实测 429，前 3 条断开后恢复 200。
- **影响**：任何人用 3 个 `curl` 长连接即可让所有评委的实时刷新（图谱更新/出题通知）失效 → 演示"看起来卡死"。成本几乎为零（DoS）。
- **建议**：改成 key=`$binary_remote_addr`（每 IP 限 2 条）+ 保留全站兜底（如 8 条）（见 §8 阶段 A 配置）。若坚持"3 人"，可用"登录占席"的应用层方案（工作量大，演示前不建议）。

### P2-1 注册口默认开放（应用层）

- **证据**：`POST /api/v1/auth/register` 应用层始终存在，无邀请码、无限流、密码最短 6 位；演示模式才用 nginx 精确路径 403 临时关闭。
- **影响**：非演示期，只要有通行 Cookie 就能批量注册账号并消耗 LLM 额度（成本风险 > 数据风险）。
- **建议**：应用层加 `ALLOW_REGISTRATION` 开关（默认 false），长期用邀请码；给 LLM 调用加每用户/每日 token 配额（已有 `llm_usage` 记录基础）。

### P2-2 应用登录限流可绕过、无账号锁定

- **证据**：`login_rate_limiter` 为进程内内存字典（5/60s/IP），`--workers 1` 下有效但重启清零；按 IP 计数，无账号维度锁定。
- **影响**：IP 轮换/代理池可绕过；对特定账号可慢速撞库。
- **建议**：加"账号维度失败计数 + 指数退避/临时锁定"；重要账号（admin）登录成功/失败写审计。

### P2-3 JWT 24 小时有效、无吊销

- **证据**：`access_token_expire_minutes = 60*24`；无黑名单/版本号，登出仅前端删 token。
- **影响**：token 泄露（HTTP 明文场景下概率不低）可用满 24h。
- **建议**：短期演示场景可接受；长期缩短到 2–8h + 刷新令牌 + `jti` 吊销表。

### P2-4 缺少安全响应头

- **证据**：响应头仅 `Server: nginx`（`server_tokens off` 已隐藏版本）；无 `Content-Security-Policy`、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、`Strict-Transport-Security`（无 TLS）。
- **影响**：点击劫持（gate 页/应用可被 iframe）、MIME 嗅探、XSS 兜底缺失。
- **建议**：加 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: no-referrer`；CSP 需先评估前端资源（演示前别贸然上，避免白屏）。

### P2-5 运维后台登录无速率限制

- **证据**：`backend-admin/app/api/v1/admin/auth.py:30` 的 `/login` 只做 `verify_password`，无任何限流/锁定；后台 token 8h。
- **影响**：后台登录页虽在门口之后，但一旦门口被穿透（口令泄露/Cookie 泄露），后台账号可被爆破（用户名 `admin` 可猜）。
- **建议**：后台登录加限流（复用主站 `RateLimiter` 或 nginx `limit_req` 对 `/api/v1/admin/login` 单独设小桶）。

### P2-6 无备份；密钥与用户模型配置未持久化

- **证据**：`crontab` 空、无 backup 定时器；`data/keys`、`data/llm` 不在 compose 挂载列表；`/opt/ai-tutor/backend/data`、`/opt/ai-tutor/backend/app/data` 仍有旧数据副本。
- **影响**：误删/重建/磁盘故障不可恢复；容器重建导致 RSA 私钥重生成（影响小）但用户自配模型（`data/llm`）会丢。旧副本含用户数据，属于隐性泄露面。
- **建议**：每日 `sqlite3 .backup` + `tar` 卷目录到异地/OSS；把 `data/keys`、`data/llm` 加进挂载；清理旧副本（先备份再删）。

### P3 级（演示前可不改，记录在案）

| 编号 | 发现 | 建议 |
|---|---|---|
| P3-1 | 容器以 root 运行、未 drop capabilities、无只读根、无内存/CPU 限制 | 长期：`USER app`、`cap_drop: ALL`、`read_only`、`mem_limit` |
| P3-2 | nginx 1.18（Ubuntu 22.04 维护中，安全更新随 unattended-upgrades）；`.htpasswd` 用 apr1/MD5 | 跟踪更新；换 bcrypt（`htpasswd -B`） |
| P3-3 | 主机还有另一项目容器 `edututor-*`（回环 18000/18080），与本站共用 Docker/内核 | 确认其维护方与补丁状态；生产建议分机 |
| P3-4 | 无集中告警：失败登录/5xx/流量突增无通知 | 长期：日志采集 + 阈值告警（可用云监控/简单 cron 脚本） |

## 七、防护有效性矩阵（威胁 × 现状）

| 威胁 | 现有防护 | 有效性 | 残余风险 |
|---|---|---|---|
| T1 无差别扫描/爬虫/漏洞探针 | 网关 302/401、端口最小化、容器仅回环 | **高** | 几乎为零（今日 157 次探针全挡） |
| T2 弱口令/默认口令 | 无检测、无锁定 | **失效** | **P0-1：演示期可直接登录** |
| T3 同链路嗅探 / MITM | 无 TLS | **失效** | 门口口令、Cookie、JWT 明文可被截获 |
| T4 门口口令爆破 | 无速率限制、无 fail2ban、无日志 | **低** | 无限速尝试，且不可见 |
| T5 通行 Cookie 泄露/转发 | 静态值、7 天、不可吊销 | **低** | 一人泄露 = 全站通行 7 天 |
| T6 演示席位抢占（DoS） | 全站 3 条上限 | **低** | 3 条长连接即可让评委实时失效 |
| T7 应用登录爆破 | 5/分/IP + nginx 8r/s | **中** | IP 轮换可绕；无账号锁定 |
| T8 Token 被盗用 | JWT 24h 无吊销 | **中低** | 盗用可满 24h |
| T9 未授权进后台 | 双门（网关 + 后台登录）+ 回环 | **较高** | 后台登录无限流 |
| T10 数据丢失/损坏 | 无备份 | **失效** | 单点 SQLite，重建/误删不可恢复 |
| T11 主机/SSH 入侵 | 密钥登录、密码关闭、fail2ban、自动补丁 | **较高** | root 直登建议改非 root；安全组待核对 |
| T12 资源滥用/成本 | 单 IP 限速、演示注册 403 | **中** | 注册默认开放、LLM 无配额 |

### 阶段 B：演示后 1–2 周

1. **TLS**：有域名 → `certbot --nginx -d <domain>`；无域名 → 先买域名或用 Cloudflare 代理（回源仍 HTTP 但外网加密）；同时加 HSTS。
2. **访问票据升级**：用 nginx `secure_link` 生成带过期时间的演示/访客链接（替代静态 Cookie）：

```nginx
# http 段
secure_link_md5 "$secure_link_expires$uri <secret>";  # 生成端：md5(expires + uri + secret)
# location
location = /enter { secure_link $arg_e,$arg_s; if ($secure_link = "") { return 403; }
                    add_header Set-Cookie "tutor_gate=<value>; path=/; HttpOnly; Secure; SameSite=Lax; max-age=43200";
                    return 302 /; }
```

3. **应用加固**：`ALLOW_REGISTRATION=false` 开关；账号锁定/退避；JWT 2–8h + 刷新；后台登录限流；密码策略 ≥10 位。
4. **备份常态化**：cron 每日 `.backup` + 卷 tar，保留 7/30 天，异机或 OSS；每季度演练恢复一次。
5. **安全响应头**（先在测试环境验证 CSP）：`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: no-referrer`。
6. **清理旧数据副本**：`/opt/ai-tutor/backend/data`、`/opt/ai-tutor/backend/app/data` 确认无用后归档删除；把 `data/keys`、`data/llm` 加入挂载，`.env` 权限收紧到 600。
7. **门口防护补齐**：`/gate` 加 `limit_req`（如 10r/m + burst 3）+ fail2ban 自定义 filter：

```ini
# /etc/fail2ban/filter.d/nginx-gate.conf
[Definition]
failregex = user "tutor": password mismatch, client: <HOST>
ignoreregex =
# /etc/fail2ban/jail.local
[nginx-gate]
enabled  = true
port     = http,https
filter   = nginx-gate
logpath  = /var/log/nginx/error.log
maxretry = 5
bantime  = 1h
```

### 阶段 C：长期（生产化）
