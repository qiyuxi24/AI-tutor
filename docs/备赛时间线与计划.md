## 二、逐周作战计划

### W1（8/31 – 9/6）：地基稳定 + 明确技术主线

**目标：现有系统能稳定跑通全流程，这是所有工作的前提**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| LLM 请求重试机制 | 技术 | 网络抖动重试 + 超时处理，演示不翻车的第一道保险 |
| 修复已知 bug | 技术 | 图谱重复节点（create_node_from_ai 追加）、画像缓存等 |
| 前端体验 | 技术 | toast 替代 alert、CORS 配置化（环境变量） |
| 通读 RAG 源码 | 学习 | 理清 rag_pipeline / hybrid_search / kb 三块现有实现，为精排打基础 |
| **里程碑** | — | 全流程演示一遍无阻断；明确 RAG 精排为 W2 技术主线 |

### W2（9/7 – 9/13）：RAG 精排（Cross-Encoder）★技术重点

**目标：检索准确度上一个台阶，这是"技术过硬"最硬的一块**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| 引入 rerank 组件 | 技术 | 在 hybrid_search 后接 cross-encoder 精排（复用 requirements.txt 已注释的 sentence-transformers） |
| 精排接入管线 | 技术 | rag_pipeline 增加 rerank 步骤，命中 chunk 按精排分数重排后注入 |
| 效果对比 | 技术 | 拿几个真实 query 对比"有/无精排"的检索质量，量化收益 |
| **里程碑** | — | 检索 Top5 明显更准；可口头向评委讲"混合召回 + 精排"技术栈 |

### W3（9/14 – 9/20）：Agentic RAG（检索工具化）★差异化亮点

**目标：RAG 从"每轮自动注入"升级为"LLM 按需检索"，这是赛道最吃香的 Agent 属性**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| 检索注册为工具 | 技术 | 把 RAG 检索封装成 function calling 工具 `retrieve_knowledge(query, source)`，后台阶段按需调用 |
| 保留轻量路由 | 技术 | 简单/问候问题仍走规则跳过（已有 router），复杂问题才触发检索工具 |
| 双模式开关 | 技术 | 保留"自动注入"兜底，Agentic 作为可切换的进阶模式，避免演示风险 |
| **里程碑** | — | 对话中能看到"AI 自主决定检索并引用来源"，这是 OPC 赛道最亮眼的演示点 |

### W4（9/21 – 9/27）：演示数据 + 图谱打磨

**目标：让产品"看起来丰富、跑起来漂亮"，为视频准备素材**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| 填充完整学科图谱 | 数据 | 建议"数据结构"或"线性代数"，15-20 个核心节点 + prerequisite 边 |
| 演示脚本 | 内容 | 写 2-3 条对话路径，预演"AI 建图 + 精排溯源 + 路径推荐"完整闭环 |
| 仪表盘/进度可视化 | 技术 | 若时间允许：学习进度仪表盘（P2）作为可视化加分，不做也不影响主线 |
| **里程碑** | — | 图谱内容丰富、可动态生长；演示路径丝滑不卡壳 |

### W5（9/28 – 10/4）：演示视频 + 作品文档 ★比赛材料攻坚

**目标：国庆假期集中产出两份核心材料**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| 录制演示视频 | 材料 | OBS 录屏，≤10min：概述≤2min + 核心演示≤6min + 总结≤2min |
| 剪辑 | 材料 | 剪映拼接 + 字幕，压缩到 500MB 以内 |
| 作品介绍文档 | 材料 | PDF：名称/3-5关键词/概要/痛点/创新点/落地场景/成效，按五维写 |
| **里程碑** | — | 视频 + 文档初稿完成 |

### W6（10/5 – 10/11）：材料精修 + 申报

**目标：所有材料定稿，完成报名**

| 事项 | 类型 | 具体内容 |
|------|------|---------|
| 申报书/承诺书 | 材料 | 官网填报 → 生成表单 → 负责人签字 → 扫描上传（学生团队免盖章） |
| 支撑材料 | 材料 | README/架构图/GitHub 地址打包（选填） |
| 材料评审 | 材料 | 内部过一遍：不懂技术的人能否看懂 = 评委能否看懂 |
| **里程碑** | — | 全部材料齐全，官网提交 |

### 收尾（10/12 – 10/15）：最终检查 + 提交

| 事项 | 内容 |
|------|------|
| 逐项核对 | 视频时长/大小、PDF 可打开、申报信息无误 |
| **提交** | **10-15 23:59 前完成官网提交**（留缓冲，别压线） |

## 三、技术主线细节（哪些值得做，哪些可放弃）

| 技术项 | 优先级 | 理由 |
|--------|--------|------|
| RAG 精排（Cross-Encoder） | ⭐必做 | 检索质量提升直接可见，技术含金量高 |
| Agentic RAG（检索工具化） | ⭐必做 | OPC 赛道最契合，演示点最亮 |
| LLM 重试/稳定化 | ⭐必做 | 演示不翻车的前提 |
| 完整学科图谱 + 脚本 | ⭐必做 | 视频素材 + 实施显著性 |
| 学习进度仪表盘 | 可选 | 有 P2 基础，时间够就做，可视化加分 |
| RAG 引用卡片拖拽 | 可选 | P1.5，锦上添花，优先级低于精排 |
| 学科切换/多图谱 | 可放弃 | 与主线无关，不投入 |

## 四、风险与缓冲

| 风险 | 影响 | 缓冲措施 |
|------|------|---------|
| 技术项拖进度 | 中 | 精排/Agentic 两条主线各留 1 周冗余（W3/W4 可交换） |
| 视频录制翻车 | 中 | W4 就把演示脚本跑熟，W5 多录几版选最佳 |
| LLM 调用失败 | 高 | W1 先做重试机制，这是第一优先级 |
| 学校不认该赛事加分 | 低 | 已确认大概率仅"行业证书"价值，不影响技术学习主线 |
| 时间被学业挤占 | 中 | 主线按周推进，W5 国庆集中攻坚材料 |

## 五、一句话总结

> **前 4 周把技术打硬（精排 + Agentic + 稳定化），国庆做材料，10/15 前提交。**
