## 一、三条路线（先看懂这个，再谈借鉴）

| 路线 | 图是什么 | 代表 | 图的来源 | 每轮对话 |
|---|---|---|---|---|
| **A 检索索引** | 图是**索引** | Microsoft GraphRAG / LightRAG / HippoRAG | **从文本自动抽取** | 命中才用 |
| **B 教学参照系** | 图是**教学可行域与坐标系** | **本项目**；MDPI 智能导学(2025) | **人工建/AI 辅建/教材生成** | **每次注入**（契约要求） |
| **C Agent 记忆** | 图是**长期记忆** | Zep/Graphiti / Mem0 / MemGPT | 从交互中累积 | 按需召回 |

三条路线**不冲突、可叠加**，但工程重心完全不同。关键判断：
- 路线 A 的成熟开源件**不能直接搬**（它们的图从文本抽、为检索服务）；**唯一真正可复用的是"图遍历扩展上下文"这一手法**。
- 路线 B 在学术上**不是异类**：ChatGPT 的记忆策略就是"始终注入"，与 Claude 的"按需检索"正相反【二手】。
- 本项目**已规避业界最大的成本坑**：GraphRAG 系的"社区摘要"需要海量 LLM 调用，而我们不对图做 LLM 摘要 —— 这是"图不来自文本"带来的架构红利。（注：**社区摘要**确实对我们无意义；但 **Leiden 聚类** 曾用于主题分组，该主题层已于 2026-09-27 整体下线删表，此路已废。）

## 二、论文脉络（四条线，按相关度排序）

### 2.1 教育知识图谱与先修关系（**最相关**）
先修关系（prerequisite relation, PR）是 EduKG 的灵魂，**正是本项目 `edges.relation='prerequisite'` 那条边**。

| 论文 | 出处 | 要点 | 对本项目的意义 |
|---|---|---|---|
| **Inferring Prerequisite Knowledge Concepts in Educational Knowledge Graphs: A Multi-criteria Approach**（Alatrash, Chatti, Wibowo, Ain） | 2025-09, IJCKG 2025, **arXiv:2509.05393** | **无监督**推断（不依赖标注）；文档/超链接/图/文本四族 **10 项准则** + **投票算法**融合 | ⭐ **最可直接借鉴**。无监督、多特征、投票 —— 本项目已落地为 **6 条准则固定分母加权投票**（见 `数据结构…_评审与改良方案.md` §11 P0-C） |
| **DGCPL: Dual Graph Distillation for Concept Prerequisite Relation** | 2025, IJCAI | 双图蒸馏学习先修关系 | 有监督路线代表；需标注数据，本项目暂不具备 |
| **MOOCCubeX**（THU-KEG × 学堂在线） | 2021, CIKM resource | 4,216 课程 / 637,572 概念 / 2.96 亿行为；**含三科（数学/心理/CS）先修关系（含人工标注）**；配套概念抽取、先修发现（co-training） | ⭐ **可用的外部评测数据集**（我们目前只有内置 8 条 gold） |
| **ACE: AI-Assisted Construction of Educational Knowledge Graphs** | 2024, JEDM | AI 辅助构建 EKG 方法论 | 构建流程参考 |
| **基础教育知识图谱标准**（CELTSC） | 2025-06 | 技术框架/数据要求/本体 | ⚠️ **值得查证**：若材料涉及"符合标准"，需核对本体是否与 `subject/board/tags` 冲突 |

**结论**：先修关系**不是我们独有的难题**，而是有专门会议（IJCKG）、专门数据集（MOOCCubeX）、专门方法体系的研究方向 —— 既是风险（别人有成熟方法）也是机会（可站在成熟方法上做量化）。

### 2.2 知识追踪（KT）：我们的"掌握度"的学术对应物
| 论文/工具 | 出处 | 要点 | 意义 |
|---|---|---|---|
| **DKT** | 2015, NeurIPS | 首个 RNN 建模学生知识状态 | 需大量交互序列，本项目**不具备** |
| **pyKT** | `pykt-team/pykt-toolkit` | 统一 30+ KT 模型 × 7 数据集的基准库 | ⭐ 价值在**评测口径**（AUC/ACC、数据划分） |
| **A survey of DLKT** | 2026-01, Neurocomputing | 系统综述 | 综述入口 |
| **DKT2** | 2025, arXiv:2501.14256 | 重审 DKT 适用性 | 说明"老模型仍有价值" |
| **Next Token KT (NTKT)** | 2025-11, arXiv:2511.02599 | 把 KT 重构为下一个 token 预测，利用预训练 LLM | ⭐ 与我们最契合（不用训练专用模型，用 LLM 做 KT） |

**判断**：❌ 不宜直接引入 DKT/AKT（吃"学生×题目×对错"长序列，我们冷启动单用户无题海）；✅ 可借鉴**评测口径**与 **NTKT 思路**（我们其实已在用 LLM 打 mastery 分数）。

### 2.3 学习路径推荐
**Personalized Learning Path Recommendation Based on Knowledge Graphs**（2026-01, MDPI Electronics）强调路径**透明性/自适应/个性化**；**Graph Reinforcement Learning**（2025, Procedia CS）需交互数据；**KT + Path**（2023, IEEE）。**结论**：本项目"**拓扑序 + mastery<50 优先**"属该领域**基线做法**（简单但正确）；前沿的"图强化学习/KT 驱动"都**依赖交互数据** → 材料中**不要声称路径推荐有算法创新**，而应声称"路径由先修图与掌握度共同决定，可解释、可审计"（恰是 MDPI 2026 强调的**透明性**）。

### 2.4 KG 增强 LLM 与幻觉抑制（支撑"定界"的价值）
| 论文 | 出处 | 要点 | 意义 |
|---|---|---|---|
| **Can Knowledge Graphs Reduce Hallucinations in LLMs? A Survey** | 2024, NAACL, **arXiv:2311.07914** | 综述 KG 增强技术如何降低幻觉 | ⭐ **L1 定界价值的权威引证**（"为什么必须注入图谱"） |
| **From Local to Global**（GraphRAG） | 2024, arXiv:2404.16130 | 图谱 RAG 奠基 | 我们与它路线不同，须明确区分**避免被误认为 GraphRAG 应用** |
| **LLM-empowered knowledge graph construction: A survey** | 2025, arXiv:2510.20345 | LLM 重塑 KG 构建全流程 | 优化 `graph_generator` 的方法论总入口 |
| **How to build an adaptive AI tutor for any course using KG-RAG**（Dong et al.） | 2025, ICEIT (IEEE) | 用 KG-RAG 构建自适应 AI 导师 | ⭐ 同类系统的学术版 |
| **Zep: A Temporal Knowledge Graph Architecture for Agent Memory** | 2025 | 时序 KG 做 Agent 记忆 | 见 §三 / 第一部分 |

### 2.5 KG 表示学习与推理（**了解即可，当前不采纳**）
TransE（2013, NeurIPS，`h+r≈t`）、RotatE（2019, ICLR, arXiv:1902.10197）、R-GCN/CompGCN、C-KGE（2025）。**为什么不采纳**：KGE 的价值在链接预测（补缺失边）与关系推理，会引入**不可解释的边**，与"可审计"目标冲突；本项目规模小、边由教学逻辑确定 → **当前用多准则规则法更合适**（可解释）。

**GraphRAG 家族（路线 A）**：Microsoft GraphRAG（社区摘要 + Local/Global/DRIFT，❌ 核心与我们无关）｜LightRAG（HKUDS，双层关键词 + 增量插入，⚠️ 思想可借）｜nano-graphrag（参考代码结构）｜Fast-GraphRAG（PPR 替代社区摘要，⚠️ PPR 记一笔）｜KAG（蚂蚁/OpenSPG，❌ 工程重）｜**HippoRAG**（OSU，PPR 单步多跳，⭐ 最值得看架构）｜Graphiti（getzep，时序 KG，⚠️ 未来学习轨迹参考）。（定性描述为【二手】，**性能数字未核实勿引用**。）

**存储与查询**：Neo4j（+GDS/APOC）⚠️ **当前不该引入**（单用户百级节点 SQLite 已足够，Docker 单容器约束下多一个服务是负担）；NebulaGraph/Jena/RDFLib ❌ 体量不符。→ 材料中**不要**把"用了图数据库"当亮点，应把"**用户级图谱隔离 + 两级切片**"当亮点。

**构建/嵌入/推理工具包**：DeepKE（浙大）、PyKEEN/DGL-KE/OpenKE/KnowledgeGraphEmbedding、Stanford OpenIE —— 仅在想脱离 LLM 用专用小模型抽取时才有意义。

**教育专用开源（价值最高）**：pyKT（评测口径）、MOOCCubeX（外部评测数据集）、THU-KEG 配套（概念抽取管线 / 先修发现 co-training）、DeepTutor/adaptive-edu/OpenMAIC（已对标）。

**同类 AI_Tutor（`098765d/AI_Tutor`，ICEIT 2025）**：双路检索 = 向量（课程文本块）+ **知识图谱遍历（`kg_hop_depth` 控跳数）** → 融合喂 DeepSeek-V3；图谱存 **`data/knowledge_graph.xlsx`**；~61 stars。**三点启示**：① 同类学术论文做法比我们简单得多 → 我们的工程化程度（SQLite + 用户隔离 + 两级切片 + SSE）**是相对优势**；② "图谱遍历扩展上下文"是这类系统标配（`kg_hop_depth`），我们的 `rag_search(source=graph)` 只有节点级检索 → **低成本改进点**；③ 它用"KG-RAG / 纯 RAG 模式切换"证明增益 → ⭐ **好的评测设计**，可照做。

## 四、本项目在坐标系中的位置

**一致的做法（可自信讲）**：用户级图谱隔离（多数同类是全局单图）；图**既读又写**（路线 A 普遍只读）；两级分组 + 按需切片（对应 LightRAG 的"双层"但我们是**教学语义分层**，更有解释性）；**不做 LLM 社区摘要**（规避最大成本坑）；路径可解释（拓扑序 + 掌握度阈值）。

**缺口（按可落地性排序）**：先修关系无量化评测（→ 已用多准则 + 内置 gold 部分补齐，缺外部数据集）｜图谱检索不能扩跳（KG-D9）｜无"图谱开/关"对照（→ **已做**，见 `知识图谱_检索与注入_方法与现状.md` §3）｜掌握度无时间维度（KG-D4 事件表为轻量版）｜注入体量无控制 G1（→ 已由字符上限 + S4 选片承担）。

**明确不采纳及理由**：Neo4j（单用户百级节点 SQLite 够用）｜GraphRAG/LightRAG 框架（图从文本抽、服务检索；借手法不引依赖）｜DKT/AKT（缺长交互序列）｜KGE 补边（产生不可解释的边）｜KAG/OpenSPG（工程重、场景不匹配）。

**可借鉴点（优先级）**：**P0** 先修关系量化能力（已落地多准则 + 离线评测；余下 = 接入生成链路、用 MOOCCubeX 实数据评测）｜**P1** 图谱检索扩跳（参照 `kg_hop_depth`）、图谱开/关 A-B（已做）｜**P2** 掌握度时间序列（参考 Graphiti 双时间轴）、PPR 多跳（HippoRAG）、查证 CELTSC 标准合规。

## 六、需求拆解与现状

**"多资料维护图谱"不是一件事，是五件事**：`溯源 → 对齐 → 补全 → 冲突 → 增量`。其中**溯源（provenance）是前四者的前提** —— 没有"这条知识来自哪本书/哪一章"，对齐无法复核、冲突无法裁决、覆盖度无法度量。

| # | 问题 | 典型场景 | 教学价值 |
|---|---|---|---|
| 1 | **对齐**（同一概念多种表述） | 教材 A"散列表"、B"哈希表" | 避免图谱被同义节点稀释 |
| 2 | **补全**（不同资料覆盖不同点） | A 有"红黑树"、B 有"B+树" | 覆盖度并集 |
| 3 | **冲突**（定义/归属/顺序矛盾） | A 说"先数组再指针"、B 反之 | 暴露矛盾本身有价值，但**不能静默合并** |
| 4 | **增量**（新书来了怎么办） | 已有图谱 + 新增一本教材 | 增量 O(新书) 而非 O(全库) |
| 5 | **溯源**（每条知识的依据） | "这个节点是哪本书讲的？" | 支撑前三者的**复核与裁决** |

**价值主张**：覆盖度 ↑（多书知识点取并集）；可信度 ↑（一概念被 N 本书支撑，支撑越多越核心）；矛盾显式化（差异摆上台面而非被一次性生成抹平）。

**现状（代码事实）**：抽取 = 单次生成按"书序×分块序"扫；去重 = **同一次生成内**（嵌入粗筛 0.78 + LLM 确认 + 降级 0.90，`_find_dedup_candidates`）；写入 = `_write_to_graph` 返回 `merged_nodes`；板块 = **只有 generator 会写**；**溯源 = 零**（节点 MD 有正文，但没有来源）；**增量 = 无**（重新生成 = 重跑全库）；先修关系已可多准则无监督推断。**结论：现在是"单源一次性生成"，不具备多源维护基础设施** —— 硬做会在"同义节点跨次生成不合并""冲突被后一次生成覆盖"两处翻车。
> ✅ **2026-09-26 更新**：写路径**已收敛为** `create_node_with_content` 唯一落点（2026-09-15）；覆盖语义**部分已解**（并轨走 `mode="append"`）。L0 溯源 / L3 按源增量已登记为 `TODO.md §5` 的 **GQ-18~21**。

## 七、业界方案

### 7.1 融合的两个层次（通用框架，**顺序不能颠倒**）
| 层 | 融合对象 | 典型手段 | 我们的对应物 |
|---|---|---|---|
| **Schema 层**（本体融合） | 实体类型、关系类型、层级 | 本体对齐、canonicalization、schema 与实例共演化 | "学科 → 板块 → 知识点" + 关系类型 |
| **Instance 层**（实例融合） | 具体节点与边 | 实体对齐/消解（ER）、属性融合、边合并 | `_find_dedup_candidates` 的 LLM 确认合并 |

**关键洞察**：Schema 层不统一时 Instance 层必然打架（`board` 归属冲突就是这个问题的实例）。

### 7.2 代表系统与可借鉴点
**KARMA**（arXiv:2502.06472, NeurIPS'25）：多智能体协作增补图谱，**冲突消解是独立角色**而非抽取副产物｜**多源教育 KG 融合**（arXiv:2305.04567, 北邮）：教材/课件/大纲三源各建子图再四步融合（见 §7.3）｜**In-context Clustering ER**（arXiv:2506.02509）：LLM **上下文聚类**消解实体（一次判一批，O(n²)→O(n/k)）｜**KGGen**（NeurIPS'25）：强调密度与语义一致性｜**iText2KG**（WISE'24）：**增量式**文本→图谱，schema 驱动、免后处理｜**LightRAG**（arXiv:2410.05779）：增量更新复用同一图索引进程，**避免全量重建**。

### 7.3 教育域对口论文的四步融合（arXiv:2305.04567，本方案主要借鉴）
**数据**：教材/课件/大纲三源 → 三子图（5 级粒度），60k+ 实体、80k+ 三元组（Neo4j）。**融合四步**：
| 步骤 | 做法 | 启发 |
|---|---|---|
| a 实体名称匹配 | 字符串 + 字面 + 语义相似度**三路并用** | 与"向量粗筛 + LLM 确认"同构；它额外用字符串/字面可作前置快筛 |
| b 定位粗粒度实体 | 融合后节点取**最粗粒度** | 我们目前"哪个先建用哪个"，粒度不统一 |
| c 属性并集 | 除 `url` 外全部属性**取并集** | 节点正文应**合并**而非覆盖（当前 `update_node_content` 是覆盖语义） |
| d 保留原始边 | 融合前所有连接关系**全部保留**并指向新节点 | 避免"合并节点导致边丢失" |
**量化指标（可借用）**：课程相关度 = 跨课程等价边数/课程节点数；**三源交集 = 最有价值知识点**（通信原理课 16 个）。**局限（反面教材）**：**没有 P/R/F1、没有金标准、没有消融**；对齐的模型/阈值/权重/决策规则**全部未给出** → 我们若做多源融合，**评测口径必须比它严**（照抄先修推断：标注集 + P/R/F1 + 阈值扫描）。

### 7.4 冲突消解：三条技术路线（共性 = **detect-then-resolve 两段式**，先检测再消解，**人在环**）
规则/文本匹配（快、可解释、零 LLM 成本，只能抓字面矛盾）｜结构一致性（环检测、层序矛盾，抓顺序类冲突）｜LLM 仲裁（语义矛盾，成本 + 幻觉，**必须记录证据与置信度**）。**没有可信工作主张"冲突全自动静默解决"**。我们的现成武器：`core/prerequisite.py` 的**多准则 + 证据链**骨架可直接复用为冲突检测器（把"是否先修"换成"两源说法是否一致"）。

### 7.5 增量更新（避免全量重建）
以**资料为单位**做 run（成本 ∝ 新书）；**对齐先于写入**（命中走"丰富/合并"，未命中才新建）；**复用图索引**（只更新受影响子图）；**幂等键** `(source_doc_id, chunk_id, span)`。**必须接受的代价** = 版本漂移（同概念前后两次融合结果可能不同）→ 对策是把合并决策落表，可追溯、可回滚。

## 八、落地设计（分层）

**L0 溯源层（前置，必须先做）**：`nodes`/`edges` 增 `sources`（JSON 数组 `[{doc_id, doc_name, chunk_id, span, extracted_at}]`）；老节点 `sources=[]` 不阻塞；复用 kb 侧已有 `chunk_id`/`path` 溯源；`doc_id` 归属 `user_id`，删资料需联动。**验收**：任一节点可列出支撑它的资料段落数，支持按资料反查。**这层不做，后面全白做。**

**L1 对齐层**：① 阻塞/粗筛（向量 + 字符串/字面三路并集）；② 候选压缩（**批量上下文聚类**，O(n₁×n₂)→O(n/k)）；③ 仲裁（LLM 两阶段：生成候选 → 校验理由）；④ 融合写入（属性/正文**取并集** + **保留原始边** + 取最粗粒度）；⑤ 决策落表 `merge_decisions(kept_id, merged_id, score, evidence, decided_by, ts)`（支持回滚与人工复核）。**工程前提**：写路径先收敛（现已收敛）。

**L2 冲突层（检测 → 人工裁决）**：术语/定义冲突（LLM 对比 + 证据链 → 待裁决队列）；先修方向冲突（**多准则投票 + 环检测**；高置信度**标注**而非改写）；板块/学科归属冲突（保留多值 + 标记不一致）；难度/时长冲突（取区间或标注分歧）。**红线**：AI 不改人类内容（护栏 `_guard_human_content`/`_guard_human_edge` 继续生效），冲突只能"提出建议 + 留证据"。

**L3 增量层**：单位 = 一份资料一次 run；幂等键 `(doc_id, chunk_id, span)`；失败隔离（单份失败不影响已有图谱）；**成本目标 ∝ 新资料规模**。

**L4 覆盖度度量**：支撑度 support（核心知识点识别）、覆盖率 coverage（图谱是否跟上资料）、对齐率（融合是否真在合并而非膨胀）、冲突率（资料间矛盾程度）、冗余率（对齐召回是否够）。报告沿用 P0：**JSON 报告 + 控制台表格**。

## 九、风险、分阶段与开放问题

**风险/约束**：① 写路径未收敛（**已解**）；② 覆盖语义冲突（**部分已解**，并轨 `append`，但 `update_node_content` 仍是覆盖）；③ LLM 成本（对齐 O(n₁×n₂) → 必须批量聚类 + 设每份资料预算上限）；④ 用户隔离（跨用户"教材"绝不能互相融合）；⑤ 资料删除的溯源联动（保留但标"来源已删除"/降级/删除 + 审计）；⑥ 版本漂移（须 `merge_decisions` 可回滚）；⑦ **评测缺失**（对口论文自己都没定量评测，我们必须自建标注集）。

**分阶段**：**P0** L0 溯源字段贯通 + 节点"来源"可查｜**P1** 写路径收敛（已完成）+ 正文/属性 `merge` 语义 + 离线评测集（两份教材同义/互补标注）｜**P2** L1 跨源对齐（三路粗筛 + 批量聚类 + 二阶段仲裁 + `merge_decisions`）｜**P3** L3 增量按资料入库（幂等 + 失败隔离 + 成本对比报告）｜**P4** L2 冲突检测队列（复用多准则投票骨架）+ L4 覆盖度指标。
