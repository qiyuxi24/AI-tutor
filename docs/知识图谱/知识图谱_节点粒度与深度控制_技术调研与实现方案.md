## 〇、结论速览

先给判断，再给证据。

**1）"节点过深或过浅"不是模型能力问题，而是"上游分块 + prompt 上限 + 去重缺失"三者叠加的工程产物。** 本项目已在 `TODO_Graph_Quality.md` 把它定位到三个可复现的根因（300 字硬限、570 字符/块的过小输入、一次吐 8 个节点的广度挤占），因此**改 prompt 与改分块就是改粒度**，无需换模型。【项目实测】

**2）外部最硬的一条规律：分块越小，抽出的实体越多、越碎。** GraphRAG 原文实测"600 token 块抽出的实体引用数几乎是 2400 token 块的 **2 倍**"——这直接解释了"块摊小 → 节点爆炸"的因果链。【已核实，arXiv:2404.16130】

**3）但块不是越小越好，存在"最优块"，且主流框架高度收敛在 ~1000–1200 token 或数千字符。** GraphReader 原文"最优 L=2k，过小的块导致语义截断、妨碍抽取原子事实"；GraphRAG/LightRAG/Graph-R1 都默认 1200 token，kg-gen 默认 5000 字符。本项目把单元下限提到 1500 字符、上限 5000 字符，方向与此一致。【已核实】

**4）教育域给"一个知识点该多深"提供了可落地的口径：3–5 分钟可讲解完的知识单元 = 一个知识点；一门课 150–500 个知识点（2 学分核心课约 150–200）。** 本项目一本书两个文件 311 个节点（正文中位 213 字）判定为"过碎"，目标 100–150 个与外部区间吻合。【项目实测 + 二手】

**5）控制粒度的成熟范式是"先粗后细"的层级抽取，而非一次性平铺。** HiRAG（实体→聚类→摘要节点）、SAC-KG（生成器→验证器→剪枝器）、教育域 4 级图谱（学科→科目→主题→知识点）都属此类；本项目"按章节树递归切生成单元"已是该范式的雏形，缺的是"剪枝/验证"回路。【已核实】

**6）评价粒度是否健康，不能只看节点数。** 应盯**平均度（avg degree）、巨型连通分量占比、正文长度中位/空壳率、关系类型复用率**四个指标——业界已有明确口径但**无权威硬阈值**，只能做同规模参照与自我纵向对比。【已核实】

| 判断 | 一句话结论 | 最强证据 |
|---|---|---|
| 块 → 节点 | 块越小，抽出实体越多越碎（近 2 倍差） | GraphRAG 600 vs 2400 tokens（arXiv:2404.16130） |
| 最优块 | 太小伤"原子事实"抽取，主流落 ~1200 token / 数千字符 | GraphReader L=2k；GraphRAG/LightRAG 1200 |
| 教育粒度 | 3–5 分钟/知识点；一门课 150–500 个 | 教育域经验口径【二手】 |
| 控粒度 | 先粗后细层级抽取优于一次性平铺 | HiRAG / SAC-KG / 教育 4 级 |
| 少而精 | 更少节点 + 更好连通，下游更优 | entity-consistency 892→683（arXiv:2510.11297） |
| 度量 | 盯 avg degree / 连通分量 / 空壳率 / 关系复用率 | arXiv:2506.05690、KGGen（arXiv:2502.09956） |

## 一、问题界定：什么叫"节点粒度"，它为什么决定图谱质量

### 1.1 把"粒度"拆成三个正交维度

"节点太浅/太多"这句话里其实混了三个彼此独立的变量，必须拆开才能分别治：

| 维度 | 定义 | 表现（过小的后果） | 本项目对应 |
|---|---|---|---|
| **深度**（单节点） | 一个节点的正文能独立支撑多少教学信息 | 正文几十到一两百字，只有一句定义 | `content` 中位 213 字【项目实测】 |
| **广度**（节点数） | 一段文本被切成多少个节点 | 一棵教材切出几百个节点 | 311 节点/2 文件【项目实测】 |
| **层级**（节点间） | 节点是否有"父概念—子概念"的结构 | 全部平铺，无层级，靠边硬连 | 现为平铺 + prerequisite 边 |

三者是**耦合**的：正文越浅 → 单个节点承载的信息越少 → 同样的教材必须切得更碎 → 节点越多。**"节点过碎"是"正文过浅"的必然结果，不是并列的两个毛病。** 所以治理顺序必须是**先提深、再减量**（反序做只会把浅内容合并成更浅的团块）。

### 1.2 粒度由什么决定：一条上游流水线

节点粒度不是生成模型"随手"定的，它被上游三步逐级锁定：

```
教材文本
  │  (1) 分块 chunking       ← 块多大，直接决定"模型一次看到多少上下文"
  │  (2) 抽取 extraction     ← prompt 允许抽几个、写多长
  │  (3) 合并 dedup/merge    ← 同义/碎片节点是否被并轨
  ▼
最终图谱的粒度画像（节点数 / 正文长度 / 平均度）
```

本文的组织顺序即按此流水线：**二（分块）→ 三（教育域"多大合适"）→ 四（抽取侧的控粒度技术）→ 五（怎么量）→ 六（本项目落地）**。

### 1.3 为什么"粒度错了"是硬伤（用途倒推）

本项目里一个节点同时是**三种单元**，深度必须满足三者中最严的那个【项目实测，`TODO_Graph_Quality.md` §1.2】：

| 用途 | 对深度的要求 | 出处 |
|---|---|---|
| 出题单元（`quiz_generate` / `grade_answer`） | 必须含可命题事实：定义 + 关键性质 + ≥1 例子或数值 + 易错点；只有一两句定义 → 出不了题或出成"背书题" | `core/quiz/` |
| 讲解单元（对话导学） | 要能独立支撑一次讲解，不靠上下文补全 | `system_prompt_common.j2` |
| 检索单元（RAG） | 语义自足，单独一段能回答一个问题 | `core/rag/`、`core/kb/` |

> **本章判断**：粒度不是审美问题，而是**下游（出题/讲解/检索）可用性的前置条件**。节点过浅，出题会退化为背书题、检索会退化为关键词匹配；节点过碎，图谱的"骨架"被噪声淹没、平均度被拉低、注入预算被稀释。因此"恰当粒度"应当由**用途倒推**，而不是由"抽到多少算多少"决定。

## 二、上游：分块粒度如何决定抽取粒度（chunk → node）

### 2.1 最硬的实证：块越小，抽出的实体越多

GraphRAG 论文（Edge et al., **arXiv:2404.16130**）给出了一条被广泛引用的原文结论【已核实】：

> *"GPT-4 extracted **almost twice as many entity references** when the chunk size was **600 tokens** than when it was **2400**."*

其 Figure 3（HotPotQA，gpt-4-turbo）的原始数值（单位：抽出的实体引用数）：

| chunk 大小 | 0 次 self-reflection | 3 次 self-reflection |
|---|---|---|
| 600 tokens | **9500** | **27500** |
| 1200 tokens | 7000 | 22000 |
| 2400 tokens | 6000 | 19500 |

**同义反复但同向的旁证**：某 KG 构建论文（"A Knowledge Graph Is All You Need", 2025）原文——800-token 块下，*"larger chunks…likely resulted in some loss of granularity. Smaller, more focused entities…might have been missed because they spanned across chunk boundaries"*——说明块大小与"抽出多少个细实体"是**负相关**，且过大块会因实体跨块而漏抽【已核实】。

> **含义**：本项目旧实现实测块仅 **570 字符/块**（远小于 1k token 的量级），正是"节点过碎"的**上游第一推手**——模型每看到一小段就急着把里面的每个术语都变成一个节点。

### 2.2 但块不是越小越好：存在"最优块"

如果结论停在"块越小实体越多"，就会得出"那干脆切到最小"的错误推论。GraphReader（**arXiv:2406.14550**）给出了反证【已核实】：

> *"the best performance is achieved with **L=2k**… smaller chunks lead to more **semantic truncation**, hindering…extracting **atomic facts**."*

即：块太小 → 语义被截断 → 反而抽不出完整的"原子事实"。**"更多实体"不等于"更好图谱"**——小块的"多"往往是碎片噪声（见 §五 KGGen 对 GraphRAG"稀疏欠连通"的批评）。

### 2.3 主流框架的 chunk 参数高度收敛（可直接对标）

| 系统 | chunk 参数 | 来源 |
|---|---|---|
| Microsoft GraphRAG | 默认 **1200 tokens / overlap 100** | 官方 Indexing Dataflow 文档 |
| LightRAG | `chunk_token_size=1200`（论文称"across all datasets"） | arXiv:2410.05779 / GitHub HKUDS/LightRAG |
| AutoSchemaKG | **1024-token** 块（`L_max=1024`） | arXiv:2505.23628 |
| Graph-R1 | **1200-token window / overlap 50** | arXiv:2507.21892 |
| kg-gen (NeurIPS'25) | 默认 **5000 字符**；遇错按 16384 字符切 | GitHub stair-lab/kg-gen |
| KARMA | 段落级 → **摘要压缩为 ≤100 词**再抽三元组 | arXiv:2502.06472 |
| iText2KG | 无固定 chunk，用 Document Distiller 重划"语义块" | arXiv:2409.03284 |

**三个可迁移的工程结论**：

1. **token 派**（GraphRAG/LightRAG/Graph-R1）收敛在 **1000–1200 token**；**字符派**（kg-gen）在**数千字符**量级。本项目按字符计量，**1500–5000 字符/单元**落在合理带内（中文 1 字≈1 token 上下，1500 字符已明显大于旧 570）【项目实测】。
2. **"语义块"优于"固定滑窗"**：iText2KG 明说"chunk 小则语义块捕捉更具体细节，反之更泛"——即块边界应跟随**语义/结构边界**，而非等长切分。本项目旧实现用固定滑窗，正是 570 字符/块的真正来源【项目实测】。
3. **可用"摘要预压缩"当粒度闸门**：KARMA 把段落先压成 ≤100 词再抽，其消融显示去掉 summarizer 会 *"produce much more entities and triples"*——**先压缩再抽取**是一个低成本的降数量手段【已核实】。

> **本章判断**：**"块"是粒度的第一道闸门**。把块从 570 字符提到 1500–5000 字符（并对齐章节语义边界），是"减量提深"性价比最高的一步——零 LLM 成本（纯切分），且一次改动同时改善深度与数量。本项目 GQ-6 已做，实测 **316 块/583 字符 → 43 单元/4402 字符（-86% 块数）**【项目实测】。

## 三、教育域：一个知识点该多深、一门课该有多少个

分块解决"看到多少"，但"一个节点该多大"最终要由**教育域的粒度标准**拍板。这一节给外部依据（含**诚实的边界声明**）。

### 3.1 标准与规范：给"层级"，但不给"数字"

| 标准/规范 | 规定了什么 | 粒度阈值 |
|---|---|---|
| **CELTS-42《基础教育教学资源元数据规范》**（教育部 2002） | 元数据元素 + 课程内容分类**三级词汇表** | 未规定字数/时长 |
| **IEEE P2807.6《Guide for K-12 Educational Knowledge Graphs》**（2021 立项）+ 国内《基础教育知识图谱建设技术规范》（CELTSC 研制中） | 数据结构 / 本体规范 / 构建规范 / 应用规范；本体含知识点、教学资源、教学活动、核心素养及关系类 | **未给粒度字数或时长阈值** |
| 中文文献通用层级 | 中学理科**三级**（知识板块—小节—知识点）；思政课分**一~五级** | 层级式，非数值式 |

**规模实证锚点**：EduKG 覆盖 9 学科、407 本教材，共 **236,934 个知识点**（≈580 点/教材）【已核实】。

> ⚠ **诚实声明**：本次**未检索到任何 CELTSC 国标或 IEEE P2807.6 明文规定知识点的"字数 / 时长阈值"**。标准给的是**层级与本体**（"有哪些层、什么关系"），不是"每点多长"。因此"600–1000 字"这类数值**没有权威直接来源**，只能由时长口径**间接折算**（见 §3.2）。

### 3.2 经验值：教育域"按时长定粒度"的口径

标准不给数字，但**教育实践**给了：

| 口径 | 内容 | 来源 |
|---|---|---|
| **知识点=可讲解单元** | "**3–5 分钟可讲解完的知识单元 = 一个知识点**"，配"知识元→知识点→知识单元→知识模块"四级架构 | 教育信息化培训口径【二手】 |
| **一门课知识点数量** | 常见区间 **150–500 个**：超星"一门课三百到五百个"；教育部"101 计划"——"一门 2 学分核心课 150–200 个" | 厂商/政策文档【原文】 |
| **按学分折算** | "知识点总数不得低于**每学分 50 个**" | 高校智慧课程建设标准【原文】 |
| **知识点↔教材目录** | "教科书一章包含若干知识点"；高中数学 18 章/82 节/438 知识点；中学理科 77 板块/302 小节/1320 知识点 | 【二手】 |
| **每章核心知识点** | Miller **7±2**（核心概念 3–5 个、次级 ≤7 个） | 【二手】 |
| **微学习/学习对象** | 5–15 分钟（SCORM 官方**不规定**，属厂商经验值）；Wiley"self-contained chunks"四级粒度 | Wiley 2005 / 厂商【原文+二手】 |

**认知负荷理论（CLT）的指导**（Sweller 2010, *Educational Psychology Review* 22(2):123-138）：制粒度的核心变量是**元素交互性（element interactivity）**——高交互（元素必须一起理解）的内容超出工作记忆容量时，应"**分离关联元素**"分解学习、学后再整合【已核实】。这为"什么时候该拆、什么时候该并"给了理论判据：**元素强耦合 → 放在同一节点深讲；元素弱耦合 → 可拆**。

### 3.3 Knowledge Tracing（KC 粒度）的权衡

本项目"知识点"在学术上对应 **Knowledge Component（KC）**。KC 粒度没有唯一最优（Pelánek, *Managing Items and Knowledge Components*）：高中生"肌肉"可作单一 KC，医学生则需细分到"头/背/颈肌"【已核实】。

Pelánek《Adaptive Learning is Hard》（IJAIED）原文给出了**双边权衡**：

> *"models with fine granularity provide a better explanation of data and can improve student learning… However… fine granularity brings **costs and disadvantages**."*

细粒度拟合更好、可能提升学习，但代价是：难管题池/KC 映射、难拟合参数，且界面展示细术语会让学生困惑（应显示教材常用术语）。

> **本章判断**：教育域给出的**不是硬阈值，而是"按时长倒推 + 按耦合度决定拆并"的方法论**。对本项目有两条直接可用的结论：
> ① **深度锚**：一个节点应当对应"**3–5 分钟（本项目放宽到 5–25 分钟）能讲完**"的单元——据此折算正文 600–1000 字是合理的（本项目目标值）；
> ② **数量锚**：一本书/一门课 100–500 个知识点是外部区间，**本项目 311 节点/一本教材偏多，目标 100–150 落在区间内**。KC 粒度研究提醒"不是越细越好"——要按**用途与受众**权衡，而非追求拟合。

## 四、生成侧：控制粒度的三类技术

分块定了"输入上限"，教育域定了"目标值"，**怎么让模型真的产出达标粒度**，是生成侧的事。外部有三类成熟手段。

### 4.1 第一类：先粗后细的层级抽取（最对口）

一次性平铺抽取必然产生"又多又平"的节点；**层级化**是业界共识解法：

| 系统 | 机制 | 关键数字 |
|---|---|---|
| **HiRAG**（arXiv:2503.10150, EMNLP2025 Findings；GitHub hhh2210/HiRAG） | Layer0 抽实体关系 → 聚类 → LLM 生成**摘要节点**构成 Layer1 → 再聚类成 Layer2，分布变化 <~5% 停止 | 约 **300 块 → 520 实体 → 40 聚类(L1) → 6 聚类(L2)** |
| **SAC-KG**（arXiv:2410.02811, ACL2024） | **生成器→验证器→剪枝器**逐层扩展，验证器判定是否展开下一层 | 精度 **89.32%**，规模 >100 万节点，较 SOTA +20% |
| **分层抽取 initial→splitting→abstraction**（arXiv:2510.11297） | 先粗后细 + **entity-consistency** 提示，拆复合节点、抽象到父概念 | vs iText2KG：Accuracy **4.34 vs 3.34**（5 分制） |
| **教育域 4 级图谱**（ACM 10.1145/3806262.3806285） | L1 学科门类 → L2 科目 → L3 知识主题 → **L4 知识点**，父子相连 | 90 L1 / 19 L2 / 2254 L3-L4 |

> **可复用点**：① 先建**目录级骨架**（章/主题），再在骨架上展开知识点，天然抑制"平铺爆炸"；② 加一个**验证/剪枝回路**（SAC-KG 式），显式判定"这个候选值不值得单独成节点"；③ **entity-consistency 提示**用极低成本同时"减节点 + 增连通"（见 §4.3）。

### 4.2 第二类：schema 约束与两阶段抽取

- **两范式分野**（综述 arXiv:2510.20345）：**schema-based**（显式结构约束：类型、层级、归一化）vs **schema-free**（开放发现）。教育图谱应偏 schema-based。
- **限类型**：Neo4j `LLMGraphTransformer` 的 `allowed_nodes`/`allowed_relationships` 只抽指定类型，官方说明用于 "**reduce noise**"【已核实】。
- **先抽后归 schema**：AutoSchemaKG 先抽三元组，再用 LLM 把实体/事件/关系抽象为概念类型，"每个元素生成 ≥3 个不同抽象层级的短语"——**同一实体被组织到多级概念层**，为"细碎节点上卷为高层概念"提供现成范式【已核实】。
- **schema 引导组件**：LlamaIndex `SchemaLLMPathExtractor`；OMD-GraphRAG 的 schema 引导 + 类型后校验使 MultiHop-RAG 检索准确率 **+3.17%**。
- **"未找到"**：直接定量比较"先抽大纲再填充 vs 一次性抽取"的专门论文（最接近的是 §4.1 的 hierarchical vs all-in-one 概念性对照）。

### 4.3 第三类：去重/合并与"少而精"的证据

粒度失控的另一半来自**同义/碎片节点没被并轨**。业界做法：

- **Neo4j 官方三档 resolver**（neo4j-graphrag-python 文档）：①**精确匹配**（同标签同名，零误判，默认档）②**语义匹配**（spaCy 向量余弦，阈值 0.85–0.95）③模糊匹配（Levenshtein）。定位为**构建后后处理**，`SimpleKGPipeline` 默认开启。【已核实】
- **增量 ER 阈值经验值**（iText2KG, arXiv:2409.03284）：实体 **0.6±0.12**、关系 0.56±0.1，建议取上界 ~0.7 保精度；其 FDR 近 0（基线最高 0.31）。权衡数字：用全局实体作上下文 → 精度 0.83；用局部 → 0.94（图更贫但更准）。【已核实】
- **in-context clustering ER**（arXiv:2506.02509）：一次判一批（O(n²)→O(n/k)），配 LLM guardrails 验证。【已核实】

**"少而精"有实证支撑**：

| 证据 | 数字 | 来源 |
|---|---|---|
| entity-consistency 提示 → 节点更少但更连通 | 节点 **892→683**；巨型连通分量占比 **0.074→0.105** | arXiv:2510.11297 消融 Table 6 |
| 关系泛化：KGGen 远优于 GraphRAG | 平均每关系类型复用 **~10 次** vs GraphRAG **~2 次**；GraphRAG 常见"more singleton nodes" | KGGen（arXiv:2502.09956） |
| 单元粒度显著影响下游 | *"the granularity of fundamental knowledge units…has a significant impact on downstream performance"* | Dissecting GraphRAG, TACL 2026 vol.14:627–655 |

> **本章判断**：**生成侧的粒度控制 = "先粗后细的组织" + "schema 约束" + "三档去重"** 三件套。其中**性价比最高的两招**是：① 用 entity-consistency 式提示一次性"减节点 + 增连通"（实证 892→683）；② 补上"精确同名"这一档去重（零依赖、零误判，直接全歼字面重复）。**"先抽大纲再填充"的定量收益暂无一手对照实验**，但其思想（层级化）已被多个系统间接验证。

## 五、评测：粒度质量如何量化

改了粒度之后，"变好没有"必须可测。教育域没有现成 benchmark，但学术与工程侧有一套**通用图指标**可搬。

### 5.1 质量维度框架

| 框架 | 维度 | 来源 |
|---|---|---|
| 六维质量框架 | accuracy / consistency / timeliness / completeness / trustworthiness / availability | arXiv:2302.11509 §3.6.1 |
| 四类维度（北大） | intrinsic / contextual / accessibility / representation | KG Quality Management 综述 |
| 23 维度（含） | Accuracy、Completeness、Concise representation、**Appropriate amount**、Variety… | SN Comput. Sci., doi:10.1007/s42979-022-01429-x |
| 本体级 | OntoClean 元属性；结构度量 tangledness（多父类占比）、fan-outness（叶类占比） | Guarino & Welty；Gangemi et al. 2005 |

### 5.2 "粒度"专用指标（附实测参考值）

| 指标 | 定义 / 含义 | 实测参考（原文口径） |
|---|---|---|
| **Average Degree** | 每节点平均边数；*"Higher values indicate more integrated knowledge representations"* | Novel 集：GraphRAG **1.48** / LightRAG 2.10 / HippoRAG 1.73 / HippoRAG2 8.75（arXiv:2506.05690） |
| **Node Count** | *"Higher values imply broader domain coverage and **finer-grained** knowledge representation"* | — |
| **Avg Clustering Coefficient** | 邻域三元闭合度，衡量局部成簇 | 化学 KG：**0.0298**（arXiv:2504.16414） |
| **Graph Density** | 实际边 / 最大可能边 = 2E/(N(N−1)) | 化学 KG：**0.000127**（N=14,523, E=13,419, mean degree **1.85**） |
| **关系类型复用率** | 平均每关系类型使用次数 | KGGen **~10** vs GraphRAG **~2**（arXiv:2502.09956） |
| **孤立节点占比** | singleton/isolated ratio | GraphRAG 系"more singleton nodes"被列为欠连通症状 |

> ⚠ **未找到**：avg degree / clustering coefficient 的**权威"健康阈值"**。因此这些数只能用于**同规模横向参照**与**本项目纵向对比**，不能当"合格线"。这本身是一条结论：**粒度没有绝对标准，只有相对改善与任务相关性**。

### 5.3 可复用的评测口径（benchmark 与指标组）

| 口径 | 测什么 | 参考结果 |
|---|---|---|
| **MINE**（KGGen 提出） | MINE-1 知识留存、MINE-2 图谱辅助 RAG | KGGen **66.07%** > GraphRAG 47.80% > OpenIE 29.84%（arXiv:2502.09956） |
| **iText2KG 指标组** | Schema Consistency / Triplet Precision / Entity-Relation Resolution FDR | 0.94–0.98 / 0.83–0.94 / FDR 0.00–0.01 |
| **WebQSP / CWQ** | KGQA（Hits@1、F1） | 端到端问答质量 |
| **MOOCCubeX** | 教育数据集（637,572 细粒度概念） | 定位为数据集，**未提供 KG 质量评测口径** |

> **本章判断**：粒度评测应建立**四指标面板**——`avg degree`（连不连）、`巨型连通分量占比`（散不散）、`正文中位长度 + 空壳率`（深不深）、`关系类型复用率`（泛化不泛化）。**不要只看节点数**：节点数下降可能来自"有效合并"，也可能来自"漏抽"——必须与覆盖率/连通性**同时看**。

| # | 建议 | 外部依据 | 落点 | 优先级 |
|---|---|---|---|---|
| 1 | **加"实体一致性"提示**（同义/碎片概念强制复用同一节点），预期同时"减节点 + 增连通" | arXiv:2510.11297：节点 892→683、连通分量 0.074→0.105 | `GRAPH_GENERATOR_SYSTEM_PROMPT` 规则区 | P1 |

**关于"要不要给节点数设硬上限"**：外部**未找到**"每块抽取实体数上限"的硬约束范式（KARMA/KGGen 仅有类型/聚类约束）。因此本项目**不宜设硬性节点数上限**，而应通过"块大小 + 粒度判据 + 一致性提示 + 去重"**四者联合**间接控制，用评测面板验证结果——这与外部实践一致。

### 6.4 一条需要纠正的预期

| 误区 | 事实 | 依据 |
|---|---|---|
| "节点越少越好" | 节点少可能是**有效合并**（好），也可能是**漏抽**（坏）；必须与**覆盖率/连通性**同看 | arXiv:2510.14271（去噪）、KGGen（欠连通批评） |
| "正文越长越好" | 超过"可讲解单元"后，长正文会让检索变糊、注入预算被稀释；目标是**够深且自足**，不是无限长 | §3.2 时长口径、`上下文工程_预算框架`（S6 固定小配额） |
| "600–1000 字有标准依据" | 标准只给层级，**字数无权威来源**；该值是**由时长口径折算的工程目标** | §3.1 诚实声明 |

## 七、风险、边界与未决问题

| # | 风险 / 未决 | 说明 | 建议 |
|---|---|---|---|
| 1 | **深度 ↑ 的成本不确定性** | 块变大 + 正文变深 → 单次输出 token 涨；但块数从 335 降到 ~80–100，"已有节点清单"的 O(n²) 固定开销大幅下降，**净成本大概率持平** | 按 GQ-6 待办实测真实 token 量（GQ-10） |
| 2 | **"先粗后细"缺定量对照** | 外部**未找到**"先抽大纲再填充 vs 一次性"的直接定量比较 | 本项目可自证：同书跑两法，用 §五面板比 |
| 3 | **无权威粒度阈值** | avg degree / clustering coefficient 无"合格线"；知识点字数无国标 | 只做**同规模参照 + 纵向对比**，不外宣"达标" |
| 4 | **嵌入欠费导致语义去重长期降级** | L3 失效则"栈/堆栈"这类同义不同名仍各建节点 | 尽早恢复嵌入；短期靠 L1/L2 字面档兜底 |
| 5 | **合并不可逆** | `--fix-dupes` 会删节点与 MD 文件 | 执行前备份 `data/knowledge/{knowledge.db,nodes/}`，先 dry-run |
| 6 | **教育域标准仍在研制** | 《基础教育知识图谱建设技术规范》未定稿 | 本体若涉及"符合标准"，需等定稿后复核 |

**边界（本文不做）**：
- 不设计"检索 → 注入"下游（见 `知识图谱_路径查询与提示词注入_技术调研与实现方案.md`）；
- 不重定义本体类型（见 `知识图谱_参照系契约.md`）；
- 不展开"多资料融合"的溯源/对齐/冲突（见 `知识图谱_多资料综合维护调研.md`，其 arXiv:2305.04567 的"融合后取最粗粒度"是本文 §4.3 的姊妹结论）。
