# 知识图谱节点小节化：设计与实现方案

> **状态**：已评审定稿（2026-09-27），待实现。
> **取代**：《知识图谱_主题层级_设计与实现方案》《主题层级_实现计划》（2026-09-26，已于 2026-09-27 删除——主题层连表带数据下线，两级分层走不通，教训见 §1）。
> **表结构真值**：`knowledge_graph.py::_create_tables`（本方案**不新增任何 SQLite 表**）。

---

## 1. 背景与教训

### 1.1 两次失败的分层

| 尝试 | 失败原因 |
|---|---|
| 主题层（`themes`/`node_themes`，2026-09-26 → 09-27 下线） | 层级建在**图谱结构层**：章/主题节点污染了出题、统计、检索、图渲染四条读路径；聚合下钻真机效果差 |
| 单节点单 MD 长文（现行 `GRAPH_FILL_SYSTEM_PROMPT`） | 一个知识点一篇自足长文，深度不足；长 JSON 输出在 M3 上截断风险高；例题等可增长内容把单文件撑大 |

### 1.2 本次定位（与上两次的本质区别）

分层建在**内容层**，不碰图谱结构：

- 小节**不进** `nodes`/`edges`，不参与判重、建边、图渲染、出题统计；
- 一个节点 = 一个文件夹 = 若干**独立成章**的平行 MD + 一个 JSON 路由；
- 「二重积分」仍是**一个**节点；定义、公式、计算方式、例题是它名下的若干篇**独立微课**。

## 2. 核心决策（2026-09-27 用户拍板）

| # | 决策 | 内容 |
|---|---|---|
| D1 | **没有主 MD** | 小节全部平行，节点本体只是一个"文件夹 + 路由"，不保留概述主文件 |
| D2 | **manifest.json 路由** | 每节点一个 JSON 承担说明与路由（小节清单、试卷挂载）；文件系统当存储，不建 SQLite 表 |
| D3 | **小节独立成章** | 每个小节是单独的完整知识单元（微课），**不为拆而拆导致知识零碎**；一个侧面撑不起独立成章就并入邻近节 |
| D4 | **模板仅供参考** | 生成时注入参考模板（定义/公式/计算方式/例题…），但提示词明确"按知识点实际形态裁剪"——定理型没有"计算方式"，算法型可拆多方法节 |
| D5 | **老节点不迁移** | 存量单 `.md` 节点保持原样、照常可用；小节化只对**新触发**的节点生效（懒迁移也明确不做，用户拍板） |
| D6 | **触发入口本期不做** | 先做生成管线与读写通路；"深入"按钮/对话自动触发是下一期 |

## 3. 存储布局

```
data/knowledge/nodes/{user_id}/
├── double_integral/               ← 小节化节点 = 文件夹
│   ├── manifest.json              ← 唯一路由/说明层
│   ├── s01_定义与几何意义.md
│   ├── s02_计算方法_直角坐标.md
│   ├── s03_例题_交换积分次序.md
│   └── ...
├── binary_tree.md                 ← 老节点：单文件，原样保留（D5）
```

- 文件夹与老的单文件按「同名路径一个是目录一个是文件」天然区分，读路径先探测目录。
- 小节文件名 = `{section_id}_{title安全化}.md`（`section_id` 形如 `s01`，manifest 内唯一）。

### 3.1 manifest 结构

```json
{
  "node_id": "double_integral",
  "name": "二重积分",
  "subject": "高等数学",
  "version": 1,
  "sections": [
    {"id": "s01", "title": "定义与几何意义", "kind": "definition",
     "file": "s01_定义与几何意义.md", "status": "filled",
     "brief": "一句话说明这节讲什么", "origin": "section_gen",
     "sources": [{"doc_id": 7, "doc_name": "高等数学.md", "section": "第9章",
                  "chunk_id": null, "extracted_at": "..."}],
     "created_at": "...", "updated_at": "..."}
  ],
  "quizzes": [
    {"id": "q-xxxx", "section_id": "s03", "source": "quiz_store", "created_at": "..."}
  ]
}
```

- `kind`：**软标签**（`definition`/`formula`/`method`/`example`/`mistake`/`custom`…），只用于 UI 图标与生成参考，**不做枚举校验**（配合 D4"模板仅供参考"）。
- `status`：`filled / failed`（生成管线写）；单节失败不拖垮整批，可单独重试。
- `sources`（2026-09-28）：**小节级溯源** —— 本节实际依据的资料片段（五键与 `nodes.sources` 同款，
  经 `normalize_source_entry` 收口，不含正文）。来源选择 = 阶段① 规划时模型给每节标注
  `source_refs`（材料编号）→ 落盘时按编号取条目；**标注缺失/越界一律回退"本批全部来源"**
  （宁可宽，不可张冠李戴）。与 `nodes.sources` 的差别：粒度到节、是本次生成的**快照**，不入库。
- `quizzes`：**引用路由**（指向 quiz_store 已有题目）。按小节出题已落地（见 §7），
  节点级出题**不写**这层路由（否则 manifest 无上限膨胀，`clear_sections` 只保留节点级引用）。

### 3.2 为什么是 manifest 而不是 SQLite 表

- 不触发 AGENTS.md 红线三处同步（admin 删号清单 / 体检脚本 / 文档路由）；
- 删节点 = 删文件夹，天然级联，无脏数据风险；
- 节点规模 10²–10³，manifest 全量扫描成本可忽略（且实例内有缓存，见 §5）。
- **代价**（明确接受）：跨节点查询（"所有 failed 小节"）无 SQL，靠体检脚本扫目录。

## 4. 地图与查询效率（三层分工）

分层后各存储的角色**严格分工**，保证地图性能与查询效率：

| 层 | 载体 | 职责 | I/O 特征 |
|---|---|---|---|
| **地图层** | SQLite `nodes`/`edges` | 图渲染、学科统计、判重并轨、掌握度、路径查询、Agent 图谱摘要注入 | **零文件 I/O**，只查库 |
| **路由层** | `manifest.json` | 节点内小节目录、状态、试卷挂载 | 实例内缓存（对齐现有 `_content_cache` 模式），写时失效 |
| **内容层** | 小节 MD | 正文，按需读取 | 永不全量加载；前端点开哪节读哪节 |

**效率关键点**：

1. **地图不读文件**：小节化完全不动 `nodes`/`edges`，图渲染与对话注入的通路不变。
2. **阶段①规划回写 `nodes.summary`**：生成小节时把节点一行摘要刷新进 `nodes` 表（走既有 `update_node_info` 唯一出口，`added_by=ai`）——地图标签始终新鲜，地图层永远不需要打开 manifest。
3. **节点内 O(1) 定位**：前端列表页拿 manifest 元数据（title/kind/status，无正文），选中后按 `file` 直读单个 MD。
4. **跨节点小节搜索本期不做**（挂账 §9）：RAG chunks 键仍按现状；将来升级为 `{node_id}/{section_id}` 时 manifest 提供元数据。

## 5. 读写收口（AGENTS.md §2 纪律的延续）

`KnowledgeGraph` 新增唯一出入口，所有调用方（生成管线 / 未来的 Agent 工具 / 手动编辑 API / 前端）不得绕过：

- `read_manifest(node_id) -> dict | None`（None = 老节点或无小节）
- `write_manifest(node_id, manifest)`：**原子写**（临时文件 + `os.replace`）；实例内缓存失效
- `list_sections(node_id) -> list[dict]`（manifest 的 sections，含元数据不含正文）
- `read_section(node_id, section_id) -> str`（按 manifest 路由读单个 MD）
- `write_section(node_id, section_id, content)`（落盘 + 更新 manifest 的 `updated_at`）
- `create_section(node_id, title, kind, content) -> section_id`
- `delete_section(node_id, section_id)`（删文件 + 改 manifest）

并发防护：manifest 读改写经**实例内锁**（`KnowledgeGraph` 每请求新建、单 uvicorn worker，风险窗口仅在多协程并发写同一节点——加 `asyncio` 侧不介入，文件级原子写兜底"最后写赢"，不做跨进程锁）。

## 6. 生成管线（本期核心）

新模块 `backend/app/core/kb/section_generator.py`，复用 `call_llm`/`extract_json` 与现有截断防线（`GRAPH_SHALLOW_REJECT_CHARS` 同款拒收线）。

### 6.1 阶段①：规划小节（一次 JSON 调用）

- **输入**：节点名/summary + 溯源资料节选（`doc_node_marks` → KB 原文，上限对齐 `GRAPH_CONCEPT_SOURCE_CHARS=6000`）+ 前置/关联节点名。
- **输出**：`{"sections": [{"title", "kind", "brief"}], "summary": "节点一行摘要"}`。
- **提示词铁律**（D3/D4 的落点）：
  - 切分依据 = **可独立教学的知识单元**，沿用"只读这一段就该学会"的自足判据；
  - **一个侧面撑不起独立成章就并入邻近节，禁止为拆而拆**；
  - 参考模板注入但声明**仅供参考、按知识点实际形态裁剪**。
- 产出回写：`create_section` 建条目（`status` 待填）+ `update_node_info` 刷新 `nodes.summary`（地图层）。

### 6.2 阶段②：逐节成文（每节一次调用）

- **输入**：单节 title/brief + 按 brief 筛过的资料片段。
- **输出**：**纯 Markdown 直出**（不走 JSON 包 content——这是现行 fill 管线最脆的截断雷；kind 等元数据阶段①已有，无损）。
- `thinking=False` + 显式 `max_tokens`（对齐 M3 三段坑纪律）；每节独立落盘；**单节失败标 `failed` 并跳过**，不拖垮整批，可单独重试。

### 6.3 与建图管线的关系（2026-09-27 收口：建图阶段② 已接入本管线）

`graph_generator` 阶段①（概念树 → 骨架节点）不变；**阶段② 改为直接小节化**：`_fill_concept`
按节点形态分流到 `_fill_sections`，由本模块承担成文（`source_text` 用建图已抓到的原文，
免二次重读 KB + 重切分）。新概念建出来就是「文件夹 + manifest + 平行小节 MD」。

- **两层粒度判据方向相反，别混**：阶段① 概念树管「**节点**是不是一个内聚知识点」
  （粗了要拆、细了要合，判据写进 `GRAPH_CONCEPT_TREE_SYSTEM_PROMPT` 的内聚判据）；
  本模块管「该节点**内部**还有哪些内聚小节」（`SECTION_PLAN_SYSTEM_PROMPT` 的三条铁律）。
- **命中老单 MD 节点**（有正文、无 manifest）仍走 `_fill_legacy`：只追加一篇「补充讲解」，
  不改写既有正文、也不把它改造成小节节点 —— 前端对有小节的节点只渲染小节，就地改造会让老正文看不见。
- 小节化后 `content_status` 由 `KnowledgeGraph.set_content_status` 翻 `filled`（正文在小节里，
  主 MD 仍是骨架占位）；**读正文一律走 `KnowledgeGraph.node_content_text`（小节优先）**，
  否则图谱注入 / RAG 索引 / 出题依据 / 导出会集体失明。

## 7. API 与前端（最小闭环）

- `GET /knowledge/node/{id}`：响应加 `sections`（manifest 元数据列表 `id/title/kind/status/sources/updated_at`）；**兼容**——老节点无 manifest 时 `sections: []` 且 `content` 照旧返回单文件全文。
- `GET /knowledge/node/{id}/section/{section_id}`：读单节正文。
- `POST /knowledge/node/{id}/section/{section_id}/quiz`（2026-09-28）：**按小节出题**（后台生成，
  几秒后推 `quiz_ready`）。与节点级出题的三点差别：只喂该节正文作依据 → 题目 `add_quiz_ref`
  挂到该节 → 题目 `source_docs` 记该节 `sources`。与对话内出题共用 per-user 去重位，
  已在出题 → 409。
- 前端 `NodeDetail.vue`：**阅读模式恒为左栏 + 右正文** —— 有 manifest 则左栏列小节（点击懒加载单节 MD，每节右侧有「针对本节出题」按钮）；老节点则左栏只有一项「正文」（右侧渲染其单 MD，不迁移）。小节正文上方标「来源：⟨资料⟩ · ⟨章节⟩」。左栏底部有「试题」分组（`knowledge_point = 图谱节点 id` 自动关联，带小节归属时显示「属 ⟨小节标题⟩」，题目 `source_docs` 显示「来源：⟨文件⟩」），点击跳出题页并聚焦该题。
  - **死锁教训（2026-09-27 修）**：第一版把「生成小节」按钮放进只有 `has_sections=true` 才渲染的侧栏里 → 没小节就没有侧栏、没有侧栏就无法生成小节。现在按钮在无 manifest 时显示，侧栏恒渲染。
