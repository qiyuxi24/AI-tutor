### 1.3 检索通路地图（三条，互不共享索引）

```
① 参照系注入（每次必在，非检索）
   chat_service._build_system_prompt → graph_analyzer.build_graph_context
   → 全量节点/边渲染 → 超 GRAPH_INJECT_MAX_CHARS(12000) 按「省摘要 → 限量节点+focus 邻域」降级
   （graph_analyzer.py:209-269）

② 按需检索（命中才用）
   rag_pipeline.pipeline → GraphRagSource → rag_manager.search
     = 向量 top5（MIN_SCORE 0.25）+ prerequisite 反向扩跳（hops，默认 0=关）
   rag_pipeline.pipeline → KbRagSource → kb_manager.search
     = 向量 + whoosh BM25 → RRF 融合（hybrid_search/fusion.py）
   ⚠️ 两源分数**尺度不同**（余弦 vs RRF），pipeline 层是"拼段落"而非统一重排

③ 结构化切片（只服务图谱页，对话链路未接）
   graph_middleware.slice_graph(subject, board)  ← 依赖 §1.2 的两条隐含约定
```

### 1.4 实体关系与"一条数据的一生"

```
users(id) ──1:N──> nodes(id, name, subject, board, tags, mastery, difficulty, …, user_id)
                     │  ▲
                     │  └── node_aliases(alias_key, node_id, user_id, source)   (别名 → 本体, 多对一)
                     ▼
                   edges(from_node → to_node, relation, label, confidence, created_at/updated_at, user_id)
                     relation ∈ {prerequisite, related, confusion, extension}
        │ node_id                                  │ node_id
        ▼                                          ▼
  data/knowledge/nodes/{uid}/<id>.md        data/rag/{uid}/rag.db :: chunks
```

**全库统一语义约定（写进 docstring 的三条）**：① 边方向 `A → B (prerequisite)` = **A 是 B 的前置**（查前置沿边**反向**走，`get_prerequisites` 递归 CTE）；② 学科归属走 `subject` 列，空则回退"tags 第一个非难度标签"；③ 同名并轨 = `normalize_node_name` 归一后相同 → 不新建、只并入正文，**并返回实际落点 ID**（调用方用返回值建边）。

```
教材 PDF ──kb 解析──> 章节/单元文本 ──graph_generator(LLM)──> {节点 + 边 + subject/board/tags}
   └─ create_node_with_content()  ← 唯一写入口
        ├─ L1 精确同名 → 并轨（返回已有 id）  ├─ L1.5 别名 → 并轨（node_aliases）  └─ 新建 → nodes 行 + MD
对话：build_graph_context（每次注入全量框架，超 12000 字符降级）+ rag_manager.search（向量；失败→关键词兜底）
   └─ LLM 回答 → 写回（graph_analyzer / agent 工具）→ 更新 nodes/edges/MD → graph_updated 事件 → 前端刷新
```

## 2. 逐项评审（问题 → 后果 → 判据）

### 2.1 学科建模：靠标签位置猜（P0）
**现状**：`node_subject()` 遍历 `tags` 取第一个非难度标签。**问题**：把"分类维度"编码成"数组位置"，schema 无法约束、索引无法加速、`WHERE subject='x'` 写不出来（只能全量 Python 过滤，`get_nodes_by_subject:571-573`）。**已发生后果**：`TODO.md §4` 实测出现 6 个 ≤2 的杂标签；`compute_stats` 必须合成「未分类」分组兜底（`graph_middleware.py:27`、`:207-210`）——这个补丁本身就是模型缺陷。**判据**：一个维度若要参与**过滤/统计/隔离**，就必须是列，而不是数组约定位置。

### 2.2 难度与层级共用一个标签空间（P0）
`graph_generator` 写 `tags = [subject] + ["一级"|"二级"|"三级"]`（来自难度映射）。**问题**：`一级/二级/三级` 字面像"层级"、实际是"难度档"，还与学科标签抢 `tags[0]`。**判据**：同一字段承担两种语义（分类 + 标度），读方必须知道写入顺序才能正确解释 —— 隐式耦合。

### 2.3 层级（part_of）不存在（P0）
教材章—节结构在生成时被丢弃，只留扁平 `board`。**后果**：① 无法按"第 5 章"选片 → `参照系契约 G1` 的 `slice_graph` 选片只能按 `subject/board`；② 注入降级只能"按 focus 邻域 + 字符数"砍（`graph_analyzer.py:245-268`），丢的是**随机语义块**不是"整章"；③ 出题/讲解无法表达"本章内"范围。**判据**：`part_of`（结构包含）与 `prerequisite`（学习依赖）是两种关系，混用会同时破坏两者；项目目前只有后者。

### 2.4 `nodes.id` 全局主键（**有意取舍，建议不改**）
全局唯一 → `_node_id_exists_globally:714-724`、`generate_node_id` 回退 `new_001:743-749`；系统其余部分**全部按 `user_id` 分区**，唯独主键全局共享命名空间。**判定**：**不改**。改 `(user_id,id)` 复合主键 = 21 个端点 + 前端 + `rag.chunks.node_id` + `quiz` + `agent_runs` 证据链全动，收益只是"少一次全局查重"。正确做法是**把取舍写进文档**：`id` 是全局命名空间里的稳定标识，用户内唯一性由 `find_node_by_name` 保证。

### 2.5 身份层只有"字符串归一化"，没有别名（P0）
并轨（去重 L1）唯一实现 = `normalize_node_name`（NFKC + 去空白 + 小写 + 剥 `_extended`/「复习」类后缀）+ 同学科过滤（`:49-62`、`:251-269`）。**问题**：只能处理"字面相同 + 碎片后缀"，**处理不了同义不同名**（"栈/堆栈"仍各建一个）；原设计依赖 L3 语义档兜底，但嵌入长期欠费 → 变成"零兜底"。**业界对照**：SKOS 的 `prefLabel`/`altLabel`；Neo4j GraphRAG 的 Entity Resolution 三档（精确→语义→模糊），我们只实现了中间档。**判据**：字符串归一化是"减法"，别名是"加法"（可人工维护、可审计、不依赖嵌入）。

### 2.6 掌握度：学习状态钉在知识本体上（P0）
`nodes.mastery INTEGER`（单值）+ `difficulty/estimated_minutes`（属知识本体，合理）。**问题**：① **语义错位**（`nodes` 描述"知识是什么"，`mastery` 描述"某人学到哪" —— 生命周期与所有权不同）；② **不可回溯**（判分答对 +20，但**没有一条记录说"这 20 分是哪道题、什么时候加的"**；`quiz.attempts` 存了作答却没回指图谱节点）；③ **不可演化**（无法做遗忘衰减/时间序列/置信区间，而 BKT/DKT 恰恰把掌握度建模为**学生 × 知识点**的隐状态，由作答事件驱动）；④ **合并即污染**（同名并轨时掌握度如何合并无定义）。**判据**：状态类字段必须能回答"谁改的、什么时候、凭什么"——现在三个都答不出。

### 2.7 边：约束与属性都缺（P1）

| 缺什么 | 后果 | 证据 |
|---|---|---|
| `UNIQUE(user_id,from,to,relation)` | 并发/脚本直写可产生重复边；查重只在 `add_edge` 代码里 | `:1023-1031` |
| `created_at` / `updated_at` | 无法做增量索引、无法审计"这条边谁哪天连的" | 表定义 `:149-161` |
| `sources`（来源段落） | 多源调研 L0 的溯源层无法落地；L3 引用只能到 node 不能到页 | `外部调研 §多源融合 L0` |
| `weight` | 多源融合/多准则推断给出的置信强弱无处存（`confidence` 有列但建图不写） | `:156` |
| 校验触发器 | 直接 SQL/脚本写非法 relation 不会报错（代码枚举只在 `add_edge:1012`） | 同上 |

### 2.8 无向关系的方向语义（P1）
`related` / `confusion` 语义上**无向**，但存储与查重都是**有向**（`:1025` 查 `(from,to,relation)`）→ `A→B(related)` 与 `B→A(related)` 可并存，渲染时出现两条重叠边。**判据**：关系类型必须显式声明有向性；无向关系要么归一化存储，要么查重时对称检查。项目现在是"隐式有向"，全靠调用方自觉。

### 2.9 检索：单腿 + 只走一种边 + 分数不可比（P0/P1）

| 子问题 | 现象 | 锚点 |
|---|---|---|
| **单腿** | 嵌入 API 欠费 → `search()` 返回 `[]`（**无关键词兜底**）→ 图谱按需检索全失效 | `rag/manager.py:204-210` |
| **只走 prerequisite** | 扩跳函数名就叫 `_expand_prerequisites`；`related/confusion/extension` 完全没用（`confusion` 教学上最值钱：易混点） | `rag/manager.py:219-268` |
| **分数不可比** | graph 源给余弦、kb 源给 RRF 分 → pipeline 只能按源拼块，不能统一重排 | `rag_pipeline/sources.py:54-74`、`:133-180` |
| **chunk 与节点结构不对齐** | `chunk_markdown` 按 MD 标题切（`rag/chunker.py:43-84`），而节点正文已是五段式 → 语义单元被切散 | 同上 |
| **`chunk_index` 段内重复** | `flush()` 内 `enumerate(_split_long_paragraph(text))` → 每个小节从 0 开始 | `rag/chunker.py:60-74` |
| **向量解码开销** | `embedding` 存 JSON 文本 + 检索时全表 `SELECT` 再 `json.loads` | `rag/vector_store.py:40-51`、`:111-145` |
| **两条 whoosh 冲突** | kb 的 whoosh 把 `node_id` 定为 `NUMERIC`，图谱 `node_id` 是 `TEXT` → 复用需改 schema（旧"不做"依据；KG-D5-b 已用参数化解决） | `hybrid_search/whoosh_index.py:61-70` |

## 3. 结构全貌与选型理由（原《设计说明》要点）

**长什么样**：不是一张"图"，而是**四张关系表（`nodes` / `edges` / `node_aliases` / `mastery_events`）+ 三类派生索引（chunk 向量、稀疏关键词、MD 正文文件）**：元数据在 SQLite，正文在每节点一个 `.md` 文件，向量/全文在按用户分区的派生库里（§1）。

**为什么这么选**：图的**用途**是"每次调用的教学参照系 + 可审计的路径依据"，不是"从海量文本里找答案"。用途决定了它必须**小、稳、可解释、可增量、零额外服务**。

| # | 决策 | 放弃了什么 | 选它的理由 | 什么时候该改 |
|---|---|---|---|---|
| 3.1 | **关系库邻接表（SQLite）而非图数据库** | Cypher 声明式多跳、GDS 图算法、原生 PPR | 规模 = **单用户 10²–10³ 节点 / 10³ 边**；Docker 单容器不增服务；递归 CTE 已能表达先修链与拓扑序；迁移/备份 = 一个文件 | 需要**频繁多跳 + 图算法**（PPR/社区检测）且单图 >10⁵ 节点时 |
| 3.2 | **`nodes` + `edges` 两张表，而非 RDF 三元组表** | 谓词可任意扩展、W3C 标准互操作 | 我们的"属性"是**字段**（mastery/difficulty/subject），不是**可无限增长的谓词**；两表能加索引、能写约束 | 接入外部本体（CELTSC）时加一层导出即可，不必改存储 |
| 3.3 | **正文存 MD 文件，元数据存库** | 全文 SQL 检索、事务一致性 | 正文是"教学内容"，需人工可读可编辑、可 diff、可版本化；库只放**可索引的结构化字段** | 正文需**全文检索排序**时，加 FTS 索引（不必搬进库） |
| 3.4 | **`id` 为 TEXT，全局唯一（非 per-user）** | 用户内命名自由 | 改复合主键要动 21 个端点 + 前端 + 全部跨表引用，收益仅"少一次全局查重" | 只有当**跨用户共享知识库**成为需求时 |
| 3.5 | **学科升为 `subject` 列（KG-D1，已落地）** | 少一列、少一次迁移 | 学科要参与**过滤/统计/隔离**三件事 → 必须是列；原"tags 首位"是位置约定 | 已改，无需回退 |
| 3.6 | **`part_of`（层级）与 `prerequisite`（依赖）分离** | 只用一种边更简单 | 两者语义正交：章包含节 ≠ 节是章的前提；混用会同时破坏组织与学习顺序（现只有后者，`parent_id` 待做 KG-D7） | 层级上线后有"章节点 vs 虚拟路径"的取舍（§13 待拍板） |
| 3.7 | **别名单独建表，而非给 nodes 加 `aliases` JSON 列** | 少一张表 | 别名要**反查**（这个写法归哪个节点？）→ 需要索引与唯一约束；JSON 列无法高效反查 | 若要支持跨用户共享别名，主键需加维度 |
| 3.8 | **掌握度保留在 `nodes.mastery`，另加事件表（KG-D4）** | 彻底外移到 `user_node_mastery` | 外移要动 21 个端点；事件表已能回答"谁改的、凭什么、何时"——**收益的 80% 用 20% 的改动拿到** | 出现"一知识点被多学习者共用"的需求时 |
| 3.9 | **不做 KGE 补边 / 不做社区摘要** | GraphRAG 系的"全局问题"能力 | KGE 补边产生**不可解释的边**，与"可审计"冲突；社区摘要要海量 LLM 调用且**增量不友好**，我们的图不是从文本抽的 | 若要做"整本书在讲什么"的全局问答，另建**只读**的主题层，不污染教学图 |
| 3.10 | **注入 = 全量框架 + 字符预算降级，而非检索式注入** | 省 token | 契约要求图谱**每次都在**（参照系语义）；检索式注入会让"约束"变成"命中才约束" | 选片（KG-D11）上线后改为**按学科/层级选片**（仍是"选片"不是"检索"） |
| 3.11 | **三档去重（精确 → 别名 → 语义）而非单一 LLM 判定** | 更少代码 | 精确档零成本零误判；语义档贵且依赖嵌入 → 分档可在任一层降级仍可用 | L3 语义档恢复后按 `dedup_status` 暴露质量 |
| 3.12 | **每条边只有 `relation`（枚举 4 值），先不加权重语义** | 更细的关系类型 | 类型越多，LLM 抽取混淆与人工维护成本越高；4 类覆盖教学主需求，且**放宽是兼容的** | 多源融合要表达"有多强"时加 `weight`（对错 vs 强弱） |

### 4.4 我们更强或与众不同的地方（可以自信讲的部分）
1. **用户级图谱隔离**：`KnowledgeGraph(user_id)` 每人一张图 —— 同类开源多数是全局单图。
2. **图既读又写**：对话中发现新知识点写回同图（GraphRAG 系普遍只读）。
3. **教学语义分级**：`subject → board` 两级分组对应教学组织（比 LightRAG 的检索语义层更可解释）。
4. **不做社区摘要 = 省掉最大的成本坑**，且图不是文本抽的 → 无需为"抽取准确率"付二次 LLM 校验成本（代价见 §6.3）。
5. **可审计**：结构约束（无悬空边/自环/重复边/先修环）+ 每次运行可凭 `run_id` 回源完整输入输出（参照系契约 AC-L3-1）。
6. **零额外服务**：SQLite + 文件 + 派生库，单容器可跑（对比 Neo4j 系要加一个服务）。

## 5. 方便检索吗？—— 能力矩阵

**现在就能高效做的（附真实 SQL）**：

```sql
-- ① 先修链（递归 CTE，实现在 get_prerequisites）
WITH RECURSIVE chain AS (
  SELECT from_node, 1 AS depth FROM edges WHERE to_node = ? AND relation='prerequisite' AND user_id = ?
  UNION ALL
  SELECT e.from_node, c.depth+1 FROM edges e JOIN chain c ON e.to_node = c.from_node
   WHERE e.relation='prerequisite' AND e.user_id = ?) SELECT DISTINCT from_node FROM chain;
-- ② 学习顺序（Kahn 拓扑，实现在 topological_sort，Python 侧）
-- ③ 学科/板块切片（KG-D1 后走索引，不再全表 Python 过滤）
SELECT * FROM nodes WHERE user_id = ? AND subject = ? AND board = ?;
-- ④ 别名/同名定位（KG-D3）
SELECT node_id FROM node_aliases WHERE alias_key = ? AND user_id = ?;
-- ⑤ 节点邻域（注入降级时的 focus 邻域）
SELECT * FROM edges WHERE user_id=? AND (from_node=? OR to_node=?);
-- ⑥ 关键词兜底（KG-D5，嵌入不可用时的通路）
SELECT * FROM nodes WHERE user_id=? AND (name LIKE ? OR summary LIKE ?);
```

| 通路 | 触发 | 检索方式 | 粒度 | 现状 |
|---|---|---|---|---|
| 参照系注入 | **每次调用** | 全量框架渲染 + 字符预算降级（12000 字符） | 节点 + 边 | ✅ 已上限控制 |
| 图谱语义检索 | `rag_search` / 对话按需 | 向量余弦 top-5（`MIN_SCORE 0.25`）+ prerequisite 反向扩跳 | chunk | ⚠️ 嵌入欠费 → 走兜底 |
| 图谱关键词兜底 | 嵌入失败时自动 | name/summary 子串（0.35/0.30） | 节点 | ✅ 2026-09-23 新加 |
| 图谱切片 | 图谱页 | `subject` / `board` 两维 | 子图 | ✅（对话链路未接） |
| 上传知识库 | 对话按需 | 向量 + whoosh BM25 → RRF → top-5 | chunk | ✅（欠费期间入库的 NULL 向量块需重传才恢复向量召回） |

**不够方便、需改造的查询**：`"第 5 章下的所有节点"` **做不到**（缺 `parent_id`/`path`，KG-D7）；`"沿 related/confusion 走 2 跳"` 只能手写邻接（KG-D9）；`"全库按关键词排序找"` 无 BM25（whoosh 只覆盖 kb，KG-D12）；`"上周改过哪些节点"` ✅ 可查（`nodes.updated_at`，2026-09-23 落地）；`"两源命中的结果统一排序"` 余弦 vs RRF **量纲不同**（KG-D10）；`"这个知识点被哪本书哪一页支撑"` 只能到节点（KG-D8）。

**判断：结构不是检索的瓶颈**。规模 = 单用户 10²–10³ 节点 / 10³ 边；带索引的等值/范围查询与递归 CTE 在毫秒级，全表扫描（兜底子串）也可接受。缺索引清单已清到只剩 FTS（排序维度，KG-D12）。在"每用户一张小图 + 每次都要注入框架"这个场景下，**关系库邻接表是合适的**；真正需要图数据库的是"单图很大 + 频繁多跳 + 要图算法"（我们不是）。

## 6. 准确率

### 6.1 四层"准确率"（混在一起谈没有意义）

| 层 | 指标 | 我们现在的数字 | 证据强度 |
|---|---|---|---|

### 6.3 与业界口径对照 / 为什么目前说不高
- **实体消解阈值**：业界语义档 0.85–0.95（Neo4j GraphRAG）→ 我们语义档**未启用**（嵌入欠费）→ 只能用零嵌入的 L1/L1.5。
- **抽取质量**：业界多用人工标注集算 P/R/F1 → 我们**无标注集、无数字**（补的第一优先级）。
- **三个结构性原因**：① 图的产出方是 LLM 且无 gold（正确性无从度量）；② 本该兜底的语义档长期欠费（历史欠费期的漏合并已形成存量，体检仍报 23 组同名）；③ 评测对象错位（测的是 kb 检索与先修推断，**图谱自身检索质量还没测过**）。

### 6.4 补齐顺序（按性价比）
1. ✅ **图谱开/关 A-B 对照**（`scripts/eval_graph_injection.py` + 14 例数据集 + 报告）；剩余 = 把"幻觉率"从代理口径升级为人工标注样本。
2. **图谱检索专项评测**（人工标 30–50 条"问题 → 应召回节点"，复用 `eval_rag.py` 口径）。
3. **抽取质量标注集**（抽 30–50 个节点人工判"定义/要点/示例/易错"是否成立）。
4. **接 MOOCCubeX 先修子集**（脚本已就绪，只差下载与转换）。
5. 恢复嵌入后重跑 `eval_rag.py --embed api`（真实向量数字替换 mock）。

## 8. 目标 schema（v2）

> 原则：**只 ADD COLUMN / CREATE TABLE，不重建表**（SQLite 无法给已有列加 `CHECK`）；迁移幂等；老数据 `NULL`/`''` 一律解释为"未知"，不阻塞任何读路径。

### 8.1 `nodes` 新增列

| 列 | 类型 | 语义 | 谁写 | 回填 | 状态 |
|---|---|---|---|---|---|
| `subject` | `TEXT DEFAULT ''` | **学科**（一等公民，替代 tags 位置约定） | 所有写路径（`create_node_with_content` 统一注入） | 一次性脚本 | ✅ D1 |
| `updated_at` | `TEXT` | 变更时间（增量索引/审计） | `update_node_info` / `update_node_content`（含并轨）/ `add_node` | `= created_at` | ✅ 2026-09-23 |
| `parent_id` | `TEXT` | **part_of 父节点**；`NULL` = 顶层 | 建图 + 手动编辑 | 留空（老数据无层级，不瞎猜） | ⏳ D7（**已作废**，见 §12 路线） |
| `path` | `TEXT DEFAULT ''` | 物化路径 `学科/章/节`，供选片（免递归 CTE） | 同上 | 留空 | ⏳ D7（**已作废**） |

新增索引：`CREATE INDEX idx_nodes_user_subject ON nodes(user_id, subject)`。`mastery_events` 落地后 `nodes.mastery` 语义降级为"**当前值缓存**"。

### 8.2 `edges` 新增列 + 约束

| 列/约束 | 内容 | 状态 |
|---|---|---|
| `created_at` / `updated_at` | 建边时间 / 最近修改 | ✅ 2026-09-23 |
| `UNIQUE INDEX` | `(user_id, from_node, to_node, relation)` | ✅ 2026-09-23 |
| `weight` | 强度（多源支撑数 / 多准则得分）—— 与 `confidence` 分工：**confidence = 对不对，weight = 有多强** | ⏳ **暂缓**（无写入方） |
| `sources` | `[{doc_id, doc_name, chunk_id, span, extracted_at}]` | ⏳ 归 KG-D8 |
| **无向归一化约定** | `related`/`confusion` 写入时按 `from_node < to_node` 归一化存一行 | ⏳ 待拍板（会改存量边） |

**实现要点（KG-D6，已落地）**：列/索引都在 `_auto_migrate` 幂等补，**不重建表**；**有重复边时索引建不上 → 只告警不阻断启动**，由 `inspect_graph_quality.py` 报出后人工合并（真实库 679 边实测重复组 **0**）；唯一约束兜住并发/脚本直写，`add_edge`/`update_edge_by_id` 把 `IntegrityError` 映射回 `ValueError("边已存在…")`，API update 据此返回 **409**。**不做的**：给 `relation` 加 SQL 级 `CHECK`（SQLite 加不上已有列）→ 本次不加触发器（两条写路径已守，唯一索引已覆盖现实风险）。

### 8.3 新增表一：`node_aliases`（别名层，判重 L1.5 档）
见 §1.1 DDL。**写入时机（三处，都不依赖嵌入）**：① `create_node_with_content` 未命中同名 → 把 `name` 登记为别名；② **并轨命中 → 把被并入的 `name` 登记为保留者别名**（"同一概念曾用名"）；③ 人工/LLM 显式标别名。**读取**：`find_node_by_name` 先查别名表，未命中再走现有归一化比较 → "栈 / 堆栈"只要登记过别名，之后**零嵌入**也能并轨。

### 8.4 新增表二：`mastery_events`（掌握度证据链）
见 §1.1 DDL。**唯一写入点（已落地）= `KnowledgeGraph.update_node_info`** —— 所有改 `mastery` 的路径（`update_mastery` 工具 / 判分回写 / `PUT /node/{id}` / 问题拆解）全经它，事件与节点更新**同一事务**。**理由参数** `mastery_reason=`/`mastery_evidence=`（默认 `manual` → 老调用方零改动）：`quiz_correct`+`question:<id>`（判分答对）、`self_report`（`update_mastery` 工具）、`manual`。**读取** `get_mastery_events(node_id, limit)`。**顺带解决**：① 可回溯；② 合并节点时可按事件重放（**尚未接**）；③ 未来接遗忘衰减/BKT 时数据已在。**明确不做**：不引入 BKT/DKT 参数。

### 8.5 迁移与回滚
M1 `ADD COLUMN`+建索引（幂等，沿用 `_auto_migrate`）→ M2 `subject` 回填 → M3 时间戳回填 → M4 无向边归一化（`--apply` 前 dry-run）→ M5 `nodes_fts` 建表填充。**统一走 `records.py` 纪律**（`AGENTS.md §1`）：加表写自己的 schema + `records.connect` + `main.py::_prune_once` 的 `_JOBS` 加一行；加列写进 `store._COLUMN_MIGRATIONS`。

## 9. 检索通路改造设计

**三条通路定位（不要互相替代）**：① 参照系注入 = 每次必在的框架约束（**不动**）；② 按需检索 = 补关键词兜底 + 按 relation 分策略扩跳 + 跨源统一融合；③ 结构化切片 = 从 `subject/board` 升级为 `subject/path`（有 `parent_id` 之后）。

### 9.2 补"第二条腿"（解决嵌入欠费即全失效）

| 方案 | 做法 | 判断 |
|---|---|---|
| **A（推荐先做）** | `name/summary` 用 `LIKE '%kw%'` | ✅ 最少代码，立刻消除单点依赖 |
| B | FTS5 `tokenize=trigram` + 1–2 字回落 A | 加**相关性排序**（BM25）时才值得 |
| C | 写入时 bigram 展开 + `unicode61` | B 的排序不够且 2 字命中率是瓶颈时 |

关键词命中的分数**不能**直接与余弦混排（尺度不同）→ 统一走 RRF。顺带把 `chunk_index` 改全局递增，使 `(node_id, chunk_index)` 成为**唯一溯源键**。
> ⚠️ 本机 SQLite 3.50.4 实测：`tokenize=trigram` 对 **≥3 字**查询命中（`先进后出`✅、`数据结构`✅），**1–2 字不命中**（`栈`✗）——中文高频词多是 2 字。

### 9.3 图结构扩跳：从"只走 prerequisite"到"按关系分策略"

| 关系 | 方向 | 建议跳数 | 教学用途 |
|---|---|---|---|
| `prerequisite` | **反向**（补前置） | 1–2（现有默认 1） | 学生卡住 → 补基础 |
| `confusion` | 双向 | 1（同桌） | "你容易和 X 混"，现有检索完全没用上 |
| `extension` | 正向 | 1 | 学有余力 → 进阶 |
| `related` | 双向 | 0（默认关） | 噪声大，按需开 |

接口形态（最小改动）：`rag_manager.search(..., hops, relations=...)` 的 `hops` 从 `int` 扩为按关系配置（默认保持现状 → 老调用方零改动）。⚠️ **预算纪律**：扩跳是注入体量的放大器 → 新增关系必须**共享同一个条数上限**。

### 9.4 结构化选片（依赖 §8.1 的 `parent_id`/`path`）
现状：注入超预算时按"focus 邻域优先 + 字符数"二分截断（丢任意语义块）。目标：`subject` → `path` 前缀 → focus 邻域三级优先（与 `slice_graph` 同构）。收益：模型看到"**第 5 章整章**"而非"第 3、7、12 章各两个节点"，I1-3（正面约束）更实。前提：`parent_id` 先落地并有数据（老图谱仍走字符降级）。

### 9.5 跨源统一融合（消除"拼段落"）
改法（复用已有件，不新增抽象）：`各源内部排序 → 取排名 → hybrid_search.fusion.fuse(多源排名, weights) → 统一 top_k → 渲染区块`，即把 `fusion.py` 的 RRF 从"kb 内部双路"推广到"**跨源多路**"。收益：分数可比、排序可调、免去"哪个源排前面"的隐式规则。

## 11. 图谱侧落地记录（原《P0实现方案》图谱侧，2026-10-12 并入）

> P0 的**注入/检索侧**（G1/G2 等）在 `知识图谱_参照系契约.md` 与 `知识图谱_检索与注入_方法与现状.md`；本节只留**图谱数据结构侧**的四项已落地。

| P0 项 | 一句话方案 | 交付物 |
|---|---|---|
| **P0-A 按学科导出恒为空** | 学科归属只认 `kg.node_subject()`（从 tags 推导），并顺手修掉中文文件名导致的 500 | 2 行修复 + 4 例回归测试 |
| **P0-B 掌握度分档前后端不一致** | 阈值收敛为**四档唯一真值** `mastery_bucket()`，1~29 归"薄弱"，仪表盘补齐该档 | 后端四档 + 前端仪表盘四色 + 13 例测试 |
| **P0-C 先修关系无可量化判定** | **多准则无监督投票**推断先修边，每条边带逐准则证据 | 新模块 `core/prerequisite.py` + 1 个 API + 15 例测试 |
| **P0-D 缺外部评测** | 三档口径（基线/新增/合并）离线评测 + **阈值扫描** | `scripts/eval_prerequisite.py` + 标注样本集 + 报告 JSON |

**P0-A（导出）**：`export_knowledge` 用 `n.get("subject") == subject` 过滤，但当时 `nodes` 表无 `subject` 键、学科只能由 `node_subject()` 从 tags 推导 → 任何带 `subject` 的导出恒返空。修复：改用 `kg.node_subject(n) == subject`。**顺带**：修好过滤后回归立刻暴露 `Content-Disposition` 头放中文名抛 `UnicodeEncodeError` → 整条导出链路 500；改用 RFC 5987 `filename*=UTF-8''<percent-encoded>`。**结论**：P0-1 表面"过滤写错"，实际"该功能对中文用户从不可用"。

**P0-B（掌握度四档）**：同一份 `mastery` 三处三套口径（前端 `ForceGraph.masteryLevel` 四档 / 后端 `graph_middleware._bucket` 三档 / `weak_points` 实际只统计 0 分），且后端注释**谎称**与前端四色一致。修复：确立后端唯一真值 `mastery_bucket()`（**0 未学 / 1–29 薄弱 / 30–69 学习中 / ≥70 已掌握**），`_subject_stats` 新增 `weak_count`（四档计数之和 = 节点总数），`weak_points` 改用 `< MASTERY_WEAK(=30)`，前端仪表盘补"薄弱"档。契约固化：`test_mastery_bucket_boundaries` 钉死 0/1/29/30/69/70/100 七个边界。

**P0-C（多准则先修推断，核心）**：现状 LLM 一次性给 `prerequisite` 边 → 不可复现/不可解释/不可量化/易遗漏。参照 Alatrash et al. IJCKG 2025（**arXiv:2509.05393**）**多准则投票**，落地为 **6 条准则 + 固定分母（=11.5）加权投票**，值域 [-1,1]：

| 准则 | 权重 | 投 +1（支持 A→B） | 投 -1（反对） | 弃权条件 |
|---|---|---|---|---|
| C1 正文引用 | 3.5 | 讲 B 的正文引用 A 名 N 次 > 反向 | 反向引用更多 | 双方互不引用 |
| C2 名称包含 | 2.5 | `A.name ⊂ B.name`（"树" ⊂ "二叉树"） | 反向包含 | 名称相同/为空 |
| C5 语义相似 | 2.0 | —（不做正向证据） | 相似度 ≥ 0.90（疑似同一概念） | 嵌入不可用或相似度低 |
| C4 共同前置 | 1.5 | — | 共同前置 ≥2 且无包含关系且 Jaccard ≥ 0.5 | 见踩坑 |
| C3 次序 | 1.0 | A 在教材/入库次序更早 | B 更早 | 次序缺失或相同 |
| C6 难度差 | 1.0 | `difficulty(A) < difficulty(B)` | 反向 | 难度相同 |

打分：`score = Σ(权重ᵢ × 投票ᵢ) / Σ(全部权重)`（分母固定 → 绝对证据强度，只需一个旋钮 `threshold`，默认 **0.30**）。按此：一条强准则（C1=3.5）单挑 → 0.304 成立；C2+C6 → 0.304 成立；仅弱准则（C6+C3）→ 0.174 不成立。**关键设计决策**：① `infer_prerequisites` 为**纯函数**（不碰 DB）；② 权重人为设定（无标注可训练，可解释更重要）；③ C4 从"共享 1 个前置就反对"改为"≥2 个且无包含关系"才反对（旧规则会杀掉正确的传递边 B→C）；④ 单字概念（栈/树/图）正文引用要求 ≥2 次命中；⑤ 结果按分数降序**贪心加边 + 保 DAG**；⑥ 已存在**间接路径**的边直接丢弃；⑦ 单节点入度上限 5；⑧ 次序默认用 `created_at` 近似（权重仅 1.0，允许 `order=` 覆盖）。**接口**：`POST /api/v1/knowledge/prerequisite/infer`（默认 `apply=false` dry-run → 只出候选与逐准则证据；`apply=true` 写 `prerequisite` 边带 `confidence=score`）；**AI 护栏**：AI 不能在"两端都人类创建"的节点间加 prereq 边（`PermissionError` 进 `skipped`，属预期）。**未做**：接入 `graph_generator` 生成链路、MOOCCubeX 实数据评测、前端复核 UI。

**P0-D（离线评测结论）**：三档口径（`baseline` 现有边 vs gold / `added` 本模块新补边 vs 「基线漏掉的那部分 gold」← 核心指标 / `merged` 基线∪新增 vs gold）。实测（内置样本，`--embed mock`，阈值 0.30）：micro-avg 8 条 gold → 基线 P/R/F1 = 0.833/0.625/0.714，**新增 = 1.000/1.000/1.000**，合并 = 0.889/1.000/0.941；**阈值扫描：0.15 以下弱证据涌入（12 条假阳性），0.20–0.40 是稳定平台期（P=R=1.0），0.50 以上全部漏空**，默认 0.30 落平台中部。⚠️ **样本量诚实声明**：8 条 gold 是回归自检与口径固化，**不是统计结论**；外部评测需 MOOCCubeX 实数据（尚未下载，只完成适配格式）。

## 12. 风险与回滚

| 风险 | 说明 | 对策 |
|---|---|---|
| **迁移不可逆** | `ADD COLUMN` 无法优雅回滚 | 动手前备份 `data/knowledge/{knowledge.db,nodes/}`；`ADD COLUMN` **不重写数据** |
| **老数据补不出层级** | `parent_id/path` 对存量图谱为空 | 层级**只对新生成图谱生效**；老节点走原降级路径，不猜 |
| **无向归一化会删边** | M4 会修改/删除存量边 | 先 dry-run 报告，人工确认后 `--apply` |
| **掌握度双写不一致** | 事件写成功但 `nodes.mastery` 没更新 | 两者**同一事务**提交 |
| **`subject` 回填错** | 老数据 tags 已污染 | 回填 = 现状 `node_subject()` 结果（不引入新判断）；错的仍是错的，但**从此可被 SQL 查出并修** |
| **改动面外溢** | 21 个图谱端点 + 前端依赖 `id/name/tags/mastery` | 本次新增列**全部可选**（带默认值）→ 老读路径不感知 |
| **网页存档节点的 subject 语义** | `create_node_from_webpage` 的 tags = `["网页", host]` → KG-D1 后 `node_subject` 会得出"网页"并写进 `subject`（用户 5 无此类节点，未暴露） | 属产品决策，本次不改 |
| **存量 `chunk_index` 未迁移** | KG-D5 只让新索引唯一 | 影响面小；需要时 `index_user_graph` 重建 |
