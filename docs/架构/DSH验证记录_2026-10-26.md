## 2. A 路（MCP）实测

### 2.1 DSH 的命令面

```
Usage: dsh [--profile] <name> [options] [app-args...]
  --from-default-profile <name> | --patch <path>（可重复）| --dump-config | --dump-config-schema
  dsh plugin --profile <name> <pnpm-args...>        # pnpm 透传（add/remove/why）
```
**没有 `mcp` / `doctor` / `console` 子命令** → 诊断只能靠 `--dump-config` 与启动时 stderr。

### 2.2 挂载方式与配置字段（关键）

profile 目录：`$DSH_HOME/profiles/<name>/`
- `cordis.yml` —— 恒为 `[]`（**不要手改**）
- `cordis.patch.yml` —— 用户层，MCP 条目写这里
- `package.json` —— `dsh.profile.bundles: [...]`

`@deepseek-ai/dsh-mcp-client` 的 Config（取自 `lib/types/index.d.ts`）：

```
transport: stdio | streamable-http   # 判别字段
serverName: [A-Za-z0-9_-]{1,32}      # 必填，全局唯一，决定模型侧工具名前缀
command / args / env / cwd           # stdio 用
url / headers                        # streamable-http 用
toolCallTimeoutMs: 60000             # 默认
maxInstructionBytes: 32768
failOnStartupError: false            # 只拒绝该条目激活，不中止 harness
reconnect: { enabled, initialDelayMs:500, maxDelayMs:30000, maxAttempts:10 }
```

补丁条目形态：`- insert: [{ id, name: '@deepseek-ai/dsh-mcp-client', config: {...} }]`，**顶层必须是 YAML 数组**（写注释会解析成 null → 启动失败）。

工具对模型的名字：**`mcp__<serverName>__<rawName>`**（v1 契约，改名会破坏历史与权限）。

### 2.3 握手与成功证据

```
initialize (protocolVersion 2025-11-25) → notifications/initialized → tools/list → 3 tools
```
- DSH 会先 spawn 一个短命"探测进程"发 `server/discover`；**它对 method-not-found 是容忍的**（会看到双 pid，不是泄漏）。
- 反证：把 command 指向不存在路径 → stderr `1 entry did not activate` + `mcp-client(spikes): initial connection or tool synchronization failed: Connection closed`，**harness 照常启动**。
- `serverName` 重复 → `serverName "spike" is already in use by another mcp-client instance`。

### 2.4 启动与卸载

| 指标 | 实测 |
|---|---|
| MCP server spawn → initialize | **1353 ms**（项目 venv）；1090 ms（对照 venv） |
| spawn → 首次 `tools/list` | **1356 ms** |
| 其中 MCP SDK import | **1301 ms**（`import mcp.server.mcpserver`），裸解释器仅 82 ms |
| 宿主退出后子进程残留 | **0**（stdin EOF → 自退出，未用 SIGTERM） |
| 从 profile 移除条目后 boot | server 日志增长 **0 字节**（确认不再 spawn） |

`tools/list` 结构：`{ name, description, inputSchema, outputSchema }`（Python 侧属性为 snake_case：`input_schema` / `output_schema` / `structured_content` / `is_error`）。
`tools/call` 返回：`content[{type:"text"}]` + `structuredContent` + `isError`；超时映射为 `-32001`。

## 3. B 路（dsh-python-bridge）实测

### 3.1 包与装饰器

- PyPI：**`dsh-python-bridge` 0.0.1**，零依赖（README 里写的 `pip install dsh-bridge` 是**错的**，PyPI 404；TS 报错文案里的名字才对）。
- 装饰器（`dsh_bridge/__init__.py`）：
  `@tool(name, description, parameters, output_schema=None, timeout_ms=None)`、
  `@service(name)` + `@provide_method()`、
  `@on(event, mode="emit"|"waterfall"|"session", prepend=False, global_=False)`、
  `capability` / `method` / `system_prompt_section(order, text)` / `guard()` / `restrict_tools(allow, deny)`。

### 3.2 spawn 约定（决定我们 worker 怎么放）

```
<pythonBin|python> -u -m dsh_bridge.runtime <module>
    [--class <cls>] [--function <f>]... [--init-args '<json>'] [--max-threads N]
```
- `cwd = spec.cwd ?? process.cwd()`（**默认不是我们的 backend 目录**）；
- `env = scrubbedParentEnv() + PYTHONUNBUFFERED=1`；给了 `spec.pythonPath` 会**前置拼进 PYTHONPATH**；
- **父环境清洗规则：名字匹配 `/KEY|PASSWORD|SECRET|TOKEN/i` 与所有 `DSH_*` 一律剔除** → 我们的 `DASHSCOPE_API_KEY`/PAT **不能指望继承**，必须显式 `env` 或 `--init-args`；
- spawn 前探测 `python -c "import dsh_bridge"`，失败 → `-32012`；
- stdout 由 runtime 接管（用户 `print()` 变成 `bridge/log` 通知，`logging` 同样被接走）。

### 3.3 握手与性能

```
initialize {cwd, clientInfo} → {serverInfo, manifest}
spawn → initialize: 225 ms（service 用例 238 ms）；echo RTT 1 ms
manifest 字段：services / provideMethods / tools / listeners / capabilities / capabilityMethods / promptSections / methods
```
误差映射：`ValueError→-32004`、`TimeoutError→-32001`、`CancelledError→-32002`、`PermissionError→-32003`、`KeyError/AttributeError→-32005`、其他 `-32603`。同步函数在线程池执行（`--max-threads`）。

### 3.4 partial 的真实缺口

| 缺什么 | 影响 |
|---|---|
| `@peroxider/dsh-python-bridge-codegen@0.0.3` 未跑（需要 DSH monorepo 的 peer deps：`@deepseek-ai/cordis`、`dsh-invariants`、`dsh-tools`、`schemastery`） | **模型可见的 TS schema 由 codegen 产物提供，bridge 只给 manifest** → 不跑 codegen，工具大概率不会出现在模型侧 |
| npm runtime `0.0.3` vs PyPI `0.0.1` | 握手只比 major（0==0），实测通过；但版本偏斜是长期风险 |

### 6.1 本机装的是哪一套

| 项 | 实测 |

| 可调用 CLI | `~/.dsh/profiles/node_modules/@deepseek-ai/dsh/lib/bin.js` = **0.1.5-rc.2**（源码在 `C:/Users/34239/Documents/GitHub/deepseek-harness`） |

### 6.2 两条硬规则（踩过才知道）

1. **`dsh.profile.bundles` 只能列声明了 `dsh.bundle` 的包**。把 `@deepseek-ai/dsh-mcp-client` 写进 bundles 会直接启动失败：
   `Error: dsh: profile bundle "@deepseek-ai/dsh-mcp-client" declares no dsh.bundle in its package.json`
   —— 它是**插件**，只能出现在 `cordis.patch.yml` 的 `insert` 里。
2. **只有 `dsh-base` 不会启动插件树**：patch 合并进去了（`--dump-config` 可见），但 harness 空闲、不 spawn 任何东西。加一个 app bundle（实测 `@deepseek-ai/dsh-acp-app`）后立刻生效。

### 6.3 联调结果（证据）

```
dsh_pid=36712 exited=False
kg_tools_children=2        # 1 个探测进程 + 1 个正式进程（与 P0 观察一致）
residual_after_kill=0      # 杀宿主后无残留
--- dsh stderr ---
ai_tutor.mcp.kg_tools | 只读网关启动：transport=stdio tools=rag_search,search_resources,fetch_webpage
ai_tutor.mcp.kg_tools | tools/list -> 3 个工具: rag_search,search_resources,fetch_webpage
```

配置（与 0.2.1 字段完全一致，可直接复用到 npm 包）：

```yaml
- insert:
    - id: ai-tutor-kg
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        transport: stdio
        serverName: ai-tutor          # 模型侧工具名 = mcp__ai-tutor__<tool>
        command: '<repo>/backend/venv/Scripts/python.exe'
        args: ['-m', 'app.mcp_servers.kg_tools']
        cwd: '<repo>/backend'         # 不传就会用 DSH 进程目录 → import 失败
        env: { AI_TUTOR_TOKEN: '<JWT>' }   # 父环境会被清洗，token 必须显式传
        toolCallTimeoutMs: 90000
        failOnStartupError: true
```
