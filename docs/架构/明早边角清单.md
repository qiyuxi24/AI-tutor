## 2. 🔶 B3-1：两套排序**要不要真合并**（这是未决问题，需要人拍）

**现状（今晚的结论）**：只统一了"**同层口径**"，**没有**合并两个算法。

- 同层口径唯一实现 = `backend/app/core/graph_order.py::order_key`（前置未达标排后 → 掌握度升序 → id）
  - 消费方：`knowledge_graph.topological_sort()`（Kahn 可学集合用最小堆）、`graph_middleware.path_board().recommended`
- 两个算法**各自保留**：

| | `knowledge_graph.topological_sort()` | `graph_middleware._layers()` / `_break_cycles()` |
|---|---|---|
| 输入 | 全量 prerequisite 边 | **切片内**（subject / board）prerequisite 边 |
| 输出 | **全序**：所有知识点的学习顺序 | **层号**：每个节点第几层（0 = 第 1 层） |
| 破环 | 排不进的节点按 `all_ids` 顺序追加到末尾 | DFS 丢 back-edge（GRAY 回边），再按**最长**前置链算层号 |
| 附带语义 | 无 | `_lift_related_only_levels`：只有 related/confusion 边的节点并入相关节点同层 |

**为什么没硬合**（作业单 P1-6 的警示条件全部命中）：
1. **输出形态不同**：一个要全序（`get_learning_path` 的 `ordered_nodes` + `current_recommendation`），
   一个要**逐节点层号**（`path_board.items[].level`、前端分层看板、`recommended` 的层前缀）——
   任一方向合并都会让另一方的返回值变形。
2. **破环策略不同**：`topological_sort` 是"环上节点扔到末尾"；`_layers` 是"丢回边 + 最长链分层"。
   改哪一边都会改变**环图**（数据有问题时）的展示结果，而环图正是最需要稳定行为的时候。
3. **附带语义只属于看板**：`_lift_related_only_levels` 是**展示**概念（"相关概念摆在一起"），
   不是学习顺序 —— 塞进 `topological_sort` 会把"概念相邻"误读成"学习先后"。

**若要真合，必须先回答这 3 个问题（人来定，别自己拍）**：
1. `path_board` 还需要 `level` 吗？（若前端改为"只要全序 + 相邻分组"，才有合并空间）
2. 环图里"环上节点"期望是**分层**还是**扔末尾**？（涉及真实脏数据的展示口径）
3. "相关概念并入同层"是否也要进学习路径？（语义上它是展示，不是顺序）

**落点（若决定合）**：`core/graph_order.py` 扩成 `learning_order(kg, *, weighted=True, layered=False)`，
两侧只调用它；`graph_middleware._break_cycles/_layers` 删除。

**禁止事项**：
- ⛔ 在没回答上面 3 个问题前改 `_break_cycles` / `_layers`。
- ⛔ 为"看起来更整齐"而让 `path_board.items` 改按掌握度排 —— 那段注释明确说卡片位置必须稳定
  （学会一个就乱跳，用户找不到东西）；掌握度只影响 `recommended`。
