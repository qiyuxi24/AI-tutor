## 五、没做完 / 卡住的（含原因与建议）

### 5.1 ⚠️ P1-6 的"两套排序合并"**没有硬合**，这是按作业单警示做的决定

作业单原话：*"若合并过程中发现两套排序的语义差异超出预期（例如破环策略不同），立即回滚并只记录 —— 别硬合。"*
**三条差异全部命中**：

| | `knowledge_graph.topological_sort()` | `graph_middleware._layers()` / `_break_cycles()` |
|---|---|---|
| 输入 | 全量 prerequisite 边 | **切片内**（subject/board）边 |
| 输出 | **全序**（所有知识点的学习顺序） | **逐节点层号**（看板分层） |
| 破环 | 环上节点按 id 追加末尾 | DFS 丢 back-edge + **最长**前置链分层 |
| 附带 | 无 | `_lift_related_only_levels`（相关概念并入同层，**展示**语义） |

合并任一方都会让另一方的返回值变形（`path_board.items[].level` 或 `ordered_nodes` 的全序），
且会改变**环图**（脏数据时）的展示行为。**已做的是能安全做的那一半**：

- ✅ "同一层里谁先学"收敛为**单一实现** `core/graph_order.order_key`（前置未达标排后 → 掌握度升序 → id），
  `topological_sort` 与 `path_board.recommended` 都调它 —— 这是 B3-1 真正要的"掌握度进入排序"；
- ✅ `topological_sort` 从 FIFO 改为**掌握度优先**（旧实现下"下一步"只看数据库行序，等于随机）；
- ❌ 两个算法本身**保留**，未合并。

**建议**：真要合并，先回答 `明早边角清单.md` §2 的 3 个问题（看板还需不需要 `level`、环上节点要分层还是扔末尾、
"相关概念并入同层"要不要进学习路径）。这 3 条是产品决定，不是代码决定。
