## 三、能演示的功能（怎么演 → 看什么现象）

> 前置：`.\start.ps1` 起服务（主前端 5173 / 主后端 8000 / 运维前端 5174 / 运维后端 8001），
> 设置页配好一个可用的对话模型 Key（不配则回落根 `.env` 的 `LLM_API_KEY`）。详细步骤见 [演示操作卡.md](演示操作卡.md)。

| # | 功能 | 怎么演 | 看什么现象（可截图/可讲解的点） |
|---|---|---|---|
| 1 | **对话 = Agent Loop** | 对话页发一句"我想学二重积分，从零讲起" | 思考气泡 → 工具调用过程（建节点/检索）→ 正文**逐 token** 流出；结束后知识图谱侧栏多出节点 |
| 2 | **知识图谱可视化** | 左侧活动栏 →「知识图谱」 | D3 力导向图；节点按掌握度**四色**着色 + 图例；搜索框输入关键词→聚焦；点节点→右侧详情 |
| 3 | **学习路径（拓扑排序）** | 图谱页 → 路径面板 | Kahn 拓扑排序出的先修顺序；高亮当前学习位置 |
| 4 | **学习进度仪表盘** | 活动栏 →「学习进度」 | 掌握/学习中/未学统计、平均掌握度、薄弱点列表、学科进度——**这些数字来自图谱与判分，不是写死的** |
| 5 | **按小节教学（B1 学习会话）** | 图谱/路径上点节点 →「去学习」 | 开场轮**只报菜单**（三小节清单 + 状态），**不会**一上来就调工具（`no_tools` 硬保证）；接着说"开始讲第一节"→ 只讲一节就停 |
| 6 | **先问再出题 + 判分闭环** | 对话里说"好，出题吧" | ~40 秒后题卡推到前端（单选/多选/判断/填空）；作答 → **判分结论单独成行**（答对/答错 + 得分）→ 该小节变"已通过" → 掌握度上仪表盘 |
| 7 | **文件知识库 + 混合检索** | 对话页右侧知识库面板上传一份 PDF → 问关于它的问题 | 解析→分块→向量+BM25 索引；回答里带**来源引用**（文件名/路径）；原件可点开预览 |
| 8 | **运行记录与证据回放** | 运维后台（5174，`admin/admin123`） | 每次对话的 `run_id`、思考全文、每个工具的参数与返回、最终回答——**评委问"凭什么说它调了工具"就给他看这个** |
| 9 | **每用户自配模型 + 回退链** | 设置页 →「模型」填 Key/地址；模型下拉 | Key **明文只在服务端**；主模型异常时静默降级到备用，教学对话不中断 |
| 10 | **用户隔离** | 注册两个账号各建一个知识点 | 互相看不到对方的图谱/画像/知识库/题库（全按 `user_id` 分区） |
| 11 | **离线测试全绿** | 项目根跑第二节的两条命令 | 现场 90 秒出 `1566 passed`、24 秒出 `41 passed`——**这是最容易演、最有说服力的"工程质量"证据** |

## 四、只能写不能演（含原因与材料写法）

| 功能 | 为什么演不了 | 材料里怎么写（建议原话） |
|---|---|---|
| **教材 → 整本图谱生成** | 一次要跑分钟~十几分钟的批量 LLM 抽取；录屏里等不起，且吃额度 | "支持从教材 PDF 自动生成知识图谱（后台批量任务，单本分钟级）"——**不要**拍现场生成，可拍**已有产物**的图谱页 |
| **联网搜索 / 网页抓取（MCP）** | 依赖外部网络与 MCP 服务进程；网络抖动就翻车 | "集成 MCP 网页搜索与抓取工具（需外部服务可用）"；演示时用**已入库**的资料代替 |
| **资源采集（Wikipedia/Wikibooks 断点续传）** | 需要外网 + 长时间；版权双模式还要人工核对 | "内置采集模块，支持断点续传与版权双模式"——陈述即可，别现场跑 |
| **扫描版 PDF 的 OCR** | RapidOCR 逐页识别是**分钟级**，且原件不设上限、原样占盘 | "扫描版 PDF 走 OCR 管线（逐页识别，分钟级）"；演示请用**电子版** PDF/Word |
| **模型回退链的真实触发** | 要真的把主模型额度打爆或写错 Key 才看得到 | 可以说"实现了主→备自动降级"，**不要**演"看它降级"（不可控） |
| **真实 API 测试（`-m llm_api`）** | 真实付费 Key、慢、易 flaky；今晚未跑 | 若材料要提，写"另有一套真实 API 集成测试（需付费 Key，按需跑）"，并注明**未纳入本次数字** |
| **前端单元测试** | 沙箱禁 Node 子进程管道（`spawn EPERM`），今晚无法验证 | 只字不提，或写"前端测试待补"（诚实反而加分） |
| **线上部署 / Docker** | 今晚明确不跑 `docker build`；容器化是**代码与配置已就绪**，不是"已验证" | "提供 Docker Compose 单容器部署方案与 Nginx SSE 反代配置"——用"提供方案"，不用"已上线验证" |

## 五、材料里禁止出现的说法（无取证，问了就崩）

1. ⛔ **并发用户数**（"支持 1000 用户同时在线"）—— 架构上 uvicorn 强制 `--workers 1`，今晚没做过任何压测。
2. ⛔ **准确率/召回率等评测分数** —— 除非能同时给出**报告文件名 + 日期 + 复跑脚本**（如 `docs/RAG/RAG_图谱混合检索与真实嵌入评测_报告.md`）。引用时要连"数据集与口径"一起说，否则不要引。
3. ⛔ **"全链路自动化测试通过 / CI 绿"** —— 今晚跑的是**离线**后端套件；没有 CI 记录。
4. ⛔ **文件数/代码量按依赖目录统计**（见第二节）。
5. ⛔ **"已部署上线 / 有真实用户"** —— 没有这回事。
