## 2. 发现的问题（按严重度）

### 2.1 🔴 P0-1：**学习会话的 AI 回复没有落库**（刷新后整段变空白）
**现象**：学习会话里 AI 的回复，落库为空；刷新页面后整段消失（只剩一个空头像气泡）。

**库证据**（`data/conversations/conversations.db`）：
```
学习会话 'mv1wg3lweg1lzw'（user 10004）:
  [0] user      "开始学习「二重积分的计算」"
  [1] assistant {"role":"assistant","content":"","tools":[],"thinking":[]}   ← 65 字节，全空
  [2] user      "开始讲第一节"
  [3] assistant {"role":"assistant","content":"","tools":[],"thinking":[]}   ← 全空

对照（同账号普通对话 'mv1vxqxupd57wr'）:
  assistant content 长度 = 140，thinking JSON 长度 = 206   ← 正常
对照（历史账号 uid=5 / uid=11 的旧会话）:
  assistant content 长度 = [246,31,373,442,200,207,383] 等   ← 正常
```
**结论**：**普通对话正常落库，学习会话的助手消息落库为空** —— 不是"历史遗留"，是**学习链路特有**。

**影响**：演示时**一旦 F5 刷新 / 切走再回来 / 换设备**，学习会话的 AI 内容全变空白（现场表现为"AI 没说话"）；**演示卡要求的"证据回放"在学习会话上也不成立**。

**性质（前端侧）**：会话是**前端全量同步**落库的（`POST /api/v1/conversations/sync` → `conversation_store.sync_from_client` → `save_conversation` 整份 upsert）。即：**前端保存的学习会话消息对象里 `content` 本来就是空串**。根因待查（学习链路的 assistant 消息对象构造/回写）。

**复现**：登录 → 图谱双击节点 → 去学习（等到开场）→ F5 → 学习会话正文全空。

### 2.2 🟠 P0-2：刷新后**学习模式上下文丢失**（模型退回普通对话）
**证据**（`agent_runs.db` 里模型的 thinking 原文，第二轮）：
> "…I notice there's **no explicit 【学习模式】 marker, and no sections listed**. So this is a **regular conversation mode**, not sectioned learning mode."

即：刷新页面后**回到**学习会话再发言，`current_node` 没有恢复 → `_build_learn_block` 返回空 → 模型不再按小节教学。
**影响**：演示中只要刷新过，后续"讲第 N 节/出题"的行为就退化成普通聊天。

### 2.3 🟠 P0-3：刷新后**历史对话列表为空**
刷新后左侧显示「暂无历史对话」，但库里该用户确有 2 条会话（`data/conversations/conversations.db` 可查）。
**影响**：刷新后找不到刚才的会话，等于"对话丢了"。
（`chatStore` 只在"localStorage 为空"时 `loadFromBackend()`；怀疑 localStorage 里存了一份退化列表 → 跳过回源。待查。）

### 2.4 🟡 P0-4：「AI 思考中…」指示器不消失
每轮 `loop_stop` 已是 `natural`（后端明确结束），但前端仍挂着「AI 思考中…」占位（`shot-19-teach1b.png` 可见）。
**影响**：与演示卡"没有『AI 思考中…』卡死"的判据混淆 —— 内容其实已经出来，只是指示器没收。

### 2.5 🟠 P0-5：**没有文档化的演示账号**
- 环境里**有数据**的账号是测试账号：`admin`(uid 5，122 节点/249 边/有 KB 与题库)、`testuser999`(uid 1，24 节点)、`朱子轩`(uid 10002) 等；**都没有公开口令**。
- 仓库与 `.codebuddy/memory` 里**搜不到任何演示账号口径**（`MEMORY.md` 只记运维后台 `admin/admin123`，且明确写过"零演示数据"是待办）。
- **结论：演示卡 §0 要求的"演示账号里已有图谱/资料/题库数据"目前无凭据可用** → 现场要么人工用已知口令的账号，要么临时建。
- 本次为验证，新建了一个账号 `demo_check_1010 / Demo123456`（uid 10004）并播了一个 3 小节节点（见 §4 清理）。

### 2.6 🟡 P0-6：仪表盘空态文案
0 个知识点时「下一步学什么」显示"**所有知识点已掌握，太棒了！**"。语义别扭（空 ≠ 已掌握），演示时若账号无数据会显得突兀。

### 2.7 🟡 P0-7：环境稳定性（对录屏有间接风险）

- `playwright-cli`（Edge 内核）守护进程在 Windows 上崩过一次（libuv `Assertion failed`）—— **属测试工具问题，与产品无关**。

## 5. 修复轮（2026-10-10 下午）

> 流程：只读调查子 agent 定位根因 → 开发子 agent 实施 → 主会话**独立复核代码 + 自己跑验证 + 浏览器端到端复验**。
> 改动**仅前端**：`frontend/src/stores/chatStore.js` 与其单测 `chatStore.lifecycle.test.js`。**未改后端**。

| 现象 | 根因 | 修复 | 验证（证据） |
|---|---|---|---|
| **P0-1 学习会话 AI 正文不落库** | 正文只在 `onDone`（`[DONE]` 帧）才 `persist()`；后端 `[DONE]` 却在 `await _analyze_and_apply(...)`（图谱分析 + 索引，可达数十秒）**之后**才发 → 用户在窗口内刷新，正文永远停在 65 字节占位对象 | ① 流式**节流落盘** `throttledPersist()`（≥1500ms，首写立即）② 接上后端**早已发出**的 `agent_done` 事件（`onAgentDone`）即时 `persist()` + 收口 `loading`，`streamSeq` 护栏防旧流迟到事件 | ✅ 新学习会话 assistant `content` 已进 localStorage（含**流式节流的中途快照**——thinking 被截断可证）与 `conversations.db`；**刷新后正文完整显示**（`shot-21/22`） |

| **P0-2 刷新后学习模式上下文丢失** | `currentNode` 是**全局 ref，从不持久化、也不从对话绑定反推**；`switchConversation` 不更新它（`conv.nodeId` 只活在内存 / localStorage） | `send()` 以 `conv.nodeId` 为准；`switchConversation`/`init` 回填 `currentNode`；`newConversation` 清空 | ✅ 刷新后再发言，后端日志出现 **`学习模式/后续轮　知识点=demo_erchongjifen`**（15:52:40） |
| **P0-3 刷新后历史列表为空** | ⚠️ **原判断需修正**：真正触发是**后端不可用 / token 过期**时 `init()` 卡在 `await ensureSession()`，`init()` 没跑完 → 侧栏与主区**静默空白**（不是 localStorage 判定错）。但原怀疑的 3 处仍是真缺陷：`startLearning` 提前 `persist()` 把对话键写成 `[]`、`persist()` 写 `''` 而非删键、`adoptRemote` 只认 camelCase 读不到后端 snake_case 的 `updated_at` | 三处全修（`removeItem` / 删提前 persist / `?? r.updated_at`）；`init()` 改**分步容错**（解析失败不再吞掉后续） | ✅ 后端健康时刷新：侧栏 **3 条会话齐全 + 当前会话正文完整**（`shot-22`）。**残留**见 §6 |
