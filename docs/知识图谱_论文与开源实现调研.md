## 0. 结论速览

**业界把知识图谱用出了三条互不相同的路线，本项目走的是第二条 —— 而且是少数派。**

| 路线 | 图是什么 | 代表 | 图的来源 | 每轮对话 |
|---|---|---|---|---|
| **A 检索索引** | 图是**索引** | Microsoft GraphRAG / LightRAG / HippoRAG | **从文本自动抽取** | 命中才用 |
| **B 教学参照系** | 图是**教学可行域与坐标系** | **本项目**；MDPI 智能导学(2025) | **人工建/AI 辅建/教材生成** | **每次注入**（契约要求） |
| **C Agent 记忆** | 图是**长期记忆** | Zep/Graphiti / Mem0 / MemGPT | 从交互中累积 | 按需召回 |

三条路线**不冲突、可叠加**，但工程重心完全不同。关键判断：

- 路线 A 的成熟开源件（GraphRAG 家族）**不能直接搬** —— 它们的图是从文本抽的、为检索服务的；
  我们的图是教学结构、为先修顺序服务的。**唯一真正可复用的是"图遍历扩展上下文"这一手法**（见 §5）。
- 路线 B 在学术上**不是异类**：ChatGPT 的记忆策略就是"始终注入"，与 Claude 的"按需检索"正相反【二手】。
  本项目"参照系每次都在"的选择有业界佐证，可作答辩论据。
- 本项目**曾最大能力缺口 = 先修关系的自动推断与评测**。学术界这条线已经很成熟
  （无监督多准则 / 双图蒸馏 / 有带人工标注的公开数据集），我们此前靠 LLM 一次性生成，**无量化指标**。
  **进展（2026-09-12）**：多准则推断 + 离线评测已落地（见 §5 P0 与 `知识图谱_P0实现方案与核心思路.md`），
  余下缺口是"接入生成链路"与"用 MOOCCubeX 实数据评测"两项。
- 本项目**已规避业界最大的成本坑**：GraphRAG 系的"社区摘要"需要海量 LLM 调用，而我们不对图做 LLM 摘要，
  图本身就是最终产物。这是"图不来自文本"带来的架构红利。

## 1. 三条路线的技术分野（先看懂这个，再谈借鉴）

### 1.1 路线 A：图作为检索索引（GraphRAG 家族）

**核心命题**：向量检索解决不了"全局性问题"（"这批文档整体在讲什么"）与"多跳关联"，于是用 LLM 把文本抽成图，
再在图上做检索。

**Microsoft GraphRAG 的两阶段**（arXiv 2404.16130，2024-04）【已核实摘要】：
1. LLM 从源文档抽取**实体知识图**（实体 + 关系 + 声明）；
2. 对图做**社区检测**并**预生成社区摘要**（community report）；
3. 查询时按 Local（实体邻域）/ Global（社区摘要 Map-Reduce）/ DRIFT 三种模式取用。

**它的代价**（业界共识，本次搜索多篇对比文印证【二手】）：索引阶段 LLM 调用量与 token 消耗极高、构建慢、
**增量更新不友好**（新文档进来要重算社区）。这正是 LightRAG（HKUDS）出现的理由 —— 用**双层关键词检索**
（低层=实体、高层=主题）+ **增量插入**，把成本降下来。

**这条路线与我们的关键差异**：它的图是**手段**（为了更好的检索），我们的图是**目的**（要教什么、教到哪）。
所以它的社区摘要、Leiden 聚类这些核心组件，对我们**没有意义** —— 我们不需要"概括一批文档"。

### 1.2 路线 B：图作为教学参照系（本项目）

与本项目最接近的学术工作是 **MDPI *Education Sciences* (2025-08) "Synergizing Knowledge Graphs and LLMs:
An Intelligent Tutoring System"**（提出 KG + LLM 的智能导学模型）【已核实标题】。
另有 **TKDE 2025 "A Framework of Knowledge Graph-Enhanced Large Language Model"**（强调 KGO 的全局规划）【已核实标题】。

**本项目在此路线上的独特点**（也是要写进参赛材料的差异点）：
- 不只把图当上下文，而是明确规定**调用前定界+定标、调用后写回**的闭环（见参照系契约）；
- 有**用户级图谱隔离**（每人一张图，`KnowledgeGraph(user_id)`），而非全库共享一张图；
- 图**既消费又被生产**（对话中发现新知识点会写回图）。

> ⚠️ 注意：参照系契约已列明 **G1(P0 注入体量)/G4(负面→正面约束)** 等缺口。
> 材料中**在满足 AC-L1-3、AC-L2-1 之前不得宣称"参照系"**（红线条款），只能写"全量框架约束"。

### 1.3 路线 C：图作为 Agent 记忆

- **Zep / Graphiti**（getzep，开源）：**时序知识图谱**作为 Agent 记忆层，论文称在 Deep Memory Retrieval
  基准上超过 MemGPT【已核实标题与结论表述】。特点：带**时间维度**（事实何时成立/失效）、支持动态增量。
- **Mem0**（arXiv 2504.19413）：LLM 驱动的记忆 CRUD（提取事实、矛盾时让模型裁决）【二手】。
- **MemGPT / Letta**：分层记忆 + 分页调度的经典范式【常识】。

**与本项目的潜在结合点**：我们的**掌握度变化本身就是时序事实**（"9-10 掌握度 20 → 9-12 掌握度 65"）。
当前 `mastery` 是**单值覆盖**，历史不可追溯。若将来要支持"学习轨迹复盘/成长报告"，
Graphiti 式的双时间轴（valid_from / valid_to）是成熟参考。**但当前不必要**（见 §5 P2）。

**一个值得注意的业界事实**：本次调研见到的 LLM 记忆系统横评提到，
**Claude Code / Codex / Gemini CLI 等 Agent 工具的记忆方案"比想象中简单"——没有 RAG、没有知识图谱，就是滑动窗口**；
而 ChatGPT 与 Claude 的记忆哲学正好相反（一个始终注入、一个按需检索）【二手】。
**含义**：图谱不是记忆的必需品；用不用图取决于"是否需要结构化约束与可审计"，而这恰是教育场景的刚需。

## 2. 论文脉络（四条线，按与本项目的相关度排序）

### 2.1 教育知识图谱与先修关系（**与本项目最相关**）

先修关系（prerequisite relation, PR）是 EduKG 的灵魂 —— 它定义"概念应被学习的逻辑顺序"。
**这正好就是本项目 edges 表里 `relation='prerequisite'` 那条边所承担的角色**。

| 论文 | 年份/出处 | 要点 | 对本项目的意义 |
|---|---|---|---|
| **Inferring Prerequisite Knowledge Concepts in Educational Knowledge Graphs: A Multi-criteria Approach**<br>Alatrash, Chatti, Wibowo, Ain | 2025-09, **IJCKG 2025**<br>arXiv:2509.05393 | **无监督**推断（不依赖标注数据）；基于 **文档特征 / Wikipedia 超链接特征 / 图特征 / 文本特征** 定义 **10 项准则**，用**投票算法**融合；在 MOOC 平台 CourseMapper 上验证，**精确率优于既有方法** | ⭐ **最可直接借鉴**。我们要的先修边正是它解决的问题，且它**无监督**（我们也没有标注数据）。10 准则+投票的融合思路可直接用于 `graph_generator` 的语义去重之后加一层关系判定 |【已核实摘要】
| **DGCPL: Dual Graph Distillation for Concept Prerequisite Relation** | 2025, **IJCAI** | 用双图蒸馏学习概念先修关系 | 有监督路线代表；需标注数据，本项目暂不具备 |【已核实标题】|
| **MOOCCubeX**<br>THU-KEG（清华知识工程组）× 学堂在线 | 2021, **CIKM** resource track | 4,216 课程 / 637,572 概念 / 2.96 亿行为 / 333 万学生；**含先修关系（数学、心理学、计算机三科，含预测值与人工标注）**；配套独立仓库：概念抽取管线、先修发现（co-training） | ⭐ **可用的评测数据集**。给 AIC 赛道的"量化报告"提供了**外部可比的评测集**（否则我们的先修准确率只能自证） |【已核实】|
| **ACE: AI-Assisted Construction of Educational Knowledge Graphs** | 2024, *JEDM* | AI 辅助构建 EKG 的方法论 | 构建流程参考 |【已核实标题】|
| **Research on the Construction and Reasoning of Educational Knowledge Graph Based on Pre-trained Language Model** | 2026, Springer | 预训练语言模型驱动的 EduKG 构建与推理框架 | 构建+推理一体化的思路参考 |【已核实标题】|
| **基础教育知识图谱标准** | 2025-06, CELTSC（全国信息技术标准化技术委员会教育分委员会） | 规定基础教育知识图谱的技术框架、数据要求、本体 | ⚠️ **值得查证**：若报名材料涉及"符合标准"，需核对本体定义是否与我们的 subject/board/tags 结构冲突 |【已核实标题与发布机构】|

**结论**：先修关系**不是我们独有的难题**，而是一个有专门会议（IJCKG）、专门竞赛数据集、专门方法体系的研究方向。
**这既是风险（别人有成熟方法）也是机会（我们可以站在成熟方法上做量化，而不是自造轮子）**。

### 2.2 知识追踪（KT）：我们的"掌握度"的学术对应物

本项目用**单值 `mastery` 0–100 + 分档**表示掌握度。学术界叫 **Knowledge Tracing**，已是深度学习主战场。

| 论文/工具 | 年份/出处 | 要点 | 对本项目的意义 |
|---|---|---|---|
| **DKT（Deep Knowledge Tracing）** | 2015, NeurIPS | 首个用 RNN 建模学生知识状态的 DLKT 模型 | KT 领域起点；**需要大量交互序列**（学生-题目-对错），本项目**不具备该数据条件** |【常识】|
| **pyKT: A Python Library to Benchmark Deep Learning based Knowledge Tracing Models** | 持续维护，`pykt-team/pykt-toolkit` | 统一 **30+ 个 KT 模型**（DKT/DKVMN/SAKT/AKT…）× **7 个主流教育数据集**的基准库 | ⭐ **价值在"评测方法论"而非模型本身**；可直接借它的数据集划分与指标口径来做我们掌握度预测的对照 |【已核实存在与规模描述】|
| **A survey of deep learning based knowledge tracing** | 2026-01, *Neurocomputing* | 系统综述 DLKT 近期代表性方法 | 综述入口 |【已核实标题】|
| **DKT2: Revisiting Applicable and Comprehensive Knowledge Tracing** | 2025-01, arXiv:2501.14256 | 重新审视 DKT 的适用性与全面性（含对 DKT 原始设计的修正） | 说明"老模型仍有价值" |【已核实标题与摘要片段】|
| **Next Token Knowledge Tracing (NTKT)** | 2025-11, arXiv:2511.02599 | 把 KT 重构为**下一个 token 预测**，利用预训练 LLM；与 DKT/AKT/AKT-text 等基线对比 | ⭐ 与我们技术栈最契合的 KT 路线：**不用训练专用模型，用 LLM 做 KT** |【已核实标题与实验描述】|

**对本项目的明确判断**：
- ❌ **不宜直接引入 DKT/AKT** —— 它们吃"学生×题目×对错"的长序列，我们是冷启动单用户、无题海交互。
- ✅ **可借鉴的是评测口径**（AUC / ACC 怎么算、怎么切数据）与 **NTKT 的思路**（用 LLM 做掌握度推断，
  我们其实已经在用 LLM 打 mastery 分数了）。

### 2.3 学习路径推荐

| 论文 | 年份/出处 | 要点 | 对本项目的意义 |
|---|---|---|---|
| **Personalized Learning Path Recommendation Based on Knowledge Graphs** | 2026-01, MDPI *Electronics* | 强调路径的**透明性、自适应、个性化** | 与我们的 `learning_path`（Kahn 拓扑）直接对标 |
| **Personalized Learning Path Recommendation using Graph Reinforcement Learning** | 2025, *Procedia CS* | 基于学习者当前知识状态 + 图强化学习推荐路径 | 更高级方案（需交互数据）；我们当前是**规则式拓扑排序 + mastery 优先** |【已核实标题】|
| **Learning Path Recommendation Based on Knowledge Tracing** | 2023, IEEE | KT 与路径推荐结合 | 说明"先修图 + 掌握度"是标准范式 |【已核实标题】|
| **Big Data-Driven Personalized Learning Path Recommendation via Knowledge Graph** | 2026, ACM | 图谱 + 多源教育数据融合 | 多源融合参考 |【已核实标题】|

**结论**：本项目"**拓扑序 + mastery<50 优先**"的路径算法，**属于该领域的基线做法**（简单但正确）。
学术界的前沿是"图强化学习"与"KT 驱动"，但都**依赖交互数据**。
→ 材料表述建议：**不要声称路径推荐有算法创新**，而应声称"路径由先修图与掌握度共同决定，可解释、可审计"
（这恰是 MDPI 2026 强调的**透明性**，反而是我们的强项）。

### 2.5 KG 表示学习与推理（**了解即可，当前不采纳**）

| 工作 | 年份 | 要点 |
|---|---|---|
| **TransE** | 2013, NeurIPS | `h + r ≈ t`，KGE 开山之作；1-N/N-1 关系建模有缺陷【常识】 |
| **RotatE** | 2019, ICLR<br>arXiv:1902.10197 | 复空间旋转建模，可表达对称/反对称/逆/复合关系【已核实】 |
| **R-GCN / CompGCN** 等 GNN 系列 | 2017–2020 | 图神经网络做 KG 推理【常识】 |
| **C-KGE: Curriculum Learning-based Knowledge Graph Embedding** | 2025, *Computer Speech & Language* | 用课程学习（由易到难）改进 KGE 训练 |【已核实标题】|

**为什么当前不采纳**：KGE 的价值在**链接预测**（补全缺失边）与**关系推理**。
本项目图谱规模小（单用户、几十到几百节点）、边主要由教学逻辑确定，
用 embedding 补边会引入**不可解释的边** —— 与"可审计"目标冲突。
→ 若未来规模上来要做"缺失先修边推荐"，再考虑；**当前用 §2.1 的多准则规则法更合适**（可解释）。

### 3.2 KG 存储与查询

| 项目 | 说明 | 对本项目 |
|---|---|---|
| **Neo4j**（+ GDS / APOC） | 主流原生图数据库，Cypher 查询、图算法库 | ⚠️ **当前不该引入**：我们的图规模（单用户百级节点）+ SQLite 已足够，且 Docker 单容器约束下多一个服务是负担 |
| **NebulaGraph / Apache Jena / RDFLib** | 分布式图库 / RDF 三元组栈 | ❌ 体量与场景不匹配 |

**判断**：本项目**用 SQLite 存邻接表**是合理选择 —— 同类开源项目 **AI_Tutor(098765d) 甚至用 Excel 存三元组**（见 §3.5），
说明"图谱"的工程门槛不在存储层。→ 材料中**不要**把"用了图数据库"当亮点（我们没用），
应把"**用户级图谱隔离 + 两级切片**"当亮点（这是很多人没做的）。

### 3.5 同类 AI Tutor 开源项目（新增对标）

**AI_Tutor（GitHub `098765d/AI_Tutor`，KG-RAG AI TUTOR）**【已核实仓库与 README】
- 配套论文：*How to build an adaptive AI tutor for any course using KG-RAG*（ICEIT 2025）
- 架构：**双路检索** = 向量相似度检索（课程文本块） + **知识图谱遍历**（`kg_hop_depth` 控制跳数）→ 融合喂给 DeepSeek-V3
- 图谱构建：课程 PDF 按 ~1000 tokens 分块 → LLM 抽 `[实体, 关系, 实体]` 三元组 → **存到 `data/knowledge_graph.xlsx`**
- 另有"聊天历史复用"（MiniLM 相似度 ≥0.85 时复用历史回答）
- 规模：约 61 stars，Streamlit 单机应用

**它给我们的三点启示**：
1. **同类学术论文的做法比我们简单得多**（Excel 存图、无用户隔离、无切片）→ 我们的工程化程度（SQLite + 用户隔离 + 两级切片 + SSE 实时刷新）**是相对优势**，材料里应体现；
2. **"图谱遍历扩展上下文"是这类系统的标配手法**（`kg_hop_depth`），我们的 `rag_search(source=graph)` 是**节点级检索**，
   没有"沿先修边扩跳"的能力 → **这是一个具体、低成本的改进点**（见 §5 P1）；
3. 它同时提供"KG-RAG / 纯 RAG"**模式切换对比**来证明图谱的增益 → ⭐ **这是很好的评测设计**，
   我们可以照做（图谱开/关 A-B 对照），直接产出 AIC 赛道要的量化证据。

## 4. 本项目在坐标系中的位置

### 4.1 与业界一致的做法（**可以自信地讲**）
- 图谱**用户级隔离**：比 §3.5 的同类开源更严谨（多数同类项目是全局单图）
- 图谱**既读又写**（对话中新增知识点写回图）：路线 A 的系统普遍只读
- **两级分组（学科→板块）+ 按需切片**：对应 LightRAG 的"双层"思想，但我们是**教学语义分层**，更有解释性
- **不做 LLM 社区摘要**：规避了 GraphRAG 系最大的成本坑
- **路径可解释**（拓扑序 + 掌握度阈值）：符合 MDPI 2026 强调的"透明性"

### 4.2 业界已有而我们没有的（**缺口，按可落地性排序**）

| 缺口 | 业界成熟做法 | 落地成本 | 价值 |
|---|---|---|---|
| **先修关系无量化评测** | 多准则无监督推断（IJCKG 2025）+ 公开数据集（MOOCCubeX） | 中 | ⭐⭐⭐ 直接产出参赛要的量化指标 |
| **图谱检索不能扩跳** | `kg_hop_depth` 沿边遍历（AI_Tutor）、PPR 多跳（HippoRAG） | **低** | ⭐⭐⭐ 提升 RAG 召回质量 |
| **无"图谱开/关"对照实验** | KG-RAG vs 纯 RAG 模式切换（AI_Tutor） | **低** | ⭐⭐⭐ AIC 赛道最需要的证据形态 |
| **掌握度无时间维度** | 时序知识图谱（Zep/Graphiti） | 中 | ⭐ 未来做成长报告 |
| **注入体量无控制（G1）** | GraphRAG 的 Local/Global 分级取用 | 中 | ⭐⭐ 契约已列为 P0 |

### 4.3 明确不采纳及理由（**材料里可以主动说，显示判断力**）

| 不采纳 | 理由 |
|---|---|
| 引入 Neo4j 等图数据库 | 单用户百级节点用 SQLite 足够；Docker 单容器约束下不增服务（见 §3.2） |
| 引入 GraphRAG / LightRAG 框架 | 它们的图从文本抽、服务检索；我们的图是教学结构，**借鉴手法而非引入依赖** |
| 引入 DKT/AKT 等 KT 模型 | 需要长交互序列，本项目冷启动单用户无此数据（见 §2.2） |
| 引入 KGE 做链接预测补边 | 会产生不可解释的边，与"可审计"冲突（见 §2.5） |
| 引入 KAG/OpenSPG | 工程重、场景不匹配 |

## 5. 可借鉴点（按优先级）

### P0 — 补先修关系的量化能力（**直接服务 AIC 赛道**）—— ✅ 已实现（2026-09-12）

> 实现方案与核心思路：`知识图谱_P0实现方案与核心思路.md`；代码：`core/prerequisite.py`；
> 评测：`scripts/eval_prerequisite.py`（`backend/eval_data/report_prereq.json`）。

1. **多准则先修推断** —— ✅ 已落地：参照 IJCKG 2025 那篇（arXiv:2509.05393）的思路 —— 无监督、多特征、投票融合。
   实现为 **6 条准则**（正文引用/名称包含/次序/难度差/共同前置/语义相似）+ 固定分母加权投票，
   每条候选边带**逐准则证据**；另有跨跳过滤、保 DAG、入度上限三层结构约束。
   **关键**：它是**无监督**的，我们同样没有标注数据，条件匹配。
   ⚠️ **未做**：把该层接入 `graph_generator` 的生成链路（接入点已明确，见文档 §6）；目前只在 API 侧按需触发。
2. **用 MOOCCubeX 的先修子集做外部评测**（数学/心理学/CS 三科含人工标注）—— ⚠️ **部分完成**：
   评测脚本、三档口径（基线/新增/合并）、阈值扫描、报告 JSON 均已就绪，并在**内置 8 条 gold 的人工样本**上跑通
   （micro：基线 P/R=0.833/0.625 → 合并 0.889/1.000）；**但尚未下载 MOOCCubeX 实数据**，因此还没有"外部可比"的数字。

### P1 — 低成本、见效快
3. **图谱检索扩跳**：在 `rag_search(source=graph)` 上加"沿 prerequisite 边扩展 N 跳"，
   参照 AI_Tutor 的 `kg_hop_depth`。改动集中在 `core/rag/` + 工具参数。
4. **图谱开/关 A-B 对照实验**：同一组问题，分别走"注入图谱 / 不注入图谱"，
   统计答案的知识点覆盖度与幻觉率。**这是 AIC 赛道"量化报告"最好写的一块**，
   且能反过来验证参照系契约 L1 的价值（呼应 NAACL 2024 那篇综述）。

### P2 — 有条件再做
5. **掌握度时间序列**：若要做"学习成长报告"，参考 Graphiti 的时序图（事实带有效期）。
6. **PPR 多跳检索**：若扩跳后精度不足，再参考 HippoRAG 的个性化 PageRank。
7. **查证基础教育知识图谱标准**（CELTSC 2025-06）：确认本体定义与我们的 subject/board/tags 是否冲突，
   涉及参赛材料合规表述。
