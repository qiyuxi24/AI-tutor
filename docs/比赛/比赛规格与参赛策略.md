|------|------|

### 1.3 我们选的赛道：大学生OPC创新创业AI agent（官方定义）

> 聚焦**高校创新创业教育与大学生AI创业实践场景**，围绕 AI agent 支撑个人或小团队开展轻量化创新创业实践进行作品创作。鼓励运用 AI 大模型、AI agent、知识库、自动化工作流等技术，探索大学生以个人/小团队形式完成**项目策划、产品设计、内容生产、运营推广、用户服务、成果交付**等创业任务的新模式。
>
> 参赛作品的开发/组织/运营/交付方式应体现 **OPC 特征**：**低成本启动、小团队协作、AI辅助执行、快速验证、持续迭代**。
>
> 可围绕：教育服务、学习支持、职业训练、校园服务、知识服务、内容创业、社会服务、文旅推广、数字营销等场景设计。

> ✅ **对 TutorAgent 的意义**：完全对口。我们正是"AI agent + 知识库 + 自动化工作流"，"低成本启动/快速迭代"与单人/小团队开发模式天然契合；只需在申报中**明确点出 OPC 五特征**如何体现。

## 二、含金量分析（客观、不吹不黑）

### 2.1 权威性：主办方是"国家级协会"，但奖项是"行业性"而非"政府行政奖励"

- 中国教育技术协会是**教育信息化领域唯一的国家级行业协会**（官方FAQ原话），主办背景权威。
- **官方FAQ明确说明**：本次大赛奖项属于**行业性奖项，而非政府行政奖励**；"在教育系统内具有较高的知名度和认可度，但最终是否被当地教育局认可，取决于各地具体政策"。
- **对学生的实际价值**：① 履历上"国家级行业协会赛事"加分；② 若走高校综测/评优，多数学校认协会级赛事，但**必须提前向学院/教务确认加分细则**——这是唯一要核实的不确定项。

### 2.2 规模与热度：2025年前身赛数据（判断竞争烈度）

前身为2025年"AI赋能在线教学创新成果大赛"（同一主办方、同一官方平台）：

| 指标 | 2025年前身赛 |
|------|-------------|
| 覆盖范围 | 全国30个省（自治区、直辖市） |
| 报名作品 | 1182个 |
| 参赛单位 | 近300家 |
| 获奖作品 | 192项（一等奖15、二等奖24、三等奖62、优秀奖91） |
| 线下决赛 | 40件作品 |

**推演**：① 整体获奖率约16%，但分赛道后我们赛道（学生AI agent）获奖概率需看报名数；② 赛道越细分、越垂直，越容易突围——OPC赛道是本届新增细分方向，**竞争者大概率是"AI+教学"类泛项目，真正把 agent 工程做扎实的少**，这是我们的结构机会；③ 首届"OPC"赛道（2026新设），**没有历史强队包袱，大家同一起跑线**。

### 2.3 权益含金量拆解

| 权益 | 实际价值 | 对我们的意义 |
|------|---------|-------------|
| 协会荣誉证书 | 行业认可，综测/履历加分（需学校确认） | 主要回报 |
| 官网成果展区长期展示 | 公开可查、可挂简历 | 加分项 |
| 企业孵化对接 | 对接头部企业（科大讯飞、阿里云、钉钉等为合作方） | 长期想象空间，别指望短期变现 |
| 全媒体曝光 | 视频号/抖音/小红书官方号 + 年会现场 | 对个人 IP 有助 |

### 2.4 客观提醒（含金量的"另一面"）

1. **不是教育部/教育厅官方榜单赛事**，与"互联网+""挑战杯"等政府主导赛事不是一个量级；对保研/评奖的权重需以学校认定为准。
2. 参赛门槛低（免费、个人可报、无需盖章）→ 报名基数可能大，但**多数是教师做的"AI+教学案例"，学生 agent 赛道竞争相对可预测**。
3. 决赛是"材料集中评审"（非现场答辩），意味着**作品介绍文档 + 演示视频是决胜核心**——技术做得再好，材料讲不清就白做。

## 三、精力分配与参赛策略（距报名截止 6 周半）

### 3.1 总原则：别"做完"，要"讲清 + 演示不翻车"

评审是**看材料**（文档+视频），不是看你的代码仓库。所以精力分配的核心逻辑是：
> **功能做到"演示亮点够用"即可，把多出来的精力全部投给"材料表达"。**

一个人 6 周半的合理分配（按投入时间占比）：

| 板块 | 占比 | 说明 |
|------|------|------|
| 功能打磨（P0/P1） | 30% | 只做"演示会露脸"的项，砍掉所有不演示的 |
| 演示数据填充 | 20% | 完整学科图谱 + 对话脚本，直接决定视频素材质量 |
| 作品介绍文档 | 20% | 五维评审逐条命中，这是"讲清"的主战场 |
| 演示视频 | 20% | 10分钟：概述2min/演示6min/总结2min，可反复重录 |
| 报名收尾 | 10% | 申报书、承诺书、支撑材料、提交 |

### 3.2 分周执行表（8/31 → 10/15）

| 周次 | 时间 | 核心任务 | 里程碑 |
|------|------|---------|--------|
| W1 | 8/31-9/6 | **P0稳定化**：LLM重试机制、toast替代alert、CORS配置化、修复图谱重复节点；项目改名"TutorAgent"收尾 | 系统在弱网/切换端口下演示不翻车 |
| W2-W3 | 9/7-9/20 | **演示差异化三件套**：①学习进度仪表盘（直接补痛点2）②节点掌握度三色着色 ③学习路径图上高亮 | 评审视觉分拉满；若有余力做RAG引用卡片（P1.5） |
| W4 | 9/21-9/28 | **演示数据**：填充1个完整学科图谱（建议"数据结构"或"线性代数"，15-20节点+前置边）+ 写2-3条对话演示脚本 | 图谱内容丰富、AI可触发动态生长 |
| W5 | 10/1-10/7 | **材料主体**：作品介绍文档初稿 + 演示视频录制剪辑（OBS+剪映） | 文档、视频初版 |
| W6 | 10/8-10/14 | 材料精修 + 申报书/承诺书 + 支撑材料 + 内部评审 | 全部定稿 |
| 截止 | 10/15 | 官网提交 | — |

### 3.3 按评审五维的"命中清单"（材料怎么写）

| 评审维度 | 评委想看 | TutorAgent 怎么答 |
|---------|---------|------------------|
| 场景适配性 | 真痛点、真场景 | 大学生自学三大痛点（碎片/无反馈/笔记痛苦）逐一对应功能 |
| 技术规范性 | 架构合理、代码规范 | 架构图（FastAPI+Vue3+SQLite）、技术选型理由、**RAG去耦合的rag_pipeline（模块化可插拔）是重要加分点** |
| 创新优化性 | 差异化、有亮点 | ①两阶段流式（SSE+后台function calling）②知识图谱自适应教学 ③拓扑排序学习路径 ④RAG路由器 ⑤AI自动笔记 |
| 实施显著性 | 真落地、有结果 | 可运行产品 + 演示视频 + 一个学科的完整图谱（"学习路径可生成、图谱可动态生长"） |
| 推广适配性 | 易复制、可推广 | 纯Web + SQLite零配置 + 一键安装/启动脚本，学生老师都能装 |

### 3.4 赛道策略（OPC 怎么"扣题"）

材料里**显式写出 OPC 五特征如何体现**（很多队伍不会点题，这就是差距）：

| OPC特征 | TutorAgent 对应 |
|---------|----------------|
| 低成本启动 | 纯开源技术栈 + SQLite 零依赖 + 一键脚本 |
| 小团队协作 | 单人/小团队可维护，模块化解耦（rag_pipeline等） |
| AI辅助执行 | AI自动维护图谱、自动笔记、自动出题 |
| 快速验证 | 两阶段流式 + 事件总线，功能可快速迭代 |
| 持续迭代 | 知识图谱动态生长、画像动态更新 |

### 3.5 风险与兜底（演示不翻车优先级最高）

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 演示时 LLM 网络抖动 | 中 | 高 | **W1就做重试+本地缓存回退**，别拖到最后 |
| 视频超10min/超500MB | 中 | 高 | 每段录完查时长，剪辑时压缩 |
| 材料"讲不清" | 中 | 高 | W5找同学试看，不懂技术的能不能看懂=评委能不能看懂 |
| 学校不认可该赛事加分 | 中 | 中 | **尽早问教务/学院**，认不认都参赛（履历价值仍在） |
| 撞题 | 低 | 中 | 突出"知识图谱自适应"这一差异化标签 |

### 3.6 组队建议（维持现状即可）

- 现状**单人完全可行**（与COMPETITION.md结论一致），不必为组队分心。
- 若中途遇到合适的：优先招**剪辑/文案**（省最耗时的视频+文档），**不要招后端**。
- 答辩环节到决赛前再说，当前无需为它投入。
