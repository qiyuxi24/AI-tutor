# 第 5 章 商业模式与落地

AI-tutor 的商业化按 **"MVP 验证 → 高校 SaaS → 平台生态"** 三段推进：先用免费 C 端跑通留存与数据验证，再以比赛背书撬动高校 B 端付费，最终开放能力做多学段生态。本章回答：怎么赚钱，凭什么能落地。

## 5.1 核心目标客户

| 阶段 | 客户类型 | 需求匹配 | 付费能力 | 合作基础 | 单客单价 |
|---|---|---|---|---|---|
| 短期（2026-2027） | 高校学生 C 端 | 自学、考前复习刚需，痛点直接 | 弱，接受增值订阅/单学科包月 | 比赛曝光 + 学长学姐口碑裂变 | 待补（参考学习通会员等 C 端通行区间） |
| 中期（2027-2029） | 高校 B 端：教务处/院系/在线课程平台 | 教师赋能工具 + 学生自学辅助，可视化学习数据 | 强，可走预算采购 | 内测留存数据 + 比赛背书 + 校内试点 | 待补（参考智慧树/学习通按校订阅通行区间） |
| 长期（2029+） | K12 / 职教 / 企业培训 | "不直接给答案"引导式教学跨学段复用 | 强 | 高校 SaaS 模式整体移植 | 待补 |

三层客户是漏斗而非并列：C 端用户即 B 端试点时的学生用户与数据来源，B 端打磨出的"通用框架 + 学科内容"能力是长期跨学段复制的资本。

## 5.2 商业盈利模式

| 阶段 | 营收来源 | 收入占比预期 | 关键里程碑 |
|---|---|---|---|
| MVP 验证期（≤6 个月） | 暂无营收，比赛奖金与校内资源覆盖开销 | **0（当前无营收，如实呈现）** | 2026-10-15 完成大赛校内申报；≥3 所高校内测启动；投资人首次接触 |
| 高校 SaaS 期（1-3 年） | 按校/按学年 SaaS 订阅 + 教师增值工具 + 单学科深度包 | B 端订阅为主，具体占比待内测数据确定 | ≥50 所高校付费；≥2 个单学科深度包（线性代数/数据结构）上线 |
| 平台生态期（3+ 年） | API 开放 + 学科内容分成 + 多学段复制授权 | 多元化，待 B 端成熟后规划 | API 正式开放；K12/职教至少 1 个学段复制验证 |

MVP 期零营收是刻意选择而非妥协——**先免费 C 端跑通留存（≥3 校 1000+ 学生），以留存数据撬动 B 端按校付费**，此即 9.3.2"C 端付费意愿不足"的应对策略本身；单人独立闭环使验证前月固定成本近乎为零，即 9.6.2 现金流应对的前提。承认分阶段、给出节奏，比财务模型更可信。

## 5.3 商业落地基础与保障

**一、技术完整度**：MVP 核心闭环（对话—图谱—画像—路径）已可演示，**91 个源文件 / 1.7 万行代码**构成完整前后端，四种教学模式与学习进度仪表盘（四色掌握度着色 + 薄弱点高亮）均已实现；演示视频与演示脚本已列为 10 月前必交付项，确保评审看到的是能跑的产品而非 PPT。

**二、工程化配套**：根目录 `install.ps1` / `start.ps1` 一键安装启动脚本已落地（覆盖前后端依赖安装与环境检查），`Dockerfile` 已编写并配套部署调研文档；批量入库 38 倍提速等性能优化同步沉淀，为 B 端私有化部署（9.4.1 合规应对的选项之一）扫清工程障碍。

**三、设计文档**：docs/ 下 **6 篇调研设计文档**（RAG 去耦合、出题逻辑、仪表盘设计等关键决策，含 35+ 外部参考引用）+ `data/AI-tutor_项目框架文档.md`（API 清单/架构决策/Review 报告），构成完整知识沉淀，使关键人断档时新成员可快速接手（9.5.1 单人持续性应对）。

**四、测试体系**：三层测试——**90+ 单元测试**（全 mock 零网络，秒级回归）+ **11 项端到端集成测试**（覆盖上传→分块→检索全链路）+ **256 文档 / 1000 query 离线评测集**（CMRC2018），评测脚本可复现、报告 JSON 落盘；新人先跑通评测集再动核心代码，质量保障不依赖人力堆砌（9.5.1 / 9.5.2 应对）。

**五、比赛背书**："中国教育技术协会 AI+教育大赛"**校内截止 2026-10-15**，申报材料与本商业计划书共享约 80% 内容；备赛 P0 清单（LLM 请求重试、演示兜底等）正在逐项推进。获奖即教育技术界权威第三方对产品价值的背书，也是高校 B 端破冰的第一块敲门砖。

## 5.4 未来落地路线图

| 阶段 | 时间 | 核心目标 | 量化指标 |
|---|---|---|---|
| 短期 | 1 年（2026-2027） | 比赛获奖 + 高校内测验证留存 | 大赛获奖；**≥3 所高校内测；1000+ 学生用户** |
| 中期 | 3 年（2027-2029） | 高校 SaaS 商业化 | **≥50 所高校付费；≥2 个单学科深度包**（线性代数/数据结构） |
| 长期 | 5+ 年（2029+） | 多学段平台生态 | API 开放；覆盖 **K12 / 职教 / 企业培训**中 ≥2 个新学段 |

每一阶段的量化指标都是下一阶段的入场券：内测留存数据是 SaaS 定价与融资的依据；SaaS 期学科包验证"通用框架 + 学科内容"解耦能力（9.2.3 多学科扩展应对），是长期多学段复制的底气。分阶段、可量化、有节奏——每一步都以已落地的工程事实为起点。
