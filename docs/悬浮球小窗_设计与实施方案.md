# 悬浮球小窗（站内）设计与实现

> 状态：**已实现**（2026-09-27）
> 影响范围：`frontend/src/components/FloatingBall.vue`（新增）、`views/HomeView.vue`、`views/SettingsView.vue`、`utils/floatingBall.js`
>
> **需求变更记录**：早先曾按"跨站"（浏览器扩展，球出现在别人家网页上）设计并实现过一版；
> 2026-09-27 需求改为**站内**，那一版的产物（`extension/` 整个目录、`views/EmbedView.vue`、

## 1. 需求

1. 悬浮球 + 小窗，**只在本应用内部**（不涉及别人的网页、不装扩展）
2. 小窗**只放对话**
3. **对话页不显示**悬浮球（那里已经有完整对话区）
4. 开关放**设置**里，且跟账号走

## 4. 关键设计决策

1. **可见性由父级控制**：`visible = 已开启 && viewMode !== 'chat'`。
   悬浮球的存在理由是"在别的页面也能随手问一句"；对话页已有完整对话区 → 不需要它。
   需求里的"对话界面不能存在"就落在这一行上。
2. **小窗与主对话共用同一个 `chatStore`**：小窗里聊的内容，切回对话页就在那儿，不搞两套历史。
   可行的前提：`HomeView` 里各视图是 `v-if` 切换（`HomeView.vue:346`），进对话页时其它页面已卸载，
   不会出现两个 `ChatArea` 同时活着；同时 `visible` 变 false 会让小窗自动收起。
3. **偏好用共享响应式状态**（`floatingBall.js` 的 `ballPrefs`）：设置页一改，球立刻响应，
   不需要刷新页面，也不需要事件总线。
4. **偏好的真值源在服务端**（`UserProfile.preferences.floating_ball`）：跟账号走，换设备/换浏览器开关状态一致；
   写入沿用设置页既有的"读完整画像 → 合并 → 全量 PATCH"模式，避免覆盖 `usage_mode` 等其它字段。
5. **球的位置只存本机**（`localStorage`）：摆放是浏览器窗口的属性，不是账号的属性，不上服务端。
6. **手动微调优先于预设**：球位置 / 小窗位置 / 小窗尺寸都存在本机，优先于设置页的预设值。
   用户在设置页**主动**改预设时清掉对应的手动微调（靠 `ballPrefsMeta.revision` 区分"用户改的"与"首次加载"），
   否则预设看起来像"点了没反应"。

## 5. 验收清单

- [ ] 设置 → 悬浮球 → 启用 → 切到图谱页，右下角出现球
- [ ] 切回对话页 → 球消失，且原本开着的小窗自动收起
- [ ] 点球展开小窗，能流式问答（`thinking` / 工具事件也正常渲染）
- [ ] 小窗里发的消息，切回对话页能接着看（同一会话）
- [ ] 拖动球到左下角松手 → 吸附；刷新页面后位置还在
- [ ] `Esc` 收起小窗；Tab 能聚焦到球、Enter 开合
- [ ] 设置里把开关关掉 → 球立即消失（不用刷新）
- [ ] 系统开启"减少动态效果" → 球不再有缩放动画

## 6. 已知限制 / 后续（都不阻塞使用）

- 快捷键 `Alt+J` 未实现（偏好 schema 里留了 `hotkey` 字段）
- 小窗里不能切换历史会话（"只放对话"的必然结果；换会话请回对话页）
- 缩放把手是**鼠标专用**（无键盘等价操作）；键盘/触屏用户走设置里的三档预设
- 8 个把手除右下角外**不可见**（靠鼠标指针形状提示）——刻意如此：380px 宽的小窗里画一圈把手太吵
- 手动尺寸/位置存在本机，多标签页之间不会即时同步（刷新后一致）
- 球的位置存在 `localStorage`，多标签页之间不会即时同步（刷新后一致）
- 移动端窄屏未专门适配（球可能挡住内容；`default_open` 建议关闭）

## 7. 附：为什么不做"跨站"（球出现在别人家的网页上）

**结论**：网页无法向其它网站注入 UI（浏览器安全模型），要出现在别人家的网页上就必须让用户
**装一次扩展**——装扩展是额外动作，还附带地址匹配、全站权限告警、上架审核等持续成本；
而需求只要站内，所以直接做站内版，零安装、零配置、零成本。

如果将来确实要跨站，那套设计（扩展 MV3 / 悬浮球脚本 / iframe 小窗 / token 交接 / 存储分区 /
CSP `frame-ancestors` / 商店素材）需要重新评估，不要凭记忆复原——其中"站点页面要不要手填扩展 ID"
和"第三方 iframe 的 localStorage 按 (顶层站点, iframe 源) 分区"两个坑当初都踩过。

## 8. 附：顺带修掉的一个既有 bug（与本功能无关）

`chatStore.js` 调 `sendMessageStream` 时多传了一个已被删除的 `mode.value` 位置参数，
而现行签名是 `(messages, callbacks, currentNode, kb)`（`api/index.js:115`）→
`callbacks` 实际收到字符串，解构出的 `onToken` / `onDone` / `onError` **全是 undefined**
（表现为对话没有流式渲染、`loading` 也不会复位）。已删掉该参数。
