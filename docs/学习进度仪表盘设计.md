## 一、设计理念：图谱 = 地图 = 科技树

**第一原则**：知识图谱是最重要的资产，是与其他 AI 学习工具差异化的根基。用户应该把图谱**当地图、当科技树**使用——进度不是单独展示的统计数字，而是"看图谱就知道自己到哪了"。

因此进度展示分两层：

```
┌─────────────────────────────────────────────┐
│  学习进度仪表盘（概览层）                      │
│  · 总体完成度 / 掌握度分布 · 下一步推荐        │
│  · 学科 × 板块进度条         · 薄弱点 Top3     │
│  ↓ 点击任意指标/节点（联动）                   │
├─────────────────────────────────────────────┤
│  知识图谱（科技树层 = 主战场）                 │
│  · 节点四色掌握度着色（灰/红/黄/绿）           │
│  · 学习路径连线高亮（"该走的路"亮起来）        │
│  · 薄弱点脉冲标记 + 图例                      │
└─────────────────────────────────────────────┘
```

**图谱即进度地图**：灰色=未开始（科技树的暗色节点）、红色=薄弱刚学、黄色=学习中、绿色=已掌握；路径高亮=接下来的路线。用户看图谱就是在看进度，仪表盘只是快速概览入口。

## 二、现有资产盘点

### 已就绪（直接复用）

| 资产 | 位置 | 说明 |
|---|---|---|
| 掌握度字段 | `nodes.mastery` (0-100) | AI 工具 `update_mastery` 写入，进度的唯一源头 |
| 预估时长/难度 | `nodes.estimated_minutes` / `difficulty` | 支撑剩余学时估算 |
| 学习路径算法 | `get_learning_path()` / `get_next_to_learn()` | Kahn 拓扑排序 + mastery<50 推荐；**后端已通，前端未封装** |
| 板块统计 | `GET /knowledge/boards` | `{board, node_count, mastered_count, mastery_avg}`，前端已封装 |
| 图谱实时数据流 | `chatStore` + SSE `graph_updated` | 图谱变更自动推送，仪表盘免费复用 |
| 三档色先例 | `GraphSearch.vue` | `<60` / `30-60` / `>=60` 分色逻辑可迁移 |
| 卡片/进度条样式 | `KnowledgeView` `.stat-card`、`NodeDetail` `.mastery-bar` | 主题变量驱动，明暗自适应 |

### 缺口（本方案补齐）

1. 图谱节点只有二态着色（0→灰、>0→紫），无"科技树"进度感
2. 前端未封装 `learning-path` / `next-to-learn` / `PUT mastery`
3. 无整体统计端点（只有板块级）
4. 无学时/最近学习时间记录（v1 不改数据模型，用对话 updated_at 估算或暂缓）
5. quiz 作答记录未回写图谱 mastery（反馈闭环断裂）

## 三、数据流（双向联动闭环）

```
对话中 AI 更新 mastery ──→ SSE graph_updated ──→ 仪表盘实时刷新（无需轮询）
                                                     ↑ 点指标 → 切 viewMode='graph'
                                                     │          + focusNode(id) 聚焦
仪表盘 ←── 聚合：/knowledge/stats（新增后端端点）
图谱   ←── 高亮：learning-path 路径 + 薄弱点
```

关键机制：
1. **单一数据源**：仪表盘数字全部从图谱聚合，不建独立进度表（v1），保证"图谱改、仪表盘变"
2. **点击跳图谱**：复用 `forceGraphRef.focusNode(nodeId)`（已 defineExpose）+ 参照 `handleGraphSearchSelect` 的"切视图等 450ms 再聚焦"模式
3. **图谱即仪表盘**：四色 + 路径高亮让图谱本身就是最生动的进度展示
