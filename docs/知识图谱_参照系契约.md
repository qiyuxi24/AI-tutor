## 1. 一句话定义

> 知识图谱不是被检索的数据库，而是**每一次 LLM 调用的参照系**：
> 调用前用它**定界**（能讲什么）、**定标**（讲到哪、学生掌握到哪），
> 调用后把新知识**写回同一张图** —— 图既是输入的约束，也是输出的产物。

三个关键词的精确含义：

| 关键词 | 含义 | 反面（我们要避免的） |
|---|---|---|
| 参照系 | 每次调用都必须引用它，与"本次问了什么"无关 | 检索式：命中才用，没命中就不用 |
| 定界 | 图谱定义教学的**可行域**，域外内容不引入教学 | 无边界型：模型自由发挥，事后才归档 |
| 闭环 | 图 → 提示词 → 回答 → 图谱分析 → 图，每轮转一圈 | 单向型：图只做冷启动，之后只读不写 |

这三条同时成立，才叫"图谱驱动"。**缺任何一条，都退化为"图谱辅助"。**

---

## 2. 参照系三问（操作性定义）

任何一次 LLM 调用（含 agent 循环里的每一个工具轮），必须能回答三个问题：

| # | 问题 | 对应层 | 未回答的后果 |
|---|---|---|---|
| ① | **能讲什么** —— 本次允许出现哪些知识点，边界在哪 | L1 定界 | 模型自由生成教学内容，图谱沦为事后归档 |
| ② | **现在在哪** —— 学生当前在图谱的哪个位置、掌握到什么程度 | L2 定位 | 讲错难度/重复已掌握内容/跳前置 |
| ③ | **依据什么** —— 这句话出自哪个节点、哪段材料 | L3 引用 | 不可审计，答辩时无法证明"不是编的" |

> **总判据：三问答不全 = 该层未落地。**
> 本契约以下所有定义、验收标准，都是这三问的展开。

## 3. 三层定义

### L1 定界（Boundary）

**定义**：该用户图谱的节点集合与边集合，构成本次调用的教学可行域；模型不得把可行域外的概念作为教学内容引入。

**不变量**

| 编号 | 不变量 | 判据 |
|---|---|---|
| I1-1 | 每次调用都必须注入可行域信息，不可省略、不可条件跳过 | 三种模式（adaptive / free_talk / recursive）全含 |
| I1-2 | 注入的节点 ID 必须真实存在于该用户图谱 | 与 `GET /knowledge/node-ids` 结果一致 |
| I1-3 | 可行域必须是**正面约束**：既说边界，也说"可讲哪些、以及它们的邻域" | 提示词中出现正面清单 + 邻域说明 |
| I1-4 | 注入体量必须受控（可行域 ≠ 全量倾倒） | 见 G1 与 AC-L1-3 |

**反例（出现即判定未落地）**

- 只在图谱为空时注入，非空时省略；
- 只写"不准脱离框架"，却不给出可讲内容的正面清单；
- 注入的节点 ID 与图谱实际不符（含幻觉 ID、已删节点的残留 ID）。

### L2 定位（Position）

**定义**：每次调用必须携带"学生此刻在图谱上的位置"与"掌握度分布"，且该信息必须被赋予**行为语义**（影响讲什么、讲多深、什么节奏），而不仅是展示。

**不变量**

| 编号 | 不变量 | 判据 |
|---|---|---|
| I2-1 | 三种模式都必须有"当前位置"概念，不能只有 recursive 有 | 请求可传位置；缺省时服务端可推导 |
| I2-2 | 掌握度数值必须出现在注入文本中 | 每节点含 `mastery` |
| I2-3 | 掌握度必须带行为语义 | 提示词中明确"mastery 高 → 精简/跳过，低 → 换角度/降难度" |
| I2-4 | 前置关系必须可比 | 注入文本含 prerequisite 边方向 |

**反例**

- `current_node` 收了但只对 recursive 渲染，adaptive / free_talk 拿到就丢；
- 掌握度只是列表里的数字，提示词没有任何一句要求模型据此调整；
- 位置只能由前端传，前端不传时服务端不做任何推导。

### L3 引用（Provenance）

**定义**：回答中凡有图谱依据的部分，可回指到具体节点/片段，使"这句话凭什么"可被外部复核。

**不变量**

| 编号 | 不变量 | 判据 |
|---|---|---|
| I3-1 | 注入的图谱内容带可引用标识（node_id） | 文本中 id 与图谱一致 |
| I3-2 | 模型回答可回指依据（显式或可推断） | 回答/记录中能定位到节点 |
| I3-3 | 引用可被审计 | 凭 `run_id` 可回源该次调用的完整输入 |

**说明**：L3 是三层中唯一的**可选增强层**（见 §8）。未落地不阻断 L1/L2 的验收，
但它是"可解释性"与答辩证据链的关键，成本低时应做。

## 4. 现状对照

> 结论先行：**L1 已落地（用负面约束的形式）；L2 半落地；L3 未落地。**
> 而三者共同构成"参照系"，所以目前**应表述为"图谱是全量框架约束"，
> 不宜直接宣称"图谱是每次调用的参照系"** —— 那需要一个缺口（G1）先补上。

### 4.1 调用链（现状）

```
POST /chat/stream
  └─ api/v1/chat.py            kb = {node_ids, name} | None
       └─ chat_service.process_message_stream
            └─ _build_system_prompt(inject_tools=True, current_node, kb)
                 ├─ _build_graph_summary(kg, detailed=True)   ← 全量图谱转文本
                 │    └─ graph_analyzer.build_graph_context
                 ├─ UserProfile.get_summary()
                 ├─ get_system_prompt() → system_prompt_common.j2
                 │    {knowledge_graph_summary}  ← 「框架约束（极其重要）」
                 ├─ _build_retrieval_context()  ← 按需 RAG（graph + kb 两区块）
                 └─ TOOL_CAPABILITY_PROMPT      ← 工具触发语义
            └─ trim_history_to_budget(system_prompt, messages)  ← 只裁历史
            └─ run_agent_loop(...)  → LLM ↔ KG_TOOLS 多轮
            └─ _analyze_and_apply(...)  ← 后台写回图谱
                 └─ publish("graph_updated")
```

## 5. 缺口清单与最小改造路径

> 原则：**先补最硬的 G1，再谈其余。** 所有改造都必须复用已有件，不新增抽象层。

### G1（P0）图谱注入无体量控制 —— 唯一会随规模恶化的缺口 ✅ 体量半边已落地（2026-09-13）

**问题**：全量节点（每节点 200 字摘要）+ 全量边无上限注入 system prompt。
当前 15-20 节点的演示规模约 3k-4k 字符尚可；图谱涨到 100+ 节点后：
每轮输入 token 线性增长（按输入计费 → 直接烧钱）、注意力被稀释、约束反而变弱。

**为什么是 P0**：这是唯一"现在能跑，但规模一大就失效"的缺口，且违反 I1-4。

**最小路径**（不新增模块）：

1. 复用已有 `graph_middleware.slice_graph(kg, subject, board)` 做选片 —— 它已实现三级粒度且有测试（`tests/test_graph_middleware.py`）。
2. 新增**一层薄转换**：选片结果 → 注入文本。它只需要替换 `_build_graph_summary` 的**数据来源**，输出格式不变 —— 因此 `system_prompt_common.j2` 的占位符与下游全部不动。
3. 加字符上限兜底：超限时按优先级截断（当前节点邻域 > 当前板块 > 同学科 > 其余），并在文本中显式标注"当前展示范围"。

**风险点**：`slice_graph` 返回原始 dict 列表，不产文本；且要防"选片过窄导致可行域失真"——
所以必须保留一条"未展示部分存在"的显式说明，否则模型会以为图谱只有这么大（I1-3 反面）。

**落地情况（2026-09-13，实测与细节见 `docs/上下文工程_调研与差距审计.md` §11）**：

- ✅ **第 3 步（字符上限兜底）已实现**：`build_graph_context(kg, detailed, max_chars, focus_node_id)`，
  上限 = `GRAPH_INJECT_MAX_CHARS`（默认 12000 字符 ≈ 7.4K token）；
  降级顺序 = 省节点内容摘要（框架必须完整）→ 限量节点（当前教学节点邻域优先）；
  任一级降级都在尾部附 `> 说明：…当前展示范围：节点 x/y 个、关系 a/b 条…`，且说明文字**计入**上限。
  **实测（300 节点）**：83,846 字符 / 44,713 token → **11,952 字符 / 7,418 token**。
- ⏳ **第 1、2 步（`slice_graph` 选片）未做**：对话链路没有「当前学科/板块」信号，
  需先有 G2 的「当前位置」才能选片。当前用「当前教学节点邻域优先」代替 —— 方向一致，
  但范围按**预算**倒推而非按**学科边界**划分。

### G2（P1）补"当前位置"到全部模式

**问题**：`current_node` 只有 recursive 消费；adaptive / free_talk 无位置概念（违反 I2-1）。

**最小路径**：

1. 请求侧扩展：`ChatRequest` 已接收 `current_node`，只需**允许非 recursive 模式也传**（schema 无需改，改的是消费逻辑）。
2. 服务端推导兜底：前端不传时，从消息历史 + RAG 命中的 top 节点推导（复用 `_build_retrieval_context` 已有的检索结果，不新增检索）。
3. 提示词侧：在 `system_prompt_common.j2` 的框架约束段落补一句"学生当前所处位置：{...}"（共用段落，三种模式一次补齐）。

### G3（P1）掌握度行为语义

**问题**：数值在、语义无（违反 I2-3）。

**最小路径**：纯提示词改动，在 `system_prompt_common.j2` 的框架约束段落明确分档行为
（`0` 未学 → 可展开；`1-50` 学习中 → 按当前难度；`>70` 已掌握 → 精简、不重复讲）。
零代码，改一个 `.j2` 文件。

### G4（P2）正面约束改写

**问题**：现在是纯负面表述（违反 I1-3）。

**最小路径**：与 G3 同一处改动，把"严禁脱离框架"改成"可讲范围 = 以下节点及其 prerequisite/related 邻域；域外概念不引入"。

### G5（可选）L3 引用回指

**最小路径**：提示词要求回答末尾以轻量形式标注依据节点（若影响教学语感则只在 `agent_runs.evidence` 层记录，不暴露给学生）。

## 6. 验收标准（AC）

> 每条必须**可机器复核**：能用一条请求或一条命令验证。无法复核的条目不许写进来。
> 复核前提：后端已启动（`backend/venv/Scripts/python.exe -m uvicorn app.main:app --port 8000`，cwd=backend）。

### L1 定界

| 编号 | 验收断言 | 复核方式 |
|---|---|---|
| AC-L1-1 | 三种模式（adaptive / free_talk / recursive）发出的请求，system prompt 均包含图谱节点信息 | 对三种模式各发一次 `/chat/stream`，从 `GET /agent/runs/{run_id}` 的 evidence 中取出输入，断言含图谱段落 |
| AC-L1-2 | 注入文本中出现的每个节点 ID 都能在 `GET /knowledge/node-ids` 中找到 | 正则抽取 `\[(\w+)\]` → 与接口返回取差集，差集必须为空 |
| AC-L1-3 | 图谱注入段落的字符数 ≤ **`GRAPH_INJECT_MAX_CHARS`（默认 12000）**，且超限时有显式"当前展示范围"说明 | 统计 system prompt 图谱段落长度；构造 >200 节点的图谱复测（单测见 `backend/tests/test_graph_injection.py::test_cap_never_exceeded`；实测脚本 `reports/probe_graph_injection.py`） |
| AC-L1-4 | 图谱为空时不报错，且注入"暂无节点"而非空段 | 新注册用户发一次对话，检查 system prompt |

### L2 定位

| 编号 | 验收断言 | 复核方式 |
|---|---|---|
| AC-L2-1 | `adaptive` 与 `free_talk` 模式下，system prompt 也包含当前位置标识 | 两种模式各发一次，检查输入文本 |
| AC-L2-2 | 前端不传位置时，服务端仍能给出位置（推导或"未指定"显式值），不得静默为空 | 发一次不带 `current_node` 的 adaptive 请求，检查文本 |
| AC-L2-3 | system prompt 含明确的掌握度分档行为规则 | 检查输入文本含 mastery 分档描述 |
| AC-L2-4 | 每个注入节点都含 `mastery` 字段 | 正则统计注入节点数 vs `mastery` 出现次数，必须相等 |

### L3 引用

| 编号 | 验收断言 | 复核方式 |
|---|---|---|
| AC-L3-1 | 任一次运行可凭 `run_id` 回源完整输入输出（含注入的全部图谱文本） | `GET /agent/runs/{run_id}` 返回 evidence 含 thinking 全文 + 工具参数与返回（**当前已满足**，作为回归项保留） |
| AC-L3-2 | 图谱/RAG 依据可定位到具体节点或文件路径 | 检查 RAG 区块含 `node_name` / `path`（**当前已满足**，回归项） |
| AC-L3-3 | 回答中的图谱依据可回指（G5 落地后才验收） | 检查回答文本或 evidence 含依据节点标识 |

### 表述合规（对参赛材料）

| 编号 | 验收断言 | 复核方式 |
|---|---|---|
| AC-N-1 | 材料中表述"图谱是每次调用的参照系"时，必须同时满足 AC-L1-3 与 AC-L2-1 | 材料评审时逐条勾选 |
| AC-N-2 | 未满足时，允许的表述为"图谱是全量框架约束"（属实、可复现），不得升级为"参照系" | 同上 |

## 7. 契约变更流程

本文之所以能当"唯一参照"，依赖以下纪律：

1. **代码先于文档**：契约描述的是系统行为，不是愿望。任何本文声称的行为，必须在代码中可复核；
   任何代码行为变更，必须在**同一次提交内**更新本文对应条目，否则视为破坏契约。
2. **改契约 = 改本文**：新增层级、修改不变量编号、放宽验收标准，都写进本文并升版本号（v1 → v2），
   在文末「修订记录」留一行原因。不允许在别处另立说法。
3. **冲突裁决顺序**：运行时行为 > 本文 > `AGENTS.md` > 其他文档（技术报告/BP/README）。
   与运行时冲突时，以运行时为准，并立即回填本文（要么改本文、要么改代码，不允许放着）。
4. **验收标准只增不删**：可放宽阈值，不可删除条目。删除等于放弃该层承诺。

## 8. 明确不做（YAGNI 边界）

以下项经评估**本期不做**，写在此处是为了避免反复讨论：

| 不做项 | 理由 |
|---|---|
| 把图谱做成向量库检索式注入（替换全量注入） | 与"参照系"定义冲突：参照系必须每次在，不能靠检索命中。正确的是**选片**（G1）而非**检索** |
| 图谱 RAG 接入 `hybrid_search` 双检索 | `whoosh_index` schema 把 `node_id` 定为 `NUMERIC`，图谱 node_id 是 TEXT，复用需改 schema + 迁移，属功能级改动；且不影响本文 L1-L3 |
| 多级 fallback 之外的图谱版本化/快照 | 无需求驱动 |
| L3 强制显式引用（向学生展示节点 ID） | 破坏教学语感。L3 的价值在审计，不在界面 |
