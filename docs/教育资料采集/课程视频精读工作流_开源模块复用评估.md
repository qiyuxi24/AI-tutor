# 课程视频精读工作流（course2md → Obsidian → Anki）开源模块复用评估

> 日期：2026-09-29 · 作者：MainAgent
> 目的：把「course2md + Obsidian + Anki」这套海外 PKM 工作流拆成**模块级技术**，逐一对齐
> ① 是否开源 / 许可证　② 能否复用进本 AI-tutor 项目　③ 复用成本（集成+运行+维护）　④ 平替方案。
> 口径：人日成本为**估算**，标 ★ 为"已具备/零新增依赖"。

---

## 0. 结论摘要（效益主义视角）

这套工作流可拆成 **6 个可复用模块**。与本项目现状对照后：

| 结论 | 内容 |
|---|---|
| **已具备（零成本）** | 知识图谱（原生 nodes/edges/小节化，即 Zettelkasten 的本地实现）+ 出题/判分 + LLM 结构化（call_llm）+ 图片 OCR（RapidOCR） |
| **真正要新引入的依赖** | ① 视频下载 yt-dlp　② ASR 转写 FunASR / Faster-whisper　③ 视频抽帧 ffmpeg　④ 间隔重复 py-fsrs |
| **总集成成本** | 约 **6~8 人日**（估算），全部依赖 MIT / Unlicense / Apache-2.0，无许可证传染风险 |
| **运行成本** | 除 LLM（已有预算）外，其余全部本地/免费：yt-dlp 免费、ASR 本地或云免费额度、RapidOCR 本地、py-fsrs 纯计算 |
| **核心理念已原生落地** | Obsidian 双向链接 ≈ 项目已有的知识图谱；Anki 算法 ≈ 可直接用 py-fsrs 接入现有出题/判分循环 |

**一句话**：本项目的"知识图谱 + 出题 + RAG"底座恰好对应这套工作流的**记忆层**，缺的只是**采集层**（视频→结构化笔记）的 3 个采集组件和一个**调度层**（SRS）。复用成本低、风险小，且几乎全是开源。

## 2. 逐模块详解 + 成本

### A. 视频下载 —— yt-dlp（Unlicense）

- **技术说明**：命令行下载器，支持 YouTube / Bilibili / 1000+ 站点，自动解析清晰度、字幕、音轨。
- **开源情况**：开源，**Unlicense（公有领域）**，无任何使用/再分发限制。
- **复用成本**
  - 集成：**约 0.5 人日**。`pip install yt-dlp`，封装 `yt_dlp` 库或子进程调用，加超时/限速/失败重试即可（符合项目"工具失败自动降级"的既有风格）。
  - 运行：免费，纯网络拉流。
  - 维护：高活跃、极稳定，接口极少变化。
- **平替**：`you-get`（站点少、维护慢）、`N_m3u8DL-RE`（m3u8 流）、Bilibili 官方 API。
- **建议**：直接复用，无需自研。

### B. ASR 转写 —— FunASR / Faster-whisper（MIT）

- **技术说明**：把视频音轨转成带时间戳文本。
  - **FunASR**（阿里达摩院）：MIT；**中文准确率高**（官方称相对 whisper.cpp 在中文 CPU 上约 2.7× 更准）；提供 Python / OpenAI 兼容 API / llama.cpp+GGUF（CPU 无 Python 依赖）三种形态；附带 VAD、标点、说话人分离。
  - **Faster-whisper**：MIT；基于 CTranslate2，CPU/GPU 都快，Whisper 系多语言通用。
- **开源情况**：均为 MIT，可商用、可嵌入。
- **复用成本**
  - 集成：**约 1.5~2 人日**。项目**已有 OCR 能力层的"插拔引擎"设计**（`parsers/ocr.py`，文档明确未来云端 qwen-vl-ocr 落点）——ASR 可照同一模式新建一个 `asr.py` 能力层（本地 FunASR / 云 API 可切换 + 降级）。
  - 运行：本地免费（有 GPU 更佳；FunASR GGUF 可纯 CPU）；或云免费额度（阿里百炼 fun-asr / paraformer 新用户有免费量）。
  - 维护：FunASR 高活跃，模型镜像国内可达。
- **平替**：`whisper.cpp`（MIT，CPU 单二进制，中文较弱）、火山引擎/阿里云 ASR API（云，按量计费）。
- **建议**：中文网课优先 **FunASR**（本地/云皆可，中文最强）；若已有云 key 且有免费额度，可先云后本地，走插拔层。

### C. 视频抽帧 + 幻灯片 OCR —— ffmpeg + RapidOCR（已有）

- **技术说明**：course2md 会按字幕时间戳截取视频画面（幻灯片/板书），再 OCR 成文字混入 md。
- **开源情况**
  - **ffmpeg**：LGPL/GPL，系统级依赖（装库或二进制）。
  - **RapidOCR**：Apache-2.0，**本项目已集成**（`rapidocr-onnxruntime` + `parsers/ocr.py::ocr_lines`）。
- **复用成本**
  - 集成：**约 1 人日**。新增"抽帧"一步（`ffmpeg` 按时间戳取关键帧 → 得到图片），然后**直接复用现有 `ocr_lines()`**，无需新 OCR 引擎。
  - 运行：本地免费。
  - 维护：ffmpeg 稳定；RapidOCR 已在线。
- **平替**：OpenCV / PyAV / moviepy 抽帧；OCR 可换 PaddleOCR（Apache-2.0，更准但更重）或云 qwen-vl-ocr（项目视觉解析方案已规划此落点）。
- **建议**：抽帧新增，OCR **零新增**（复用现有插拔层）。

### D. LLM 结构化（去重 / 纠错 / 分节）—— 复用 call_llm（★已具备）

- **技术说明**：course2md 用 LLM 对转写文本去重纠错、切分章节。本项目**已有 `call_llm`（MiniMax-M3）+ `json_extract`**，是唯一带 fallback 的 LLM 出口。
- **开源情况**：非外部依赖，是项目自身能力。
- **复用成本**：**零新增依赖**。只需按"一工具一文件"约定（`core/agent_tools/tools/`）新增一个"视频转讲义/分节"工具，复用 `call_llm`。
- **平替**：无需。
- **建议**：直接复用，注意 M3 三段坑——批量结构化抽取要 `thinking=False`、长 JSON 显式调大 max_tokens（AGENTS.md §项目特有约定）。

### E. 知识卡片 / 双向链接 —— 复用项目原生知识图谱（★已具备）

- **技术说明**：Obsidian 的 Zettelkasten（拆独立卡片 + 双向链接）在项目里对应**知识图谱的 nodes/edges + 节点小节化**。
- **开源情况**：Obsidian 本体闭源；本项目图谱为自研 SQLite（nodes/edges/小节 manifest）。
- **复用成本**：**零新增**。视频讲义结构化后，走既有唯一建图出口 `KnowledgeGraph.create_node_with_content` + `graph_generator` 建图管线即可。
- **平替**：无需（项目图谱即平替，且数据结构经过完整设计，见 `docs/知识图谱/`）。
- **建议**：直接复用，守住"新建节点只有一个出口"的硬约束。

### F. 间隔重复 SRS —— py-fsrs（MIT）

- **技术说明**：Anki 的调度算法可从客户端剥离。**FSRS**（Free Spaced Repetition Scheduler，DSR 记忆模型，Anki 官方采用）是目前最先进的开源间隔重复算法；`py-fsrs`（Python 实现，MIT）与项目 Python 后端完全同栈。
- **开源情况**：MIT，可嵌入商用产品。
- **复用成本**
  - 集成：**约 1 人日**。`pip install fsrs`，在出题/判分循环里加"调度器"：出题时取到期卡片 → 判分（已有 `grade_answer`）→ 把评分喂给 FSRS 更新间隔。
  - 运行：纯计算，免费。
  - 维护：稳定，版本演进快（当前 6.x）。
- **平替**：自实现 **SM-2**（约 50~100 行，公开算法，无许可证问题）、LeetCode 式简单复习表。FSRS 为现代默认，首选。
- **建议**：直接复用 py-fsrs，接在 `grade_answer` 之后。

## 4. 落地注意事项（对齐仓库硬约束）

1. **加表三处同步**：若新增 SRS 复习表（如 `reviews`）到 `knowledge.db`，必须 `knowledge_graph.py::_create_tables` 建表 + `_auto_migrate` 补索引，并同步 `backend-admin/app/core/db.py::delete_user_rows` 删号清单、`scripts/inspect_graph_quality.py` 体检口径、AGENTS.md §5 路由。**加列**走 `_auto_migrate` 的 `ALTER TABLE` 清单。
2. **用户隔离**：视频/转写/复习表全按 `user_id` 分区；`KnowledgeGraph(user_id)` 每次新建、用毕 `close()`。
3. **OCR/ASR 插拔层**：ASR 新建 `asr.py` 能力层（本地/云可切换 + 降级为空），与 `parsers/ocr.py` 同一模式，避免跨模块引用私有符号。
4. **上传原子性**：视频 → 转写 → 抽帧 → 建图若分步落盘，失败需回滚，参照 `kb_manager.upload_and_index` 的原子语义（`except BaseException` 兜断连）。
5. **建图唯一出口**：视频讲义建节点必须走 `create_node_with_content` + `graph_generator`，禁止调用方自写节点 MD。
6. **SRS 接入**：卡片复习沿用现有出题/判分循环（`quiz_generate` / `grade_answer`），FSRS 只做调度，不另起一套掌握度信号（项目掌握度主信号 = 出题判分）。
7. **新工具 = 1 模块 + 1 行注册**：视频转讲义/SRS 触发若做成 Agent 工具，按 `core/agent_tools/tools/README.md` 复制模板 + 注册 `NATIVE_SPECS`，不要手写第四份说明。

## 6. 合规边界（视频采集与再利用）

> 本节是本工作流复用进 AI-tutor 的**合规闸门**。在接入 A（yt-dlp 下载）、B（ASR 转写）、C（抽帧+OCR）模块前，必须先确认合规前提。
> 完整声明文本见同目录《合规声明_视频字幕采集与再利用.md》。

### 6.1 三层许可框架

视频解析/字幕提取是否"被允许"，取决于三个**互相独立**的许可层，任何一层踩线都构成独立风险：

| 层面 | 规则 | 对本文模块的影响 |
|---|---|---|
| **① 著作权法** | 第24条：**为个人学习、研究或者欣赏**，使用他人已发表作品，可不经许可、不付报酬（须指明作者/名称、不得影响正常使用、不得不合理损害权利人权益） | A/B/C/E 个人自用=合理使用，不侵权 |
| **② 平台协议** | B 站用户协议 **4.3.15**：未经书面许可，不得以机器人/爬虫/脚本等自动程序获取平台内容、数据 | ⚠️ yt-dlp 下载 B 站视频=违约（后果限流/封号/封IP，非刑责） |
| **③ 技术措施** | 第49条：不得故意避开/破坏技术措施；第53条：未经许可复制/发行/**通过信息网络向公众传播**=侵权 | 未破解 DRM 即无碍；下载**付费/大会员内容**被协议明确禁止 |

**核心区分**（第53条）：侵权成立的关键动作是"复制发行"和"**向公众传播**"（上传、再分发给公众）。**个人下载、个人自用=复制，受合理使用保护；上传/分享/再分发=侵权**。

### 6.2 对本文各模块的合规提示

- **A 视频下载（yt-dlp）**：个人研究用途=合理使用，低风险；但 B 站下载违反 ToS 4.3.15，**优先用官方字幕接口 + 个人登录态少量拉取**，或使用**授权素材**（自己录播、已购买/已授权课程、CC 协议资源）。
- **B ASR 转写**：转写自用内容无碍；转写他人在售课程/付费内容需授权。
- **C 抽帧 + OCR**：同上，个人自用无碍。
- **E 建图入库**：仅**入库自用**，不得将第三方内容再分发。

### 6.3 落地红线（接入前逐条确认）

1. [ ] 仅个人学习/研究/竞赛自用，**不向公众传播**入库的第三方内容
2. [ ] B 站采集优先官方字幕接口+登录态，**不内置大规模爬取**
3. [ ] **不破解技术措施、不下载付费/大会员内容**
4. [ ] 若项目**商用**（如国创/BP 方向），合理使用保护失效——先做内容授权盘点，第三方内容全换**自产或已授权**来源
5. [ ] 开源相关采集/解析工具时，附《合规声明》（见下）
