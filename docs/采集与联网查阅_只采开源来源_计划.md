## 3. 核心设计

### 3.1 唯一业主模块：`backend/app/core/open_source.py`（纯 stdlib 叶子模块）

**为什么放 `core/` 根**（导入方向已核实）：

- 放 `agent_tools/` → `collector` 与 `mcp_servers` 都要依赖 `agent_tools` 包；
- 放 `collector/` → `agent_tools/web_archive.py` 顶层 import 会触发 `collector/__init__` 包级初始化（`collector/__init__.py:13` → `manager` → `adapters`），而 `collector/adapters/web_page.py:26` 反过来 import `agent_tools.net_guard` → **包级环**（现有代码在 `web_archive.py:94` 用惰性 import 规避的就是这类问题）；
- 结论：判定模块必须**谁也不依赖**。`open_source.py` **只 import stdlib**（`re` / `urllib.parse`）——**连 `collector/types.py` 都不 import**，只输出 `"L0"/"L1"/"L2"/"L3"` 字面量，从而彻底零环、零耦合。

**模块内容（三个数据表 + 三个纯函数）**：

```python
# 1) 开放来源：域名后缀 → 授权等级（L0/L1）。唯一来源表，采集侧也用它
SITE_LEVELS: dict[str, str] = {...}

# 2) 开放来源：域名后缀 → 给人看的许可标签（留痕/文案用，可选）
SITE_LABELS: dict[str, str] = {...}

# 3) 关闭来源：付费墙 / 登录墙 / 明确禁止 / 盗版分发（黑名单，最高优先级）
CLOSED_SITES: frozenset[str] = frozenset({...})

def classify(url: str, html: str = "") -> tuple[str, str]:
    """返回 (等级 L0/L1/L2/L3, 判定依据)。任何异常 → ("L3", 原因)。"""

def is_shareable(url: str, html: str = "", mode: str = "personal") -> bool:
    """该 URL/页面在本模式下是否可留存（= classify 结果落在该模式允许集内）。"""

def license_label(url: str, html: str = "") -> str:
    """给人看的许可标签，如 'CC BY-SA 4.0' / '许可不明'。"""
```

**判定顺序（优先级从高到低）**：

| 顺序 | 输入 | 输出等级 | 说明 |
|---|---|---|---|
| 1 | URL/域名命中 `CLOSED_SITES` | **L3** | 付费墙/登录墙/明确禁止/盗版分发库（决策 #13）。**优先级高于一切**，页面里写了 CC 也无效 |
| 2 | URL/域名命中 `SITE_LEVELS` | **L0 / L1** | 人工核验过的开放来源 |
| 3 | HTML 命中开放许可声明（`rel="license"`、`creativecommons.org/licenses/...`、SPDX 标识、页脚 `CC BY-SA 4.0`/`CC0`/`Public Domain`） | **L0**（BY/CC0/PD/MIT/Apache）；**L2**（NC/ND 受限） | 新增能力，纯正则、离线可测 |
| 4 | 其它 | **L3** | **fail-closed：判不出来一律不可采** |

**为什么出口直接复用 L0–L3（而不是新枚举）**：`types.py:8` 里 L3 的定义**本来就是「版权不明/明确禁止」**——未登记站点判 L3 属于既有语义的精确用法，不需要新分级、不需要改 `types.py`、也不存在两套映射漂移。模式规则（谁能采哪一级）仍然只在 `types.ALLOWED_LICENSE`。

**识别边界（防误杀）**：
- 只认**正向**信号才给 L0/L2；
- 负向文本（页脚"版权所有 / All rights reserved / 未经许可不得转载"）**不判 L3**（这些在正常站点页脚随处可见，直接判会大面积误杀）——规则是"把已识别的受限等级降回 L3"；
- 大小写不敏感；子域后缀匹配沿用现有语义（`host == suffix or host.endswith("." + suffix)`，`web_page.py:116-118`）。

### 3.2 接线点 1/3：`collector/adapters/web_page.py`（**实建 2 行**）

| 改动 | 现状 → 新 |
|---|---|
| 来源表 | 删掉本地 `_SITE_LICENSE` 字面量，改为 `from app.core.open_source import SITE_LEVELS as _SITE_LICENSE`（**保留同名别名**，既有测试的 `monkeypatch.setitem(wp._SITE_LICENSE, ...)` 照常可用） |
| 默认等级 | `_DEFAULT_LICENSE = "L2"` → `"L3"`（未登记 = 版权不明 = 不可采） |
| `license_for_url` / `is_allowed` / `candidate_from_url` / `fetch()` | **一行不改**（签名与逻辑全不动；行为只随表与默认值变化 → §6 的口径变更） |

> **偏差说明（相对 v2 计划，实施时核实）**：原计划还要在 `fetch()` 里加一次 `classify(url, html)` 以支持
> 「未登记但页面声明了 CC」的放行。**该路径实际不可达**：候选由 `candidate_from_url` 构造，而它只有 URL、
> 没有 HTML —— 未登记站点在**候选阶段**就被判 L3 拒掉，`fetch()` 永远见不到那个页面。
> 因此采集侧改为**纯表驱动**（要采就先入 `SITE_LEVELS`）；「页面许可声明自动放行」保留在**真正拿得到 HTML
> 的联网路径**（§3.3 的 `archive_html`），那里既不需要额外请求、也不会浪费请求。
> 净效果：`web_page.py` 从 3~5 行降到 **2 行**，改动更小、且两个阶段不再有两套判定。

### 3.3 接线点 2/3：`core/agent_tools/web_archive.py`（约 4~6 行）

| 位置 | 改动 |
|---|---|
| `fetch_and_archive()`（`web_archive.py:107-133`） | 在 `is_blocked_url` 之后、发请求之前插一次 `is_shareable(url)`；不通过 → `warning` + 返回 `None`（沿用现有静默失败语义） |
| `archive_html()`（`web_archive.py:85-104`） | 落盘前插一次 `is_shareable(url, raw_html)`（HTML 级声明判定）；不通过 → 返回 `None` |

**这样即覆盖 C + D 两条路径，且 `tools/fetch_webpage.py`、`mcp_host.py` 零改动**：
- D：`fetch_webpage` 调 `archive_html`（`fetch_webpage.py:76-78`），拿不到节点就自然"不存档"，**返回给模型的正文文本一字不变**（宽松版决策）；
- C：`mcp_host` 调 `schedule_archive_from_search` → `archive_search_results` → `fetch_and_archive`，非开源结果页在**发请求前**就被跳过。

### 3.4 接线点 3/3：`core/agent_tools/tools/download_resource.py`（约 3 行）

在 `is_blocked_url` 检查之后（`download_resource.py:149-152`）插一次 `is_shareable(url)`；不通过直接返回友好文案（工具层约定：不抛异常）：

> 「该来源许可不明或非开放许可，未下载入库。建议改用开放许可来源，或自行下载后上传。」

**为什么这里是 fail-closed 而不像 `fetch_webpage` 那样宽松**：它产出的是"长期留存 + 可被 `rag_search` 检索"的内容，属于真正的采集。

### 3.5 三条路径的严格度总表

| 路径 | 产出 | 非开源 URL 的行为 | 非开源但页面声明了 CC 的 URL |
|---|---|---|---|
| A 采集 web_page | KB 文档（可检索） | **拒绝**（L3 不入候选/不入库） | **放行**（L3 → L0） |
| C 联网搜索存档 | 图谱节点 | **不抓、不存**（发请求前拦截） | 放行 |
| D `fetch_webpage` 存档 | 图谱节点 | **不存**（正文照常返回给模型） | 放行 |
| D `fetch_webpage` 只读 | 仅模型上下文 | **照常返回**（只看不留） | 照常返回 |
| E `download_resource` | KB 文档（可检索） | **不下载、不入库** | 放行 |

## 4. 开关与配置：**不加 `config.py` 字段**

- 开关内联在 `open_source.py` 模块级常量（如 `ENABLED: bool = True`），**不读环境变量、不动 `core/config.py`**——项目规定"所有环境变量集中在 config.py"，那是指**需要 env 可配**的项；本次只有 3 个接线点、回退仅需改一个常量，加 config 字段属过度设计（YAGNI），也会多污染一个共享模块。
- 回退方式：改常量（或测试里 `monkeypatch`）。
- 若日后确实需要运维侧开关，再单独一步加 `config.py` 一个字段（那是既有扩展点，届时再议）。

## 8. 风险与对策

| 风险 | 级别 | 对策 |
|---|---|---|
| **误杀**：开放站点不在 `SITE_LEVELS` 里被判 L3 | 高 | ① 页面许可声明自动放行（§3.1 第 3 步）覆盖绝大多数 CC 站点；② 拒绝时日志带 `classify` 的依据文本，便于补表 |
| **漏放**：非开源站点伪造 CC 声明 | 中 | 声明只能"放行"，不能覆盖黑名单（第 1 步优先级最高） |
| `example.org` 类测试夹具被新默认值拒绝 | 中 | §6 已逐条列出修法（补 `monkeypatch.setitem`）；不视为回归 |
| 采集侧行为收紧影响既有演示流程 | 中 | 未登记站点本就不该采（这正是本次目标）；演示用 L0 源（维基/OI-wiki/OpenStax）不受影响 |
| 多人/AI 会话并发写同一仓库 | 中 | 提交**路径限定**（禁 `git add -A` / `commit -a`）；动手前 `git status` 看别人 WIP |
| 口径变更被误读为"回归失败" | 中 | §6 逐条列出 + 提交说明标注"口径变更" |
