# 借鉴 OpenMAIC（清华 THU-MAIC）完善 TutorAgent — 方案

> 创建：2026-08-29
> 目标：在保持 TutorAgent 轻量架构（FastAPI + Vue3 + SQLite）的前提下，精准借鉴 OpenMAIC 的可复用模块，补齐参赛短板。

---

## 一、先决结论：OpenMAIC 的协议与适配性

| 维度 | 情况 | 对我们的意义 |
|------|------|-------------|
| **协议** | v0.3.0 起由 AGPL-3.0 **改为 MIT**（现 v1.0.0） | ✅ MIT 允许自由使用/修改/商用，借鉴无合规风险（保留版权声明即可）。README 要求遵守子包 LGPL-3.0（mathml2omml） |
| **技术栈** | Next.js + React + TS + LangGraph + Zustand + Tailwind | ⚠️ 与我们 Vue3 + FastAPI + SQLite 不匹配，**前端组件无法直接复用**，只能借鉴设计/思想 |
| **架构理念** | 多智能体编排（AI 老师 + AI 同学）、动作引擎、回放引擎 | ✅ 我们已有"图谱驱动自适应 Agent"，可借鉴其"动作执行 + 流式反馈"理念 |
| **规模** | 21.7k stars，非常庞大 | ⚠️ 不可照搬，只抽取高价值低耦合模块 |

**总原则**：**"借鉴思想 + 自研实现"，不做跨栈移植。** 重点借鉴 OpenMAIC 的设计模式，落到我们的技术栈里，避免引入 React 组件或重依赖。

## 二、可借鉴模块清单（按价值/成本排序）

### ⭐ 高价值低成本的"思想借鉴"（推荐优先）

| # | 借鉴点 | OpenMAIC 做法 | TutorAgent 现状 | 借鉴落地建议 |
|---|--------|--------------|----------------|-------------|
| 1 | **两阶段生成流水线** | 大纲生成 → 场景生成（每章节→幻灯片/测验/交互） | 已有"两阶段流式响应"（文本 SSE → 后台 function calling），但**缺"生成物"概念** | 借鉴其"从输入→结构化课程大纲→分章节产出"的链条，让 AI 导学先出**学习大纲/计划**，再逐章节教学 |
| 2 | **动作执行引擎**（lib/action，28+ 动作） | 动作与业务解耦，动作驱动白板/语音/特效 | 我们工具=function calling（KG_TOOLS），动作即图谱操作 | 把 KG_TOOLS 抽象为"动作层"，未来动作可扩展为**作图/出题/语音**，模块更清晰 |
| 3 | **服务商抽象层**（lib/ai / audio / media） | 统一 Provider 适配 16+ 服务商 | 当前硬编码阿里云 qwen-plus（AsyncOpenAI） | 抽象 `LLMProvider` 接口，支持切换 deepseek/GLM 等（复用已有的 OpenAI 兼容层即可，成本低） |
| 4 | **学习产物导出**（lib/export：.pptx / 交互式 HTML / ZIP） | 一键导出可离线播放的课堂 | 我们有"图谱知识一键导出 Markdown"（TODO P3） | 借鉴"离线资源内联（data: URI）"策略，把导出的知识点做成**自包含交互式 HTML**（复习卡片），演示加分项 |
| 5 | **AI 教师主动引导** | 高亮关键区域、设置条件、引导注意力 | 我们有自适应/递归教学模式 | 在提示词里强化"主动引导"（已部分具备），借鉴"设置条件+提示"做成**引导式提问** |

### ⭐⭐ 中高价值的模块级借鉴（需自研适配）

| # | 借鉴点 | OpenMAIC 做法 | 借鉴落地建议 |
|---|--------|--------------|-------------|
| 6 | **测验（Quiz）场景** | AI 生成单选/多选/简答，实时判分反馈 | **高优先级**：这是补"痛点2（无反馈）"的最直接武器。新增"AI 出题 + 判分 + 反馈"模块，把节点变测验题，落进知识图谱（node→题目） |
| 7 | **白板（SVG 白板）** | 实时绘图、推导公式、画流程图 | 借鉴"共享白板"思想，做**图谱 + 手写推导的联动白板**。我们已有 D3 图谱，可加一个可拖拽/画线的白板覆盖层 |
| 8 | **交互式模拟（HTML Interactive）** | 生成 HTML 交互实验（物理模拟器等） | 成本较高，可**简化为"交互式 HTML 卡片"**嵌入节点内容（如流程图、小游戏），作为节点内容的一种类型 |

### ⭐⭐⭐ 值得借鉴但需权衡成本的高阶模块

| # | 借鉴点 | 说明 | 建议 |
|---|--------|------|------|
| 9 | **多智能体编排**（圆桌辩论/AI 同学） | LangGraph 状态机管理多角色讨论 | 参赛加分项但工程量大。可做**"AI 同学"轻量版**：对话中模拟一个虚拟同学提出追问/异议，制造"多智能体"讨论感（改 prompt 即可，成本低） |
| 10 | **回放引擎** | 课堂播放状态机（idle→playing→live） | 适合演示"学习过程回放"，但非核心。暂缓 |
| 11 | **PPT 导出**（packages/pptxgenjs） | 定制 PowerPoint 生成（MIT） | 我们已有 Markdown 导出。若演示需要"生成课件"，可考虑但优先级低 |

## 三、推荐落地优先级（结合参赛截止 10-15）

结合 COMPETITION.md 的三大痛点与 TODO.md，建议按以下顺序借鉴落地：

### 第二梯队（P2，差异化加分）
4. **[借鉴#4] 知识复习卡自包含 HTML 导出** — 演示时可一键导出漂亮复习页
5. **[借鉴#9] "AI 同学"轻量多角色讨论** — 改 prompt 模拟同学追问，制造多智能体感
6. **[借鉴#7] 白板/图谱联动** — 手写推导 + 图谱

### 第三梯队（P3，有余力再做）
7. [借鉴#3] LLM 服务商抽象层
8. [借鉴#2] 动作引擎重构
9. [借鉴#10] 回放引擎
10. [借鉴#11] PPT 导出

## 四、技术落地方案速览（怎么接进现有代码）

### 1. AI 出题模块（首选）
```
后端 backend/app/core/quiz.py（新增）
  - 输入：node_id（或 topic）
  - 用 call_llm(enable_tools=False) 让 LLM 返回 JSON 题目 [{question, options, answer, explanation}]
  - 存入新表 quiz_questions（node_id, question, options_json, answer, explanation）
  - 判分 API：POST /quiz/{id}/grade {user_answer} → {correct, feedback}
  - 复用现有错误码体系（E-QUIZ-xxx）
前端
  - NodeDetail.vue 加"出题测验"按钮
  - 新增 QuizView/题目卡片组件（单选/多选/简答）
  - 复用已有的对话流式/存储
```

### 2. 学习大纲生成
```
后端 chat_service 或新增 prompt：
  - system_prompt_adaptive.j2 增强，让 AI 首轮输出结构化学习大纲（可用 add_knowledge_node 建骨架）
  - 或新增"learning-plan"模式
前端
  - 对话首条消息后展示可勾选的学习计划
```

### 3. "AI 同学"轻量讨论
```
提示词注入：新增一个系统 prompt（system_prompt_peer.j2）
  模拟一个虚拟同学 S，在学习中提出追问/误区/举例，AI 老师回答
  两种实现：
    a) 一次调用里 LLM 同时扮演老师+同学（最简单）
    b) 两个角色分两次调用对话（更真实，成本高）
前端：MessageBubble 区分"老师/同学"角色气泡（复用现有角色样式）
```

## 六、本次调研要点（2026-08-29）

- OpenMAIC 版本：现 v1.0.0（2026-08-27 发布），协议 MIT
- 核心引擎：两阶段生成流水线 / 多智能体编排(LangGraph) / 动作引擎(28+动作) / 回放引擎
- 场景类型：幻灯片、测验、交互模拟、PBL
- 深度交互：3D 可视化、模拟、游戏、思维导图、在线编程
- 导出：.pptx / 交互式 HTML / 课堂 ZIP / MP4
- 集成：OpenClaw（飞书/钉钉/Slack/Telegram 20+ 应用）
- 关键差异：OpenMAIC 是"生成课堂"（一次性产出），TutorAgent 是"持续导学"（对话+图谱+画像），两者定位互补，我们借鉴其"生成物"与"交互"能力，强化"导学"闭环
