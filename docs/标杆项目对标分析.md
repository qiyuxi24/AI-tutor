# 标杆项目对标分析 — TutorAgent 功能差距与学习路径

> 创建日期：2026-08-31
> 目的：拉取同类开源项目做功能矩阵对比，找出 TutorAgent 缺失/待补强的模块，为"工具适配度"提升提供优先级依据。
> 参考标杆：DeepTutor（港大 HKUDS）、adaptive-edu（上海二工大）、Autonomous Learning System（ALS v3.2）、OpenMAIC（清华，已借鉴）。

## 二、TutorAgent 现状功能矩阵

### 已有（√）
- 两阶段流式对话（SSE 文本 + 后台 function calling）
- 知识图谱：SQLite + 节点 MD、D3 力导向图、学科→板块两级切片（graph_middleware）
- 四种教学模式：自适应引导 / 自由对话 / 递归式教学 / 学习路径推荐
- 图谱生成：从学科教材自动生成图谱（graph_generator，含语义去重）
- 学习路径：Kahn 拓扑排序
- RAG 四层：图谱 RAG + 上传文件 KB + 混合检索（向量+BM25+RRF）+ Agentic RAG 工具（rag_search）
- 知识库：目录树、去耦合解析器（PDF/Word/PPT/图片OCR）、path 溯源、父级扩展
- 用户画像 v2：结构化 JSON + AI 观察笔记 + 完整度
- AI 出题（quiz/：生成/判分/质量过滤）
- 认证（JWT）、会话历史、事件总线、错误码体系、主题切换、Docker 部署

### 缺失 / 薄弱（✗ / △）
| 模块 | 现状 | 说明 |
|------|------|------|
| **间隔复习（SM-2）** | ✗ 完全没有 | 学习工具标配"抗遗忘"能力，ALS 有完整调度器；DeepTutor 用 Mastery Path 分级替代 |
| **学习进度仪表盘** | △ 仅有图谱节点着色（TODO P1 未完成） | adaptive-edu 有统计可视化；COMPETITION.md P1 已列入待办 |
| **知识追踪（Knowledge Tracing）** | △ 掌握度字段是简单启发式 | adaptive-edu 用 MEFKT 模型化；我们可先做"基于交互数据的轻量掌握度模型" |
| **测评闭环** | △ 有 quiz 出题/判分，但无"初测→阶段测→复习计划"联动 | adaptive-edu 核心闭环；可把 quiz 结果回写图谱掌握度 |
| **主动知识缺口检测** | △ 图谱可看薄弱节点，但无 LLM 驱动的"缺口报告+任务生成" | ALS 的 exploration 模块 |
| **记忆分层（L1/L2/L3）** | △ 仅用户画像（约等于 L2 表面事实） | DeepTutor 三层可审计记忆 + Memory Graph |
| **深度研究/报告** | ✗ 无 Deep Research | DeepTutor 生成带引用的研究报告；与"递归式教学"可结合 |
| **沉浸式阅读** | ✗ 无文档-对话并排 | DeepTutor Immersive Reading，页级引用 |
| **多智能体协作** | △ 单 Agent（function calling），无 subagent 咨询/多角色 | DeepTutor Subagents/Partners；TODO 有"AI 同学"轻量多角色讨论 |
| **教师端/三端** | ✗ 仅学生端 + admin | adaptive-edu 三端；参赛加分项但工作量较大 |
| **复习卡/知识导出** | △ 有节点导出计划（TODO P3） | DeepTutor Book Engine（文本/测验/闪卡/时间线块）；自包含 HTML 导出（TODO 已列） |
| **代码沙盒/验证** | ✗ 无 | ALS 沙盒验证；DeepTutor office 技能子进程沙箱 |

## 三、差距结论与优先级建议

> 参赛硬约束：校内截止 2026-10-15，还有 ~6 周。按"演示冲击力 + 实现成本 + 与 Agent 赛道契合度"三维排序。

### 🥇 第一梯队（强烈推荐，2-4 周内可落地）
1. **学习进度仪表盘 + 掌握度可视化**
   - 后端 `GET /knowledge/stats`（总节点/掌握/学习中/未学、平均掌握度、按学科/板块）
   - 前端 HomeView 仪表盘面板（进度条 + 图表）
   - 成本低、演示直观，COMPETITION.md 明确列入 P1
2. **间隔复习（SM-2）**
   - 后端：复习队列模块（卡片 = 图谱节点 + 掌握度），SM-2 调度算法（纯 Python，无新依赖）
   - API：`GET /review/due`、`POST /review/{node_id}/grade`（Again/Hard/Good/Easy）
   - 前端：复习页（打卡式卡片流）
   - 直接对标 ALS，是"学习工具"的硬核标配
3. **测评闭环（quiz ↔ 图谱联动）**
   - 出题时按薄弱节点优先选题；判分结果回写节点掌握度
   - 打通"诊断→练习→反馈"闭环，评审可演示完整链路

### 🥈 第二梯队（有资源则做）
4. **主动知识缺口检测报告**
   - LLM 基于图谱掌握度 + 会话历史生成"薄弱点清单 + 推荐学习任务"
   - 作为 Agent 主动能力展示（对齐赛道"Agent"主题）
5. **复习卡导出（自包含 HTML）**
   - 已有 TODO 计划，演示加分，成本低
6. **轻量多角色讨论（"AI 同学"）**
   - prompt 级改造，成本极低，展示 Agent 多角色能力

### 🥉 第三梯队（比赛后 / 论文方向）
7. **知识追踪模型（MEFKT 风格）** — 学术亮点，但需数据积累，短期演示效果弱
8. **三层记忆架构** — 架构亮点，可先做 L2 事件时间线扩展
9. **沉浸式阅读 / Deep Research / 多智能体 subagent** — 大工程，适合赛后再议

## 四、技术实现参考（学习清单）

### SM-2 间隔复习（对标 ALS planning/scheduler）
- 卡片数据：`{node_id, user_id, ease_factor, interval_days, due_date, repetitions, lapses}`
- 算法：经典 SM-2（super-memo），Q=0..5 六档（或简化 4 档 Again/Hard/Good/Easy）
- 与图谱掌握度联动：Good/Easy 提升掌握度，Again 降低；掌握度 >70 可标记"已掌握"移出复习
- 参考实现：`als/planning/`（APScheduler 调度 + JSON 数据）

### 知识追踪（对标 adaptive-edu MEFKT）
- 轻量版：基于"节点交互事件"（阅读/作答/对话提及）的贝叶斯或 IRT 模型
- 完整版：MEFKT（Memory-Enhanced Factorized Knowledge Tracing，multi-head attention + 记忆增强）
- 建议：先做规则 + 事件日志，再抽象模型接口（可插拔）

### 测评闭环（对标 adaptive-edu）
- 初测：入学诊断（quiz generate + 全学科抽题）
- 阶段测：按板块/路径节点出题
- 结果回写：`POST /quiz/{id}/grade` 判分后，更新图谱节点 mastery + 画像

### 记忆分层（对标 DeepTutor L1/L2/L3）
- L1 事件轨迹：JSONL 追加会话/图谱操作事件
- L2 表面事实：现有用户画像 JSON（升级为引用 L1 事件 id）
- L3 综合：跨会话总结（定时 LLM 聚合）
- Memory Graph：节点 = 实体，边 = 关系，现有图谱可承载

## 五、结论

TutorAgent 的差异化底座（图谱 + 混合 RAG + Agent 工具）已经明显强于多数同类项目，**缺的是"学习工具化"的表层模块**：间隔复习、仪表盘、测评闭环、缺口报告。这些模块恰好是评审一眼能看到的"学习产品感"，且实现成本可控（纯 Python 算法 + 现有图谱/quiz 复用），是未来 6 周的最优投入方向。
